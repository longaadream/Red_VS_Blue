# 技能文本规范化与关键词系统重构计划

## 目标

把当前“自由发挥”的技能描述，重构成“短描述优先、关键词承载复杂规则、展开后补充解释”的混合式方案。

目标效果：

- 默认阅读成本接近炉石：短、快、扫一眼就懂
- 复杂机制仍然能表达完整，不牺牲战棋规则清晰度
- 技能文案可批量维护，不再一条一条手工发散
- 前端可以统一做关键词高亮、标签、说明弹层

## 当前问题

基于现有 `data/skills/*.json` 的抽样，主要问题集中在这几类：

1. 同类效果说法不统一
   - 例：`造成自身攻击力100%的物理伤害`
   - 例：`造成当前攻击力1.5倍的伤害`
   - 例：`造成等同于自身攻击力的伤害`

2. 句式顺序不统一
   - 有的先写范围，再写目标
   - 有的先写效果，再写持续时间
   - 有的把触发条件塞在句尾

3. 规则词和实现词混杂
   - 文案里直接出现 `buff`、`debuff`
   - 文案里混入实现细节，如 `被子弹:false的格子拦截`

4. 数值表达格式不统一
   - `100%攻击力`
   - `自身攻击力100%`
   - `当前攻击力1.5倍`
   - `攻击力×1.2`

5. 高频机制重复解释
   - 冰冻、禁疗、真实伤害、沉默、击退、传送等在很多技能里反复展开

6. 长文本技能没有分层
   - 默认就把全部规则塞进一段描述里，导致图鉴和选将页阅读成本很高

## 我们的协作模式

这一轮开始按“你拍板，我落地”推进：

- 我负责：规范设计、关键词提炼、文件修改、批量改写、UI 接入、校验脚本
- 你负责：少量关键风格判断和有争议机制的定调

执行节奏：

1. 我先出草案和改动
2. 我只把真正需要你决策的点压缩出来
3. 你一句话拍板
4. 我继续推进下一轮

## 目标风格

当前已定：

- 风格：混合式
- 倾向：偏炉石

这意味着：

- 默认描述尽量短
- 高频规则交给关键词承载
- 复杂技能允许保留第二层展开说明
- 世界观名词保留，但规则表达尽量标准化

## 文案规范 v1

### 1. 描述层级

每个技能当前先只保留两层信息：

1. `description`
   - 默认展示的最终文案
   - 不再拆分短描述和长描述
   - 所有需要给玩家看的信息都直接写进这里

2. `keywords`
   - 技能涉及的规则关键词数组
   - 供 UI 高亮、标签、筛选使用

### 2. 句式顺序

主动技能统一使用：

`[目标/范围] + [效果] + [持续时间/次数/限制]`

示例：

- `对1个相邻敌人造成1点物理伤害。`
- `对3格内1个敌人造成150%攻击力的魔法伤害，并冰冻1回合。`
- `传送到5×5范围内1个空格。`

被动技能统一使用：

`被动： [触发条件] + [效果]`

示例：

- `被动：受到致命伤害时，免疫该伤害并恢复5点生命。`
- `被动：回合结束时，若生命值低于50%，恢复2点生命。`

持续状态统一使用：

`获得/施加[状态名]： [效果]`

示例：

- `获得【寒冰坚忍】：受到的伤害减少50%，持续2回合。`

### 3. 固定词法

统一优先使用以下表达：

- 用 `对X造成Y伤害`，不用“给予伤害”“打出伤害”
- 用 `恢复X点生命`，不用“回复”“治疗X血”
- 用 `持续X回合`
- 用 `获得` / `施加`
- 用 `相邻`、`X格内`、`X×X范围内`
- 用 `1个敌人` / `所有敌人` / `1个友军`
- 用 `物理伤害` / `魔法伤害` / `真实伤害`

### 4. 禁止项

默认展示文案里尽量不出现：

- `buff`
- `debuff`
- 代码字段名
- `false/true`
- 纯实现导向的内部判断描述

### 5. 数值表达统一

统一成下面这套：

- `100%攻击力`
- `150%攻击力`
- `攻击力+2`
- `移动范围-1`
- `受到的伤害减少50%`
- `最多2层`

不再混用：

- `自身攻击力100%`
- `当前攻击力1.5倍`
- `攻击力×1.5`

除非该技能真的依赖“当前攻击力”这种特殊动态含义。

## 关键词系统设计

### 关键词的职责

关键词不替代全部文本，只负责承载高频规则。

关键词适合处理：

- 高频状态
- 高频伤害类型
- 高频控制效果
- 高频位移与召唤机制
- 高频资源机制

### 首批关键词范围

建议先只保留“有专门规则含义、能明显减少解释成本”的关键词：

- 真实伤害
- 禁疗
- 冰冻
- 沉默
- 召唤
- 圣盾
- 护盾
- 充能
- 流血
- 燃烧

暂不做关键词、仅作为普通描述词使用的内容：

- 物理伤害
- 魔法伤害
- 治疗
- 眩晕
- 减速
- 击退
- 传送
- 冲刺

### UI 展示方式

默认方案：

1. 技能名下方展示短描述
2. 短描述中的关键词高亮
3. 技能卡底部显示关键词 tag
4. 点击关键词弹出标准解释
5. 复杂技能额外提供“展开详情”

## 数据结构建议

现有技能 JSON 在保留兼容的前提下，逐步补充这些字段：

```json
{
  "id": "frostbolt",
  "name": "冰霜箭",
  "description": "对5格内1个敌人造成100%攻击力的魔法伤害，并冰冻1回合。冰冻期间不能移动或使用技能。",
  "keywords": ["魔法伤害", "冰冻"],
  "targetText": "5格内1个敌人",
  "effectTags": ["damage", "control"]
}
```

字段约定：

- `description`: 默认展示的最终描述
- `keywords`: 关键词数组
- `targetText`: 可选，便于后续做结构化生成
- `effectTags`: 内部分类标签，偏开发用途

## 分阶段执行

### 阶段 A：建立规则

产出：

- 本文档
- 关键词字典草案
- 技能字段约定

### 阶段 B：接 UI

目标：

- 图鉴页支持关键词高亮
- 技能详情支持关键词说明
- 保持旧数据兼容

### 阶段 C：批量重写技能描述

建议顺序：

1. 基础共通技能
2. 常见法术/控制技能
3. 复杂传奇技能
4. 触发器与衍生技能

### 阶段 D：加自动校验

检查项：

- 是否缺少 `keywords`
- 是否引用未定义关键词
- 是否出现禁用表达
- 是否描述过长
- 是否混用多套数值写法

## 需要你后续拍板的少数问题

后面我们只需要你在这些点上定一下：

1. `治疗` 和 `恢复生命` 要不要区分成两个术语
2. `护盾` 和 `圣盾` 是否严格区分
3. `冰冻` 的标准定义是否固定为“不能移动或使用技能”
4. `燃烧`、`流血` 这类世界观状态是否都做成正式关键词
