# ADR-0019：零阶段 AI 使用单步合法估价与位置潜力

状态：提议中
日期：2026-08-28
关联任务：RED-122
风险：Medium

## 背景

RED-84/85/86 已提供公开观察、权威合法候选、隔离 transition、机制兼容合同和通用回合规划器。后续训练仍需要一个无需训练、固定、可解释的弱基线。

RED-122 最初采用“合法外层动作 + 费用放宽后续动作”的双层完整枚举。真实 8v8 PvE 评测中，默认 10,000 节点配置的首个正式战斗决策持续超过 5 分钟仍未返回，无法作为可玩的 PvE 基线。用户因此明确要求取消第二层搜索，同时把位置价值和位置带来的未来潜力直接纳入静态估价。

初版单步实现又把模拟限制为 2 个候选。对内置 `simple-v1` 的 3 局评测全部在 40 回合上限平局，且候选 trace 显示低语义排名的攻击或技能可能从未进入估价。用户因此进一步要求保持单步搜索，但测试全部严格合法策略后再选最大估值。

完整枚举 v3 在固定种子 `335607069` 和 `4254588968` 中暴露出新的局部循环：`resources` 直接奖励已经花掉的 AP，`turnProgress` 又固定惩罚交出控制权，因此单步重规划会把轻微变差的移动判为正收益。典型表现是同一棋子反复在相邻两格往返，第一局至少 65 次、第三局至少 96 次严格反向移动；同时会选择只造成自伤而没有形成攻击结果的技能。资源消耗必须回归为行动手段，价值由后继局面的生命、减员、威胁、安全和位置体现。

## 决策

1. 使用人工、版本化、玩家相对的静态估价 `F_p(S)`；终局固定优先，普通特征按数量级分层，重复状态按类型去重，护盾按最大生命归一化并封顶。
2. 只接受 `aiEnvironmentV1.listLegalActions()` 的严格合法候选，使用 RED-86 的通用语义稳定排序；除回合动作护栏外不按数量、类型、费用、目标或墙钟时间裁剪。排序仅固定 trace 与同分顺序。
3. 每个严格合法候选恰好执行一次隔离 `simulate()`，选择全集中的 `argmax F_p(Simulate(S, a))`，只返回一个正式动作，并在权威状态更新后重新规划。
4. 删除费用补贴、费用不足候选、`λ`、top-3 聚合和任何第二层动作枚举。
5. 将位置价值放进 `F`：低血暴露、按地图尺寸归一化的中心控制、对敌方公开核心目标的压迫、未来攻击覆盖、友军汇合支援、可达移动空间，以及公开地形的治疗、充能、掩体和伤害。敌方没有存活核心时，目标压迫退化为到最近存活敌棋的距离。
6. 位置特征只使用公开几何、通用棋子属性与地图格属性，不按角色、技能、阵容或地图 ID 写分支。
7. RED-85 兼容性作为 trace 诊断保留；候选是否合法和结果如何仍以权威 transition 为准。
8. 正式 agent/profile ID 固定为 `rvb-ai-zimse-v1`。同分时先选 `endTurn`；非结束动作再按较低正式费用、稳定 action JSON 和 candidate ID 决定。这样只有动作后的局面改善才能证明资源消耗合理；候选模式固定为 `all-legal`，不使用墙钟裁剪。
9. 调用方必须回传同一权威回合已经提交的动作数；默认第 8 个动作只允许 `endTurn`，避免局部正收益令单步贪心形成无界长回合。
10. v4 不再把 AP、充能的消耗或交出控制权本身计入收益，`resources` 与 `turnProgress` 保留为零权重诊断项；`actionability` 也不再读取剩余 AP。攻击压力、未来攻击与战略位置权重调整为 `20,000 / 30,000 / 12,000`，安全权重为 `1,000`，使追击由动作后的位置和威胁收益驱动，而不是由花费驱动。
11. 对合法接收但公开观察完全不变的技能、移动或卡牌 transition 标记 `blocked=true`。零阶段 trace 保留该候选，但不为它计算 `F` 或参与最终选择，防止沉默、打坐等拦截动作被重复提交。
12. 位置估价权重更新或候选合同变化时递增 profile schema 版本；逐格追敌与真实伤害优先版本为 5，正式 agent ID 保持 `rvb-ai-zimse-v1`。
13. 部署阶段的锁定进度权重为 `500,000`，确保战斗位置权重增强后仍能一次性收束部署，不形成免费重复调位。
14. 未触发回合动作护栏时，节点数必须与严格合法候选数相等；候选选择先按 `胜利 > 非终局 > 平局 > 失败` 排序，再比较普通估价和 tie-break，防止可累加位置/攻击分覆盖立即胜利。
15. 最终 decision trace 记录稳定 `selectionReason`，使终局、静态分、费用、`endTurn` 与稳定 ID 的决胜层级可直接审计。
16. 候选估价通过 AI 环境的 `simulationMode: evaluation` 执行。该模式构造不含历史 replay/action-log 载荷的推演视图，只保留紧凑初始化记录，并保留 gameplay state、去重 action ID、root seed 与 RNG cursors；它继续调用同一个 `runBattleActionIsolated()`，不修改规则 runner 或正式提交路径。终局时 AI 环境修正 `settledAt.actionIndex` 并重算对应 hash，使它与完整模式一致。
17. evaluation transition 不生成完整 state diff 与第二份完整 pre-state hash；其最小 transition hash 在相同输入下仍确定。完整/轻量模式必须得到相同 accepted/rejected、blocked、公开观察、静态估价与 gameplay state hash。
18. blocked 比较忽略纯 `targetingRevision` 变化；若棋子、资源、状态、回合或其他公开观察发生变化，候选仍视为有效结果而不是 blocked。
19. 核心生命使用 `6×sqrt(剩余比例)`，非核心使用 `0.25×剩余比例`，使残血核心的边际伤害更高并鼓励集火。v5 把核心存活和生命权重提高到 `200,000 / 80,000`，护盾提高到 `30,000`，使真实掉血与破盾压过未兑现的攻击增益。该规则只读取公开 `isCore`，不识别具体角色或召唤物 ID。
20. v4 的双方共享核心接敌潜力由 v5 的决策方主动追敌分项替代，见决策 23。
21. 新内核提供 `BattleStateHashIndex` 后，每次规划为根状态构造一次索引并传给全部候选 transition。索引只复用不可变前态的 hash 结构，不缓存候选结果、不共享候选后态，也不减少候选；夹具必须验证索引根 hash 与输入状态一致且全部候选收到同一个索引对象。
22. 核心接敌的 BFS 距离场按公开地图尺寸和 walkable 格缓存，跨等价候选和后续决策复用；最多保留 8 个最近使用拓扑。缓存不含棋子占位、隐藏信息或候选结果；公开地图拓扑变化时重新计算。
23. v5 增加独立 `enemyProximity`：以公开可行走最短路为收益，常态取每个己方棋子的最近敌核距离；仅在己方核心数多于敌方的清场阶段，按敌我数量比混入双方核心的最大接近度一对一匹配，使部分优势兵力追击远处残敌，同时不改变前期接敌策略。无核心时退化为普通敌棋。距离按 walkable 格数量归一化，使追击保持连续但不压过真实伤害和生存。它不减去敌方到我方的镜像距离，避免主动推进信号精确抵消。中心位置降为 `5,000`，追敌为 `80,000`。
24. 斩杀机会按敌方目标去重：无论多少己方棋子能斩杀同一目标，该目标最多贡献一次；权重降为 `5,000`。实际击杀后虽然机会项消失，核心减员、生命、存活和墓地收益仍严格更高，避免 AI 为保留“可斩杀”分数而结束回合。
25. 攻击压力和未来攻击潜力也按敌方目标聚合，每个目标只取最强己方来源，权重降为 `2,000 / 2,000`；交叉火力不再按来源数量重复放大。位置安全只扣除己方受敌方覆盖的风险，不再把敌方受威胁重复算作安全收益。三项共同保证消灭残血目标不会因“理论压力消失”而降低估价。
26. v6 保留 v5 权重并加强优势清场：己方核心占优且敌核不超过 4 个时，用地图跨度的平方根缩短追击距离尺度，并奖励进入 `moveRange + 1` 的下一动作范围；只剩一个敌核时进一步集中追兵。敌方被至少二比一包围时，使用带 `ceil(己核数/敌核数)` 容量的全员均衡分派，替代只能保证每个目标一名追兵的一对一混合。势均力敌、劣势及前期不启用该增强，避免强追覆盖生命和生存判断。
27. 公开 `statusTags` 若带 `sourcePlayerId`，估价按来源与承载棋子的阵营关系判断正负：己方来源施加于敌方的公开状态视为敌方负状态，己方来源施加于己方视为正状态；缺少来源的标签保持中性，已经由公开 Buff/Debuff 表示的同类型状态不重复计分。这使血契等真实控制结果能胜过无收益结束回合，而不按具体角色或技能 ID 编码。
28. v7 适配 `progressive-reserve-v1`，但不改变单步合同。`deployReservePiece` 的每个“候选棋子 × 权威合法落点”仍各执行一次隔离 transition；部署后若新棋子带有公开 `deployment-first-move-free` 标签，追击与未来攻击分项把移动范围的 50% 视为静态接敌潜力。未兑现机动折价，实际免费移动后以真实位置计价，使固定局面中完整推进的追敌分严格高于保留标签。该估价不枚举第二个动作、不读取预备区私有实例，也不复制权威移动合法性。

## 不采用的方案

### 保留双层搜索并只降低节点预算

不采用。它仍使延迟随每个外层局面的后续分支相乘，而且不同局面的预算截断比例差异很大；较低预算得到的胜负也不能代表默认 profile。

### 在规则层增加快速近似模拟

不采用。它会扩大权威规则接口并形成第二套 transition 语义，超出零阶段任务范围。

### 按具体角色或技能编写站位脚本

不采用。零阶段必须阵容无关，并为后续训练提供通用而非内容特化的基线。

### 首版直接使用 minimax 或训练模型

不采用。敌方搜索和自动权重优化属于后续阶段；本版本先保证单步决策可解释、合法和可实时运行。

## 影响

- 搜索复杂度从“外层候选 × 后续候选”降为 `O(|A_legal|)` 次单步 transition，节点数可直接审计。
- 相同状态、玩家、root seed 和 profile 得到相同动作与 trace hash。
- 评分能解释立即胜负、存活、生命、资源、威胁、公开状态和位置潜力。
- 单步贪心不能识别必须先牺牲即时分数的多步组合，也不搜索敌方应对。
- 激进权重仍可能让棋子过度追击；v5 通过更高生命、护盾和位置安全权重约束风险，并用固定局面与真实 PvE 回放继续校准。
- 完整候选枚举会比旧 2 节点版本更慢，真实耗时取决于合法候选数和单次权威 transition 成本。
- 推演视图不携带历史 replay，不能被调用方当作正式可持久化状态；最终选择仍必须提交原权威状态并生成完整审计记录。

## 验证与回退

固定 fixture 验证公开视角镜像、隐藏信息不变、终局/斩杀、防守、中心与敌方目标推进、未来攻击、暴露风险、支援、机动、地形、每个严格合法候选恰好一次模拟、合法最终动作和确定性 hash。完整/轻量 transition 对照覆盖 accepted、blocked、rejected、公开观察、估价、gameplay hash、RNG authority 与输入 replay 不污染。性能样本记录候选数、节点数、P50/P95/最大耗时与非法动作；不得通过候选裁剪满足延迟目标。

回退整体移除零阶段模块、profile、测试和文档；现有 simple/planner 保持不变，无需迁移数据。旧双层实现不作为回退目标，因为它已证明不满足实时 PvE 性能。
