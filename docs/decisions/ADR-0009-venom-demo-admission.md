# ADR-0009：将毒液准入 Demo v0.1 暗方候选池

## 状态

已接受；角色准入决定仍有效，技能数量、行动点与规则限制已由 RED-129 部分取代。

## 日期

2026-08-17

## 背景

Demo v0.1 原有候选池为光方 13 枚、暗方 12 枚。RED-42 按功能缺口筛选下一批角色后，毒液（Eddie Brock，早期反派形态）被选为低复杂度的暗方机动与队形控制角色。项目负责人已确认其角色方案与数值，并批准建立单角色准入任务 RED-89。

候选池属于核心对局合同的一部分。仅生成未准入的数据会让角色无法通过 Demo manifest 进入标准选角流程，也会使产品合同与可加载内容不一致。

## 决策

- 将 `red-venom` 加入 Demo v0.1 暗方候选池，候选池由光方 13 / 暗方 12 调整为光方 13 / 暗方 13。
- 毒液使用 14 生命、3 攻击、1 防御、4 移动，配置宿主转移、共生拖行与利爪撕裂三项技能。
- 使用项目负责人明确提供并批准的原图作为毒液头像，仓库内保存为 `public/venom.png`；不新增或下载其他角色图片。
- 技能沿用现有目标选择、弹射物轨迹和伤害结算接口，不新增全局规则或状态来源。

## 后续修订（RED-129）

2026-08-29，项目负责人批准 RED-129 取代本 ADR 中“仅三项技能”“共生拖行 AP 0”以及“不新增规则”的限制：毒液新增被动【腐蚀】，因毒液的效果改变敌方位置时使其定身 1 回合；【共生拖行】改为 AP 1。毒液的 Demo 准入、基础属性、头像来源与候选池决策保持不变。

## 备选方案

### 只生成角色与技能数据，不加入 Demo manifest

未采用。该方案不会进入标准候选池，无法完成已获批准的单角色准入，也会留下产品合同、manifest 与实际意图不一致的问题。

### 等待雾子与我爱罗全部完成后一次性准入

未采用。RED-42 要求每名角色拆分为独立准入任务；独立交付更容易验证数值、机制和回退范围。

## 影响

- 暗方候选数增加到 13，与光方数量一致。
- RED-89 最初新增 0 AP、冷却 1 的强制位移技能；RED-129 将【共生拖行】调整为 AP 1，并新增【腐蚀】被动及其定身规则。
- 共生拖行复用确定性弹射物轨迹，空掩体阻挡、掩体角色优先碰撞、深坑放行均沿用核心合同。
- 不改变阵容仍需选择 8 枚不同核心棋子的规则。

- RED-89 当时仅让毒液在共生拖行保留“弹射物” keyword 与 effectTag，并清空波风水门全部技能 keywords、将角色显示名修正为“波风水门”；这些 RED-89 调整当时不改变水门技能机制。水门当前的锚点、标记与可选响应机制由后续 RED-129 负责，本 ADR 不再描述其现行规则。

## 验证方式

- 自动测试验证角色与技能加载、manifest 唯一性和四项技能（含【腐蚀】被动）的固定场景。
- 固定场景覆盖换位范围、四方向拖行、角色与地形阻挡、深坑、掩体角色、非法目标、AP 与冷却结算。
- RED-89 人工检查选角列表中暗方出现毒液，并核对技能介绍、目标提示与位置变化。
- RED-129 只以 `lib/game/**` 权威源码与数据回归验证【腐蚀】及 AP 调整；不修改或重建浏览器与 Android 的两个 `game-engine.js`，旧 bundle 不作为本次跨端证据。

## 回退方式

回退 RED-89：从角色与技能 manifest 移除毒液，删除头像、对应 JSON 与测试，恢复波风水门角色名及其技能原有关键词，并将核心对局合同候选池恢复为光方 13 / 暗方 12。无需迁移存档或修改经济数据。

只回退 RED-129 的毒液修订时：移除【腐蚀】技能及其定身规则，恢复【共生拖行】AP 0，并保留 RED-89 已完成的毒液准入、基础属性、头像和候选池决定。该局部回退不得修改或重建浏览器与 Android 的两个 `game-engine.js`。
