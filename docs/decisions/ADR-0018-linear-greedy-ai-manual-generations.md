# ADR-0018：一阶线性贪心 AI 使用人工触发的镜像进化策略逐代训练

- 状态：提议中
- 日期：2026-08-27
- 关联任务：RED-110
- 风险：Medium

## 背景

项目已有无头权威 AI 环境和逐局进程隔离的自博弈 runner，但没有参数优化循环。首个 PvE AI 的目标较低，开发设备又不保证有连续数小时的训练窗口，因此需要一个可解释、可复现、能按代停止且不会生成半代权重的最小方案。

## 决策

1. 一阶 agent 使用固定公开特征的线性加权和，只做一步贪心，不引入特征交互或多步搜索。
2. 每代使用 12 组正负镜像扰动，共 24 候选；每候选对 2 个训练 seed、1 个轮换阵容、2 个固定对手和红蓝换边，固定为 192 局。
3. 每局在独立子进程执行，父进程最多并发 3 局；每局完成即原子检查点，聚合和参数更新不依赖完成顺序。
4. 只有完整且无硬失败的一代才做 centered-rank 镜像梯度估计和一次 Adam 更新。非法动作、异常、循环、无动作和全部预算失败关闭。
5. 每次命令最多运行一代。完成后进入 `awaiting-user`；安全暂停进入 `paused`，恢复同一代；不设置后台自动下一代。
6. 完成或暂停时把紧凑审计证据提交到 RED-110 专用 GitHub 分支；原始逐动作对局仅本地保存。同步失败阻止下一代。

## 备选方案

- 对 17 个参数逐一做有限差分：每代比赛量至少随参数数目线性增长，且胜负噪声高，未采用。
- PPO、MCTS 或神经网络：可表达交互，但实现、样本和调试成本超过一阶目标，未采用。
- 单进程并发规则归约：模块级规则运行时仍有共享状态风险，未采用。
- 自动连续训练：设备可能中断且用户要求逐代批准，未采用。
- 公开局面裁决预算结束：可避免低阶候选整代无信号，但会改变 RED-110 的现有硬门禁合同，留待独立任务评审。

## 影响

- 收益：参数可解释、训练计划固定、同 seed/换边降低方差、任意完整对局后可恢复、不会产生半代更新。
- 成本：一步模拟仍昂贵；当前开发机一代约 10–18 小时，且线性模型无法表达组合关系。
- 风险：预算裁决可能偏向保守存活，训练 seed 和两个对手可能过拟合；候选不能跳过独立公开验证直接晋升。

## 验证方式

- 特征公开信息边界、有限值和 schema/hash 测试；
- 固定局面选招、终局优先和稳定同分测试；
- 24 候选、192 局、镜像扰动、centered rank 和 Adam 确定性测试；
- 缺局/硬失败不更新、暂停/恢复只补缺局、逐局检查点测试；
- 3 子进程真实规则冒烟、进度/ETA、GitHub 紧凑证据和分支门禁；
- 训练候选在独立公开 seed 上执行现有固定基线与人工回放。

## 回退方式

停止离线训练并 revert RED-110 文件。保留本地 run、失败复现和 GitHub 历史证据供诊断；无需迁移线上状态、存档或玩法数据。
