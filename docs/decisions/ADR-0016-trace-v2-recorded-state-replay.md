# ADR-0016：Trace v2 使用记录状态而非重跑规则

- 状态：Accepted
- 日期：2026-08-22
- 任务：RED-94

## 背景

RED-94 原先只导出 `rvb-match-trace/v1` 诊断 JSON。它保存动作和少量 hash，但没有足够状态事实来恢复整局棋盘，也不能逐步检查棋子、事件和随机流。

如果导入旧 Trace 后调用当前版本 `runBattleAction()` 重跑动作，结果会依赖当前角色数据、技能实现、规则版本和随机实现。增加角色、修改技能或修复规则都可能让旧对局得到不同结果；更糟的是，界面可能展示一局实际上从未发生过的比赛。因此“规则重演”不适合作为公开开发者工具的可信调试证据。

Trace 文件由玩家导入，属于不可信输入。该功能同时涉及终局公开数据、完整战局状态和本地持久化，按 High Risk 处理。

## 决策

### 1. 记录事实，不重算规则

采用 `rvb-match-trace/v2` 记录状态回放：

- 初始化时记录一个脱敏的完整初始检查点。
- 每条成功权威命令记录动作元数据、命令后的可物化检查点、语义事件、随机流游标以及命令前后权威状态 hash。
- 某帧的命令前检查点定义为上一帧的命令后检查点；第一帧使用初始检查点。归档不重复存储同一个相邻状态。
- 地图未变化时，帧写入 `inheritsMap: true` 并省略 `postState.map`；查看器必须从上一检查点物化完整状态后再展示和验 hash。地图发生变化的帧仍保存完整地图。累计 `actions` 不进入检查点，语义事件由帧的 `events` 单独保存。
- 检查点另有稳定 JSON 的 SHA-256 hash 链；hash 始终针对物化后的完整状态计算，导入时同时校验权威 hash 链和检查点 hash 链。
- 被拒绝或幂等重复动作不创建帧。

回放器只读取这些记录事实，不调用 `runBattleAction()`、`applyBattleAction()`、房间 API 或当前规则数据来推导结果。

### 2. 复用战场表现层

回放页复用正式 `BattleViewModel`、`BattleRenderer3D`、状态展示和战术几何模块。它传入物化后的当前记录检查点生成视图，不在 UI 中实现生命、移动、技能、胜负或合法性规则。棋盘覆盖整个视口；帧摘要、播放控制和按命令/棋子/事件/变化/完整性分组的检查器作为可折叠浮窗覆盖在棋盘上。

Trace 携带最小展示快照，包括记录时已知的棋子、技能名称、描述、类型、基础冷却/充能/消耗，以及安全本地图片标识；不携带技能执行代码。每帧棋子状态继续保存当前冷却、充能、解锁和剩余次数。未知角色、技能和事件保留稳定 ID，并以通用只读文本降级。这样新内容不会要求旧对局重新执行新规则。

### 3. 只在权威终局公开完整归档

- 进行中公开投影删除回放归档、action trace 和 applied action IDs。
- 只有已提交 `terminalResult` 的权威终局投影保留完整脱敏归档。
- 开发者中心和回放页检测真实对局活动标记并 fail closed。
- 功能不接受 roomId、不连接 WebSocket、不读取房间、不提交动作，也不写奖励或统计。

客户端活动标记只是产品门禁，不作为服务端授权；真正的数据边界由公开投影控制。

### 4. 把导入文件视为不可信输入

导入器在写入本地存储和打开回放前验证：

- 精确格式版本、必需对象/数组和基础字段类型。
- 32 MiB 文件上限，以及深度、节点、数组和字符串预算。
- 连续帧序号、前后权威 hash 链、检查点 SHA-256 链和终局连接。
- 危险原型键、认证/密钥/令牌等敏感字段。
- 外部 URL、`javascript:`、`data:text/html` 和不安全图片标识。

展示导入内容时只使用文本节点，不把字符串作为 HTML 执行。验证失败不会覆盖最近一次有效 Trace。

### 5. 本地持久化与版本行为

最近一场有效 v2 以 IndexedDB 为主存储；不支持 IndexedDB 的测试或受限环境才降级 localStorage。下载的 JSON 使用无缩进紧凑序列化，是可移植事实文件，不是正式存档或房间恢复格式。

v1 缺少检查点，明确提示“旧诊断格式，无法回放”，不得猜测补齐。未来破坏性变化必须使用新格式版本并显式迁移或拒绝，不能静默套用当前规则。

## 后果

收益：

- 回放展示的是实际记录状态，不会因新增角色或当前规则变化而重写历史。
- 可以在任意命令边界检查棋盘、棋子、事件、关键差异、随机流和 hash。
- 表现复用正式战场组件，避免第二套棋盘和 UI 规则。
- 进行中对局不公开完整历史，开发者工具没有真实房间控制能力。

代价与限制：

- 记录状态仍比纯动作日志大。链式结构避免相邻 pre/post 重复，不变地图采用有界继承，累计 actions 不重复写入，下载采用紧凑 JSON；长局仍可能超过 32 MiB。固定 seed 的 4 命令验收样本从旧实现的 588,507 字节降为 135,349 字节，其中固定开销 67,746 字节、样本平均每帧约 16,900 字节。按该简单样本估算 32 MiB 约容纳 1,981 帧；复杂选择会话、卡牌和扩展状态会降低容量，因此这不是协议保证。
- MVP 不记录每个动画毫秒，也不为一个命令内部每个语义子事件保存完整中间检查点。
- 展示快照保证可读降级，不承诺未来客户端像素级还原旧资源。
- IndexedDB 只保留最近一场；多场管理、流式分块和云分享需独立任务。

## 备选方案

### 用当前规则重跑动作

拒绝。跨角色、技能和规则版本不稳定，可能生成从未发生的状态；同时扩大导入文件触发规则执行的攻击面。

### 每帧同时保存完整 preState 和 postState

拒绝。相邻命令的 postState 与下一命令的 preState 完全相同，会近似翻倍体积。链式检查点仍能完整定义每帧前后状态。

### 保存任意深层状态差量

不采用通用 JSON patch 或任意字段差量。唯一例外是同一 v2 内明确定义的顶层不变地图继承：导入器先物化完整状态再校验该完整状态的 hash，地图变化时必须重新写入地图。更广泛的差量协议、分块和迁移可在 v3 重新评估，但需要独立 ADR。

### 压缩成短回放码或上传云端

不在 MVP。短码需要服务端存储、生命周期、隐私和可用性设计；把整局压进少数字符在当前状态规模下不现实。

### 复用真实房间或观战接口

拒绝。会把局外调试器连接到实时权威状态，扩大作弊、安全和生命周期风险。

## 安全与隐私

回放检查点递归删除认证信封、签名、token、账号标识、公私钥、助记词、密码、cookie、session、secret 和 credential 等字段。服务端终局投影与浏览器导入器形成两道边界。未知字段也必须通过预算、危险键和 URL 检查。

Trace 仍可能包含公开玩家名称、棋子选择和完整对局策略；下载/分享由用户主动触发，后续若提供云分享必须新增隐私和保留期设计。

## 回退

代码回退为撤销 RED-94 提交。没有数据库迁移、随机算法或正式存档变更。已有 v2 文件可以保留；旧客户端会拒绝未知格式。回退不会删除用户下载文件，本地最近记录可由开发者中心清除。
