# ADR-0014：服务端权威成长型回合计时

> RED-138 取代说明：本文涉及公开初始/最终站位、个人重投与独立 45 秒部署锁定的条款只适用于 `legacy-reroll-v1` 和缺少 mode 的历史状态。新建对局默认使用 [ADR-0024](./ADR-0024-progressive-reserve-deployment.md) 的渐进部署，候选、落位和免费移动共用当前成长回合时限。
>
> RED-164 取代说明：本文第 4 条关于“计时始终跟随 input owner”及回合外 pending 超时结束活动回合的语义，已由 [ADR-0025](./ADR-0025-off-turn-pending-response-timer.md) 取代。回合外 pending 现在冻结普通回合计时并使用独立 15 秒响应计时。

- 状态：Proposed（等待 RED-36 人工验收）
- 日期：2026-08-20
- 关联：RED-36、RED-31、RED-34

## 背景

Demo 合同要求完整轮次 1–2、3–4、5–6、7–8、9+ 的单回合时限分别为 45、60、75、90、105 秒，最后 15 秒进入烧绳。无有效玩法动作的超时需要影响该玩家自己的下一回合，并在连续第三次时复用权威投降终局。浏览器本地时间、刷新和服务端处理耗时都不能改变规则结果。

## 决策

1. `lib/game/turn-timer.ts` 定义纯规则状态、阶梯时长、投影和可注入的 `AuthoritativeRuleClock`；生产时钟使用 epoch-shaped `performance.timeOrigin + performance.now()`，测试使用伪时钟。
2. 房间协调器在异步读取前记录命令的逻辑 `receivedAt`，并以每房间串行锁冻结逻辑权威时钟，直到规则、唯一一次 CAS、序列化和结果入队全部结束。恢复时只累加进程内的排除时长，不改写已提交的 `deadlineAt/burnStartsAt`，也不估算或预测第二个版本。
3. `turnTimerBurn` 和 `turnTimeout` 只能由服务端调度器发出，并与普通动作一样通过 `runBattleAction()` 和唯一的房间版本 CAS。传输层只收到该次 CAS 已真实提交的快照；失败的 CAS 重试不会广播 speculative authority version，跨过 15 秒阈值的处理也不会令烧绳投影反转。
4. 计时归属始终跟随当前 `inputOwnerPlayerId`。计时从 action 延续到 end，覆盖所有 pending 与“回合结束时”选项/目标输入，直到收尾完成并真正切换下一回合；只有终局停止。pending 转给对手时保存活动玩家已消耗后的剩余预算和烧绳状态，响应完成后恢复而不重置。玩家主动结束回合所产生的 end phase 响应继续使用当前回合预算；若 action phase 的预算已经归零，超时强制执行一次 `endTurn` 时才产生 pending，则确定性取消该输入并直接进入下一回合，不补发新预算。end phase 响应超时也直接进入下一回合，不重复执行 endTurn 触发或持续时间结算。只有输入 owner 同时也是活动回合玩家的无操作超时才累加，下一次自己的回合使用 20 秒。
5. 第三次连续无操作超时由 RED-34 的权威终局结算生成 `timeout-surrender`，不新增第二套胜负逻辑。
6. 公开快照携带 `serverNow` 和只读 `turnTimer` 投影。客户端只用服务器期限和校准后的显示时钟刷新 HUD，不提交超时、不重置期限、不改写规则状态。
7. `legacy-reroll-v1` 与缺少 mode 的历史状态继续遵守 RED-31 的部署可见性合同：双方初始/最终站位公开，只有尚未提交的个人重投选择留在服务端私有状态。新建渐进部署不适用本条。

## 后果

- 同一状态、种子、伪时钟和命令序列产生相同结果，测试不需要真实等待。
- 浏览器刷新或多客户端重连只重新投影剩余时间，不产生房间写入。
- 系统计时动作会进入 Action Trace/动作日志，便于记录阶段、输入所有者、活动回合、期限和连续超时次数。
- 调度器超时后若权威状态进入 `bot` 的 action phase，会立即复用统一 bot-turn 队列继续 PVE 对局。

## 回退

- RED-36 明确不处理断线/重启后的时钟恢复，因此排除时长只保存在当前服务进程；未来若扩展进程恢复合同，需要持久化或重建该偏移。
- 回退 RED-36 协调器、规则状态、客户端 HUD 和调度接线，恢复无回合倒计时的受控开发模式。
- 不保留客户端权威 timeout，也不改动 RED-31 部署、RED-34 终局或存档格式。
- 本实现没有数据迁移；回退通过 revert RED-36 PR 完成。
