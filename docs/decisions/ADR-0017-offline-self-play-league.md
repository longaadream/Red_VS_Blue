# ADR-0017：离线成对自博弈使用不可变历史档案与硬门禁

- 状态：提议中
- 日期：2026-08-22
- 关联任务：RED-87
- 风险：Medium

## 背景

RED-84 已提供无头确定性环境，RED-86 已提供通用回合规划器，但项目仍缺少统一的版本比赛、历史对手、seed 隔离、机器报告和候选晋升边界。只对战当前代、只看 Elo、混用训练与保密 seed，或在进程级 TriggerSystem 上并发规则归约，都会产生不可复现或被优化污染的结果。

## 决策

1. 所有离线比赛只通过 `aiEnvironmentV1` 枚举与模拟，agent 不复制规则。
2. 每个 seed/阵容样本必须让 agent 与其阵容整体交换座位，形成同 root seed 的 pair。
3. 训练、公开验证和外部保密候选 seed 分层；保密集合只能在候选评估时通过私有文件注入并校验 commitment。
4. agent 与 roster 使用不可变版本档案；报告内嵌快照和 config hash，历史回放不依赖可变“最新版本”。评估至少包含一个显式历史对手。
5. 非法/拒绝、异常、重复状态、动作/回合/节点预算和无动作先执行硬门禁；门禁通过后才展示胜负矩阵与拆分证据，系统不按单一 Elo 自动晋升。
6. 报告 schema v1 同时记录 rules/content/config hash、代码 commit、原始动作证据、终局、矩阵、性能环境和最小复现。
7. 每局在独立子进程中串行执行；默认一次一局，允许父进程以受控 `processCount` 并发互不共享规则状态的单局子进程。父进程按确定性 schedule 聚合并逐局写检查点，进程内并发仍失败关闭。

## 影响

- 收益：固定样本可成对复现，历史冠军可长期回放，失败 seed 不会被排除，候选晋升证据不再被单指标简化。
- 成本：完整 8 人阵容和历史对手池仍耗时且报告体积增长；提高 `processCount` 会近似线性增加峰值内存。
- 边界：不实现优化算法、在线学习、客户端接入、规则/数值/随机修改或训练数据入库。

## 验证

- schema/config/hash、三层 seed 隔离与 holdout commitment 测试；
- 多阵容、每 seed 自动座位交换、重复 trace/终局 hash 测试；
- 历史快照回放、胜负矩阵与座位/阵容/seed 拆分测试；
- 拒绝、异常、循环和确定性预算硬门禁测试；
- 正式 RuleRuntime/TriggerSystem/动态代码缓存连续对局隔离测试；
- 单局子进程进度、稳定聚合、检查点 commitment 与中断恢复测试；
- 单命令固定基准、机器报告、真实吞吐量和最慢 fixture 证据。

## 回退

整体 revert RED-87 的纯离线代码、脚本、配置、测试和文档。保留私有输出中的失败 seed 与 trace；无需迁移玩家存档或玩法数据。
