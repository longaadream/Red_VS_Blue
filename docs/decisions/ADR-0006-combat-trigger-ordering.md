# ADR-0006：战斗触发器的跨类别稳定排序

状态：已接受  
日期：2026-08-15  
接受日期：2026-08-16  
关联任务：[RED-61](https://linear.app/redvsblue/issue/RED-61/定义并实现战斗触发器跨类别稳定排序)  
风险：Medium

## 背景

`TriggerSystem.checkTriggers()` 依次处理全局规则、棋子规则、玩家规则、响应卡和 AttachedEffect。此前全局/棋子规则按 priority 降序，玩家与响应卡不排序，AttachedEffect 按升序且默认值为 `50`；同优先级依赖数组或注册顺序。

## 决策

一次事件分发按以下键确定执行顺序：

1. 类别 rank（升序）：全局规则 `0`、棋子规则 `1`、玩家规则 `2`、响应卡 `3`、AttachedEffect 触发器 `4`。
2. 同类别内按 priority 降序；未声明 priority 时为 `0`。
3. 同 priority 保留事件开始时的玩家、棋子、手牌、附加效果和触发器数组快照顺序；稳定标识仅用于需要进一步区分的消费者。

消费者在当前类别开始执行前必须以快照读取。执行期间的弃牌或其他集合变更不得改变当前事件尚未执行的消费者顺序。

AttachedEffect 从“数值小者先、默认 `50`”统一为“数值大者先、默认 `0`”。这是有意的兼容性变化；实施前应盘点带显式 priority 的 AttachedEffect，并在固定状态回放中验证依赖旧顺序的内容。

`blocked`、`pending` 与异常的语义不由本 ADR 改变。

## 影响

- `checkTriggers()` 必须在每个类别中以统一 priority 语义排序。
- 响应卡须基于手牌快照执行，不能用会受弃牌影响的原数组索引继续扫描。
- RED-61 必须提供表驱动回归测试，覆盖类别顺序和 priority 方向。

## 验证方式

以固定战斗状态构造全局、棋子、玩家和 AttachedEffect 消费者，断言类别 rank 与 priority 轨迹；并验证响应卡的手牌快照不受本次弃牌影响。使用相同状态和命令重复执行，应得到相同轨迹。

## 回退方式

若 RED-61 引发规则回归，回退该任务的独立提交，并用失败场景的固定状态与触发器轨迹诊断；不得通过静默重排内容数据掩盖问题。
