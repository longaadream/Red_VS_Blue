# ADR-0026：暗方角色的目标规则、秘密状态与复活结果

- 状态：已接受
- 任务：RED-163
- 日期：2026-09-01

## 背景

蓝染、乌尔奇奥拉与葛力姆乔需要共享【灵压】目标条件、镜花水月的秘密标记与单体技能目标改写、伤害驱动变身、首次死亡归刃，以及可重复触发的回合外 pending。把这些行为按角色或关键词写进主进程会让后续内容无法复用，也会使 UI、AI 与服务端产生不同的合法目标。

## 决策

1. 技能可用 `statusTag.rule` 或 `statusTag.rules` 引用纯 `targetValidation` rule。首个主要棋子目标由权威 targeting 统一执行这些规则；【灵压】只是数据名，主进程不识别该名称、角色或技能 ID。
2. `beforeSkillUse` 规则可返回 `targetReplacementPieceId`。规则负责声明并校验自己的替代目标集合；镜花水月允许选择蓝染 3 格内、属于蓝染敌方的存活角色（包含原施法者），因此替代目标可不满足原技能的阵营与施法者距离限制。pending 恢复时只改写挂起根动作的主要目标，不重新支付成本、不重复技能、也不伪造第二条动作。
3. `visible=false` 的棋子 statusTag 对所有者保留，对手与观战者的所有棋子容器投影移除。镜花水月以一个公开激活标签和一个私有目标标签表达，规则通过私有标签判断触发；技能数据同时声明隐藏通用战斗日志中的目标名称。
4. 伤害触发的治疗进入现有 `healQueue`，不在 DamageBatch 的同步回调内递归结算。乌尔奇奥拉的两条伤害规则分别记录造成与受到的每次正伤害，并由回合开始规则完成一次归刃。
5. `onPieceDied` 规则可返回显式、经过安全整数校验的 `revival` 生命档案。DeathBatch 在既有击杀/死亡生命周期之后应用档案，再按现有最终存活判断决定是否移入墓地。葛力姆乔首次死亡仍产生一次死亡事件和击杀充能，随后以归刃档案原地复活；第二次死亡进入普通终结。
6. 归刃后技能只登记在模板的 `transformedSkills` 中，供棋子简介作为衍生技能展示，不进入初始实战技能表。归刃规则使用既有通用技能增删 ABI 授予【黑虚闪】；葛力姆乔归刃时移除【王虚的闪光】并授予【豹王之爪】。
7. 镜花水月与狩猎本能复用既有可取消 pending 事务及 RED-164 的 15 秒回合外响应计时，不创建角色专用计时器或 pending 状态。

## 结果

- UI、AI、权威 reducer 与回放共享同一目标候选和状态变化。
- 新的数值比较型技能条件可通过 statusTag/rule 复用，不增加玩家关键词数量，也不增加关键词硬编码。
- 目标改写保持单次原子技能语义；取消或没有替代目标时原技能继续结算。
- 私有标签不会通过公开战局或 AI 观察泄露，但激活状态仍可公开展示。
- 复活发生在冻结 DeathBatch 内，不允许规则直接破坏批次成员或最大生命不变量。

## 未采用方案

- 阻止原技能后重新施放：会重复目标校验、触发器、成本、冷却、日志和随机消费，不能保持原子语义。
- 在 `turn.ts` 按【灵压】、蓝染或技能 ID 分支：不可复用，并会让目标查询消费者分叉。
- 在伤害回调内直接治疗或直接改写死亡候选生命：违反确定性 EffectBatch/DeathBatch 的结算边界。
- 为每个回合外角色建立专用 pending 或计时器：与现有统一事务和 RED-164 冲突。

## 验证与回退

- 固定 seed 验证灵压合法/非法目标、镜花水月替代/无替代/到期、黑棺双段、乌尔奇奥拉伤害计数与归刃、葛力姆乔首次/再次死亡、豹王之爪五段与同回合多次狩猎。
- 验证对手与观战者看不到私有 statusTag，技能与规则清单可被生产加载器解析，目标 fixture hash 与新增内容同步。
- 回退 RED-163 时移除三名角色、对应技能/规则与 manifest 项，回退通用 target-validation、目标改写和 revival 返回面，并恢复文档与测试。没有存档迁移、依赖或经济数据变化。
