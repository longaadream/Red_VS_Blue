# ADR-0015：权威交互会话生命周期与确定性续接

状态：已批准，RED-121 扩展
日期：2026-08-27
关联任务：[RED-97](https://linear.app/redvsblue/issue/RED-97/统一交互式触发会话取消语义与规则队列续接)、
[RED-121](https://linear.app/redvsblue/issue/RED-121/准入维伦与图拉扬并重构圣光手牌体系)
风险：High

## 背景

回合开始事件可能连续经过棋子规则、玩家规则与响应卡。旧实现只保存当前弹出的目标或选项，没有完整保存消费来源、剩余规则队列、响应卡快照和原动作；取消则直接清空 pending 状态。结果是波风水门的地格请求被拒绝后，客户端清除了本地选择而服务端仍在等待；取消水门后，观者等后续消费者也不会继续执行。

同类风险还存在于技能、卡牌、伤害、治疗、召唤和状态变化：调用方如果忽略 `needsOptionSelection` / `needsTargetSelection`，会提交半完成状态，或者在重试时重复结算成本、随机数和已完成消费者。

## 决策

1. option 与 target 都是服务端权威、版本化的 pending interaction session。会话至少包含 `selectionId`、`stateRevision`、所有者、来源和取消策略。
2. 所有提交先在原状态上校验玩家、会话 ID、修订号和候选值，再克隆和执行。无效、过期或重复提交不改变状态、随机游标或规则限制。
3. 每个逻辑根动作建立统一、可序列化的事务记录：根动作、动作前 targeting revision、确定性运行时 checkpoint、有序选择答案及当前消费者键。权威战局在 pending 期间保持动作前状态，不保存或广播半结算状态。
4. 恢复时从根动作重放；消费者键由类型、规则/卡牌 ID、来源、事件类型和确定性消费者序号组成。规则与响应卡在首次执行交互分支前消费匹配答案，因此同一规则多次出现也不会串用答案。
5. 取消规则或响应卡交互时记录“跳过当前消费者”并继续重放；声明 `cancelValue` 时按该值恢复。直接技能/卡牌释放选择没有 fallback 时取消整个根动作。`canCancel: false` 必须由合法选择或确定性超时候选完成。
6. 原动作在全部交互完成前不支付行动点、充能、冷却或卡牌成本，不移出手牌，不写成功日志，也不提交伤害、治疗、加牌、召唤或状态变化。最终成功时整笔只提交一次。
7. `before*`、`after*`、伤害、治疗、召唤、加牌、状态变化、回合开始/结束及响应卡统一支持暂停。暂停信号必须穿透技能/规则沙箱，不能被包装为普通技能失败。
8. 客户端提交会话凭证。一次提交被权威端拒绝但会话仍存在时，客户端保留选择态并允许重试；只有权威状态表明会话结束时才清理交互 UI。
9. AI observation 与候选动作暴露同一 option 会话凭证和取消能力。该字段扩展保持 AI 环境 v1 的向后兼容，候选 ID 仍按完整动作重新计算。
10. 公开投影只暴露交互所需字段；事务根动作、答案、checkpoint、trigger context 和 continuation 永不下发。
11. 若交互在移动、伤害或其他暂态变化之后请求目标，合法候选按挂起点的服务端私有暂态快照计算；权威战局仍保持动作前状态。盖章后的候选集用于提交校验，暂态快照与逻辑挂起回合 `suspendedTurn` 不进入公开投影。
12. 旧技能返回的后置 `pendingTargetSelection` 作为合成 target consumer 接入事务：重放恢复到相同后置选择点，再消费答案并执行一次 `effectCode`；不得先提交技能成本或核心效果。

## 备选方案

- 取消时清空全部 pending：实现简单，但会跳过观者及后续规则，破坏触发顺序。
- 保存可执行闭包或 JavaScript 调用栈：无法稳定序列化、跨进程恢复或进行公开投影。
- 仅修前端点击：可以掩盖一次拒绝，却不能修复服务端队列丢失和取消语义。
- 为每个 `after*` 或伤害/治疗调用点单独维护 continuation mode：状态组合会持续膨胀，也无法覆盖规则内部嵌套事件。

## 影响

- `suspendable-action-transaction.ts` 负责协议、消费者序号、答案消费和暂停信号；`turn.ts` 负责根动作 checkpoint、重放、提交与回滚；`triggers.ts` 负责规则和响应卡的答案注入。
- `pending-interaction.ts` 集中定义 option 会话和稳定错误码；target 会话继续复用 ADR-0005 的权威候选协议。
- UI 与 AI 不再自行推断取消能力或省略凭证。
- `turn-timer.ts` 使用服务端私有 `suspendedTurn` 归属逻辑挂起回合；公开投影通过白名单排除该字段、事务记录及候选暂态。
- 旧的专用 `cardAfterAfterTrigger` 等 continuation mode 被统一事务取代，不再按调用点扩展。
- 旧的、未版本化 pending option 存档或内存状态不会被静默接受；Demo 尚未承诺跨版本恢复这类进行中对局。

## 验证方式

- 固定状态回放水门地格 → 观者选项 → 行动阶段，验证顺序和次数。
- 取消水门后仍进入不可取消的观者选项；取消观者得到稳定拒绝。
- 过期 ID、非法地格和非法选项均保持输入状态不变，随后合法重试成功。
- 覆盖 option → target → 剩余规则 → 冻结响应卡的混合链，每个消费者恰好一次。
- 覆盖飞雷神与志志雄伤害前选项，验证恢复时目标凭证、成本和伤害只提交一次。
- 覆盖 `afterCardPlay` 与嵌套 `afterDamageDealt` pending，验证 pending 期间成本、手牌、伤害和日志均未提交，恢复后只提交一次。
- 覆盖主动卡牌、响应卡内部再次触发交互规则，以及续接后异常，验证卡牌执行边界不吞暂停信号。
- 覆盖移动后按暂态位置计算候选，以及旧式后置目标 `effectCode`，验证候选与提交几何一致且原动作只提交一次。
- 覆盖恢复阶段异常、非法/过期/重复提交、取消和超时，验证输入状态、随机游标和规则限制不被污染。
- 验证玩家、对手和观战公开投影均不包含事务内部字段。
- 运行聚焦回归、受影响模块测试、全量测试、类型检查、Lint、编码检查、浏览器引擎构建和真实战场冒烟。

## 回退方式

整体 revert RED-121 的统一事务提交及生成的跨客户端引擎文件，并恢复 RED-97 的队列续接实现。不得只回退客户端凭证、服务端会话类型或某一个客户端 bundle，否则会重新形成客户端与权威状态分叉。
