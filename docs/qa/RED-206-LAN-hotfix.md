# RED-206：Windows 虚拟局域网连接热修

基线：`origin/main`，`0a75d9928fd4e79ffdad529a4b11c92bd5909f30`。

用户报告同一 Radmin 房间内发现主机后，健康检查超时。发现代码原先直接接受 UDP 中的地址，并按主机 ID 去重；因此先到的不可达无线网卡地址会排除后到的可达虚拟网卡地址。连接期间子网扫描继续运行，取消扫描也不取消在途 HTTP 请求。

修复先验证广播候选的 HTTP 健康端点，再发布主机列表项。Windows 广播携带其他接口候选，兼容只有单地址的旧公告。UDP 与子网探测共用最多 16 个请求槽，UDP 优先；取消清空排队任务并中止在途请求。用户点击连接先取消扫描。提示同时说明虚拟局域网地址，并更新全量扫描耗时说明。

验证：新增三个失败回归在修改前全部失败。最终 7 个定向测试文件、42 项通过，覆盖相同 ID 不可达地址先到、单公告多接口、共享并发上限、取消队列、实际 fetch 的 AbortSignal，以及连接前取消扫描。Electron 编译、根类型检查通过。独立 AI 审查实测全局峰值 16、取消后在途归零，最终通过。

Windows 本地分发使用已验证的 0.1.2 客户端副本，仅替换编译后的主进程及三份页面文件（页面同时同步到两个分发目录，共七个文件）。执行既有 `verifyClientPackage` 验证分发内容。未修改资源规则、数据库格式、系统防火墙或正式更新地址。候选目录和分发清单位于 `dist/RED-vs-BLUE-0.1.2-LAN-hotfix`。

回退：退出热修版，重新运行原 0.1.2 客户端。三台真实 Radmin 设备之间的连通性需玩家复测，测试未声称替代其网络环境验收。用户已明确授权直接发布此 Windows 热修 Release。
