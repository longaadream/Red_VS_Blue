# RED-252：选择结果原句保存与能力组伤害归因

基线：`main` / `082166c6b803b2e838bce5f0f6824c5bbc714dd6`。沿用 `codex/RED-252-modular-content-graphs` 与 PR 240；本轮风险 Medium，未合并或发布。

## 本轮用户确认

- 选择器返回一个有类型的选择结果；在该语句内保存或新建变量，不另显示“新建变量＝当前目标”。多次选择分别保存，互不覆盖。
- 伤害里的“技能引用”改为实际能力组引用。主动技能仍是独立实例，冷却、次数和等级的原规则不变；技能执行仍返回成功或失败。
- 用户当前打开的编辑器和未保存草稿保留。复现和验证使用隔离项目，不用重新载入用户窗口来覆盖草稿。

## 已定位的原问题

1. 结果绑定的编译内部声明被渲染为第二条作者语句。界面应合并显示与产生结果的语句精确关联的声明，独立手写声明仍显示。
2. 旧伤害的 `skillId` 出现在可点击句子中，却被 `isInternalAuthorParameter` 禁止编辑；点击后误显示“请先完成前置选择”。已有来源、目标和数值并不能解除这条错误限制。
3. “当前技能.倍率”已翻译到字段 `powerMultiplier`，当前技能实例字段注册没有支持它。修改源接口后，还必须重新构建实际编辑器使用的共享 bundle。
4. 中文“目标”符合变量名规则。命名错误写入全局提示后，切换到另一个合法绑定仍可能保留旧错误。磁盘没有截图中的未保存草稿，不能断言用户当时输入了什么；回归使用明确的“甲非法输入→查看乙合法绑定”场景。

## 独立审查发现

- 两条都有结果绑定的语句交换位置时，原实现只移动当前语句的绑定，可能拆开相邻语句与其绑定。应验证双方组连续，以及反向移动可恢复。
- 规则事件携带上游 `skillId` 时，初版当前能力组解析误选攻击者技能的组。规则入口应优先当前规则实例与规则持有者；事件来源不等同于规则执行者。
- 当前能力组引用需验证跨选择等待后的精确恢复，不能只验证同步 WeakMap 句柄。旧伤害版本与新归因版本需分别验证，不能据新模块通过宣称旧数据已自动迁移。

## 行为边界与回退

伤害的新接口默认：主动技能使用当前能力组，其他入口未填写能力组时不归因。切换到当前能力组会建立真实引用；没有当前组的卡牌不伪造组。旧伤害图仍按原版本加载，不在打开文件时静默改写。

无默认值结构字段的入口取 schema 字段与现有字段的并集。显示未填写不等于声明或赋值；应用前不预填，已有额外字段保留。原绑定已失效时保留可见声明和诊断，不能把错误藏掉。

本轮不改变对局存档格式、随机算法、资源经济或选择网络协议。回退时成组撤回本轮句式、结果绑定、能力组归因版本及共享生成物；保留旧版本读取能力。测试产物是隔离作者项目，不改用户当前窗口及未保存草稿。本轮证据不等于长期 RED-252 全部内容最终验收。
