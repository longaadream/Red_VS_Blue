# 现有棋子技能与句式编辑标准核查

日期：2026-10-13。关联：[RED-252](https://linear.app/redvsblue/issue/RED-252)。本轮为只读静态核查；同时修复的中文句号和 Tab 输入见 [预览验证记录](authoring-preview-review-2026-10-13.md)。没有修改游戏规则或正式引擎。

## 结论

**当前目录和独立预览尚不能作为“所有现有棋子技能均可完整编写”的交付。** 变量、复杂表达式、筛选、分支、循环、伤害、治疗、位移、状态、规则和 extension 已能组合很多基础效果；仍缺少若干生命周期区别、定义配置、事件类型和选择配置。设计文档中已经确认的能力，也有尚未完整落到这套句式目录的部分。

本报告区分三件事：手册里有设计契约、预览中能完整表达并提示类型、实际游戏宿主能编译并执行。现有资源有 gameplayModules、接口有 sourceIds、或预览接受自由文本，都不能单独证明后两件事。这里不报告“已迁移百分比”，也不把缺少提示一律判成运行引擎没有能力。

## 用户截图的写法

选择器最外层的“每项”是棋子；`每项.位置.地格效果.任意满足(...)` 内层的“每项”是地格效果实例。选择返回单个棋子后，用 `结果4.阵营 != 当前棋子.阵营` 分支，对敌方造成伤害、对同阵营治疗，结构与类型关系正确。`伤害量` 需要在可见作用域中先声明为数值。无需额外编写棋子是否存活等 fallback。

**当前数据有一个实际不匹配：** 地格效果的 `.类型` 暂时映射底层 `tileType`。[天照地格定义](../../../data/tiles/amaterasu.json) 是 `id: amaterasu`、`name: 天照`，[天照之炎](../../../data/skills/sasuke-amaterasu.json) 的模块参数使用 `tileType: amaterasu`。因此截图的 `每项.类型 == "天照"` 在这个映射下不会命中；临时匹配实际数据应写 `每项.类型 == "amaterasu"`。

这不是要求作者长期记英文 ID。应由资源目录提供显示为中文“天照”的有类型引用候选，并定义它与实例类型字段的比较关系。现预览仅有通用文本类型提示，未完成这条资源语义接入；不能把它宣称为已经支持中文定义引用。

## 2026-10-13 方案讨论后确认

用户接受上述补齐方向，并回复“没事变量名用英文就用英文吧，可以的，我没意见”。本节记录决定，不表示目录、编译器或运行引擎已完成对应修改。

- 英文变量名及既有英文标识可以保留，不强制翻译，也不批量重命名现有中文变量。句式、参数说明继续使用中文。名称语言不改变引用身份和比较语义：文本 `天照` 不会因此自动等于 `amaterasu`。
- 棋子仍为统一类型；同一个召唤语句提供明确的方式参数：**创建新实例**、**原实例回场**。前者创建新身份，后者保留指定实例身份。不依靠棋子当前是否在场隐式切换含义。
- 保持通用声明、事件字段、选择、返回类型和原子语句组合的补齐方向。先前提出的批量结果保持对应序号、失败项不压缩，以及句式编辑/逐参数编辑方式一并按方案推进。
- 具体选项可见范围、多选参数和各定义字段等未展开细节仍作为后续提案讨论，不能将总体认可视作对未展示默认值的确认。

### 选择数量与稳定返回类型：已确认（数量配置修订）

用户认可上一轮返回类型、顺序及重复选择方案，并明确修订：“加一个最少最多，不要跟恰好做成两种，恰好 n 就做成最多 n 最少 n”。

- 同一个选择语句有单选和多选配置。单选返回 T；多选始终返回元组<T>，实际只选一项时仍返回元组。返回形状在编写时确定，不依运行时选中数量变换。
- T 由选项映射的值类型推导。数量统一只使用“最少数量”和“最多数量”两个参数，均支持数值表达式；固定选 n 项就是最少数量 n、最多数量 n。不设独立的“恰好”参数、模式或另一套接口。
- 多选结果按选择顺序排列，使用 [1] 访问第一项；同一个选项默认不能重复选，不同选项返回相同值时保留各自结果，遵守元组可重复语义。
- UI 数量编辑统一使用最少/最多两项，不另设“恰好 / 范围”切换。选项不足和交互失效由引擎处理并给出诊断，不能留下无法完成的等待，也不要求作者增加检查语句。

例：选 1 项为最少 1、最多 1；选 2 项为最少 2、最多 2；选 1～3 项为最少 1、最多 3。

### Rule 触发入口及伤害事件字段：已确认

用户回复“可以的，继续吧”，认可上一轮入口及事件字段提案。

- Rule 入口配置触发器、监听范围、优先级和效果正文；优先级沿用原有顺序。监听范围沿用当前棋子、己方阵营、本玩家、全场，敌友关系按阵营。
- 范围筛选的对象由触发器决定：造成伤害前/后看伤害来源；受到伤害前/后看承受者；被指定为目标前看被指定目标；移动/位置改变看发生移动的棋子；死亡前/后看死亡棋子。自伤分别触发造成和受到伤害，沿用可计数两次的决定。
- 伤害事件字段：来源（棋子/玩家/卡牌实例）、承受者（棋子）、伤害量（数值）、伤害类型（普通/真实）、实际伤害量（数值，仅伤害后提供）、extension（扩展数据）。编辑器随所选触发器提供对应字段。
- 前事件允许按事件契约修改，后事件的结算数据只读。在伤害转移前可以使用普通赋值 `当前事件.承受者 = 当前棋子`，随后防御、扣血与派发由权威伤害流程继续；作者不重新造成一笔伤害。
