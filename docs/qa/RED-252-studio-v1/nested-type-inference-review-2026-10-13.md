# 独立预览：嵌套类型推导修复

关联：[RED-252](https://linear.app/redvsblue/issue/RED-252)。角色：实现者。风险：Low；仅独立 HTML 预览与 QA 记录，不变更正式引擎、工作台、内容或资源包。

## 复现与根因

在“选择棋子”的筛选条件输入 `每项.位置.地格效果.任意满足(每项`，内层候选错误显示“未知类型”。先用真实 Chrome 复现断言失败，证据见 `output/authoring-preview-nested-types-before.txt`；用户截图是修改前的界面证据。

选择器候选类型被注入得过晚；内层谓词绑定又被用于解释外层来源。同名“每项”的作用域混用后，无法从棋子的位置继续找到地格效果元组。相邻路径还存在泛型声明未具体化、调用链/下标接收者截断、实例别名和返回标签未连到类型结构的问题。

## 修改

- 先建立选择器外层上下文，再按函数嵌套逐层推导每项；每个调用使用进入该调用之前的绑定解释其来源。退出谓词恢复外层。
- 调用结果、链式调用、下标、可空类型和实例别名继续传递具体类型。普通调用、成员调用、中文全角写法共用推导。
- 复制实例沿用来源类型；转换和选项按声明类型投影；候选选择沿用候选元素类型；选棋子、选地格和基本操作使用显式结果类型元数据，避免把“目标棋子”“选中值”“是否成功”等显示标签当成类型。
- 技能、状态、规则、手牌的集合成员接到实例字段；当前技能/规则/卡牌上下文使用实例类型。定义类型仍独立保留。
- 从类型清单同源接入已确认的伤害、治疗、位移、路径事实四种结果结构，不复制未冻结的结构。依据 AUTHOR_STATEMENT_MANUAL 的既有约定，单目标伤害/治疗返回单项结果，容器目标返回结果元组。
- 函数新建的泛型变量根据实际表达式更新正文类型；来源变化立即更新后续字段，来源失效清除过期自动类型；作者明确选择的具体类型不会被覆盖。
- “类型”参数内支持映射的泛型逗号；普通表达式中的小于比较保留原义。
- 未声明的自定义 extension 仍允许输入；无法推导时指出缺失的容器或扩展声明，不猜成外层对象。
