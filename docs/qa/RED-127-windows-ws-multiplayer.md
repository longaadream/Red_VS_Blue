# RED-127 Windows 双人 WS 联机候选验收

状态：实现者自检清单，等待人工双机验收
风险：High

## 前置条件

1. 两台 Windows 电脑安装并加入同一个 Radmin LAN 网络。
2. 完全退出旧客户端；删除旧测试客户端目录与旧 `game.db`，不复用旧数据。
3. 两台电脑使用同一份 RED-127 候选 zip，完整解压后运行，不要只复制 EXE。
4. Windows 防火墙允许主机上的 `RED vs BLUE.exe` 与内置 `node.exe` 访问专用网络。
5. 记录主机 Radmin 地址（应为 `26.x.x.x`）和客户端实际显示的端口。

## 主流程

1. 主机点击“我当主机”，确认底栏显示 `26.x.x.x:<port>`，且没有数据库、`ws` 或 Prisma 缺包错误。
2. 主机进入大厅，确认可在四张受控地图间切换；分别至少创建一个非“大型洞穴”房间。
3. 客机使用 `http://26.x.x.x:<port>` 连接。预期连接验证成功并进入同一大厅；不需要 HTTPS 证书，也不使用“强制连接”绕过验证。
4. 客机加入主机房间。双方应同时显示 2/2、相同房主、相同地图、相反座位；刷新后仍一致。
5. 双方分别点击“准备”。Relay/LAN 模式下按钮都可用，双方看到相同准备状态，然后进入选将。
6. 双方各选择恰好 8 枚本阵营棋子并确认。第一方等待，第二方确认后双方进入同一战斗。
7. 确认部署阶段和普通回合都显示权威倒计时；计时只由服务端推进，两端剩余时间允许有显示延迟但不能持续分叉。
8. 使用一张被效果降为 1 AP、而基础定义为 2 AP 的手牌。1 AP 时按钮应可用，提交后由权威服务端正常结算，不显示“需要 2 AP”。
9. 在非当前玩家客户端关闭并重新打开页面，重新加入房间。预期通过 WS 快照恢复到相同回合、棋盘、AP、充能和倒计时。
10. 双方各完成至少一个普通动作并结束一个回合，确认没有 HTTP 500、checkpoint missing、房间人数分叉或客户端本地独立推进。

## 传输边界检查

开发者可在候选服务运行时执行：

```powershell
Invoke-WebRequest http://127.0.0.1:<port>/api/rooms -UseBasicParsing
```

预期 HTTP 410，响应包含 `PLAYER_REST_DISABLED`。这表示旧玩家 REST 已禁用，不表示服务器离线。管理接口、静态页面和 `/ws/rooms/**` Upgrade 不应被该边界拦截。

## 失败时保留

- 两端客户端版本/提交、Radmin IP、端口和房间 ID；
- 失败时双方屏幕截图；
- 主机内置服务器 stderr 尾部；
- 失败前最后一个 WS RPC 的 method、requestId、错误 code/context；
- 当前回合、阶段、authorityVersion 和倒计时；
- 是否全新数据库、是否完整解压同一 zip。

自动测试和单机 smoke 不能代替上述双机人工验收。
