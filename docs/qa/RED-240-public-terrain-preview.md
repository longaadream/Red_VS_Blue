# RED-240 拖动路径公开地格预演

用户复现：拖动经过可见天照、敌方黑百合毒素，路线数字出现，但状态和生命没有预测变化。

最小复现：红方棋子从 (0,0) 经 (0,1) 到 (1,1)，蓝方在 (0,1) 持有公开天照，或在最终落点 (1,1) 放置致命毒素。原页面绑定在 90ms 后确实调用预测棋盘显示，但预测状态没有天照，落在毒素上的预测生命仍为 100。正式执行会附加天照或扣除 4 点真实生命。当前毒素只在最终落点触发，不能将中途经过预测成扣血。

原因：publicViewerExecutionSnapshot 过滤敌方玩家的动态规则，并删除其玩家状态。公开地格未被用作对应 canonical 接触规则的证据。以前的天照路径测试只覆盖查看者自己持有规则，未覆盖公开敌方地格。

修复约束：只纳入公开地格明确对应的 canonical 规则和必要接触数据。规则继续调用正式规则引擎，不能在 UI 计算伤害或复制效果。隐藏地格、无公开地格证明的玩家状态及任意敌方规则仍不参与预演。

页面绑定测试运行实际拖动控制器、90ms 请求协调器和真实规则预演，只替代 WebGL 绘制。验证预测状态传给 showPreviewBoard、生命 100→96、公开毒素消耗、权威状态不变、回拖清除。规则测试另外对比正式 applyBattleAction，验证公开天照/毒素与隐藏数据等价性。

本轮没有改变伤害数值、正式移动接触规则或拖动动画。预演仍在跨格停留 90ms 后执行；连续快速跨格会取消旧请求，停留后显示最新完整路线结果。真实鼠标长按停留与 Electron/双客户端验收仍需人工执行。

用户已明确选择保持毒素落点触发。验证：预演、隐私、技能页面和拖动等 10 文件 104 项通过；追加敌方鼬坐标式天照回归后，移动规则与页面绑定 20 项通过。独立审查 36 项通过，修复审查发现的缺损公开数据判断和鼬/混合来源兼容问题，无剩余实质代码发现。独立审查指出的敌方鼬测试缺口已补上。

规则浏览器引擎已重建。相关 lint、临时仅排除本地 baseline 归档的类型检查、编码和 diff 检查按本轮候选执行。无来源、无 owner、无 cells、无 canonical sourceId 的纯展示标记保留兼容，不用它重建规则；已知 canonical 天照缺 cells 时拒绝。

回退本轮修复提交并重建引擎可恢复 6d1b360db；会重新出现公开敌方地格预测缺少效果的问题。无存档迁移。
