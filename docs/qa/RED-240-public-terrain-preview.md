# RED-240 拖动路径公开地格预演

用户复现：拖动经过可见天照、敌方黑百合毒素，路线数字出现，但状态和生命没有预测变化。

最小复现：红方棋子从 (0,0) 经 (0,1) 到 (1,1)，蓝方在 (0,1) 持有公开天照，或在最终落点 (1,1) 放置致命毒素。原页面绑定在 90ms 后确实调用预测棋盘显示，但预测状态没有天照，落在毒素上的预测生命仍为 100。正式执行会附加天照或扣除 4 点真实生命。当前毒素只在最终落点触发，不能将中途经过预测成扣血。

原因：publicViewerExecutionSnapshot 过滤敌方玩家的动态规则，并删除其玩家状态。公开地格未被用作对应 canonical 接触规则的证据。以前的天照路径测试只覆盖查看者自己持有规则，未覆盖公开敌方地格。

修复约束：只纳入公开地格明确对应的 canonical 规则和必要接触数据。规则继续调用正式规则引擎，不能在 UI 计算伤害或复制效果。隐藏地格、无公开地格证明的玩家状态及任意敌方规则仍不参与预演。

页面绑定测试运行实际拖动控制器、90ms 请求协调器和真实规则预演，只替代 WebGL 绘制。验证预测状态传给 showPreviewBoard、生命 100→96、公开毒素消耗、权威状态不变、回拖清除。规则测试另外对比正式 applyBattleAction，验证公开天照/毒素与隐藏数据等价性。

本轮没有改变伤害数值、正式移动接触规则或拖动动画。预演仍在跨格停留 90ms 后执行；连续快速跨格会取消旧请求，停留后显示最新完整路线结果。真实鼠标长按停留与 Electron/双客户端验收仍需人工执行。

用户已明确选择保持毒素落点触发。验证：预演、隐私、技能页面和拖动等 10 文件 104 项通过；追加敌方鼬坐标式天照回归后，移动规则与页面绑定 20 项通过。独立审查 36 项通过，修复审查发现的缺损公开数据判断和鼬/混合来源兼容问题，无剩余实质代码发现。独立审查指出的敌方鼬测试缺口已补上。

## 天照层数与移动伤害浮字补充

天照接触规则读取 `contactCells`，每个实际接触的天照格增加一层，路径不包含起点，终点不重复结算。`stacks` 是层数；`intensity: 2` 不能读作两层。原 renderer 对 `stacks: 1` 不显示层数，随后选择 `intensity: 2`，导致首次接触的徽标显示 2。另有正式 endTurn 规则：仍站在天照地格的棋子在回合结束再加一层。这与移动接触是两个不同的触发时点。当前鼬技能也是 `stacks: 1, intensity: 2`；历史审计里的 2→1 指强度，不能称为初始层数。

移动预演原本只使用结果 snapshot，没有把结果 events 的伤害/治疗显示为浮字。浮字应读取真实规则输出，与技能预演同样标记 `preview: true`，使用预测终点（死亡时回退到权威棋子坐标），取消/换路线时由预演生命周期清理。不能修改正式浮字或用 UI 再算毒素伤害。

## 当前公开预演的边界

预演在隔离副本中调用正式 `applyBattleAction`，但输入不是未经投影的完整权威状态。训练营目前也使用这个公开入口。

- 对手手牌内容、牌库/抽牌堆、隐藏状态及地格、仅所有者可见的数据被投影或移除。伪装/镜像棋子按公开外观计算。
- 敌方规则只保留公开初始定义、可见状态关联或明确公开来源证明；敌方玩家状态只保留公开天照/毒素接触所需的最小字段。快照携带的任意执行代码不会用于预演，执行资源来自 canonical 加载器。
- 私有调试、回放、冒险扩展及未知扩展被去除。公开地格、天照接触 cells、水门锚点等是明确支持的字段；因此新增公开效果若依赖新扩展，需要补齐投影与回归测试，不能假定已有白名单完整支持它。
- 随机玩法结果、未证明的执行来源、未完成部署、customCards、部分声明式能力（statusTag/summonCapability/deathParasitism）等会返回 unavailable；根选择未完成则返回 needs-input。
- 还需要选择目标/选项的反应是额外限制：移动返回 needs-input；技能可以跳过该反应后重新执行公开假设，不能称为完整权威结局。已支持的查看者续选须完成输入，不能由预演猜测答案。
- 输出还会移除执行闭包、运行时、规则内部字段等，结果只用于展示，不改变真实状态、行动历史或随机游标。

公开天照/毒素曾被误删是实现遗漏，已经补齐对应来源证明。隐私投影必须保留；当前预演也有上述功能支持限制，不能宣称所有可见规则均无条件完整执行。
