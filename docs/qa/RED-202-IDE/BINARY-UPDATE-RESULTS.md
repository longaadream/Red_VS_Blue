# Windows NSIS 差量下载验收结果（2026-09-10）

## 当前候选：修正依赖打包后的 0.1.3 → 0.1.4

### 人工升级发现的安装路径问题

0.1.3 已由用户安装完成、客户端运行与内容健康检查成功。升级 0.1.4 时弹出“无法关闭”提示。查进程确认客户端与内置服务器已退出；安装器 temp 仅有 old-uninstaller、尚无新版压缩包，阻塞于旧版卸载。NSIS 在旧版卸载失败时也使用相同文案。

只读逐文件 Win32 DELETE-access/shared-all 句柄探测（未删除文件）发现唯一失败为 Next 调试 sourcemap，原完整路径长度 260，错误 3；同文件加长路径前缀后成功。已将这一 .map 文件备份移出旧安装目录，验证 SHA-256 一致，保留恢复记录。后续手动入口改为工作区根下 RVB-Update-QA 短目录，避免新版重新写入相同超长路径；这次需要取消当前安装并重装短目录基线后重测升级。不能将原先 35/37 个回归及下载成功记录视为安装升级已通过。

旧 0.1.1 人工安装长时间未完成，原先下载验证通过不能代表安装体验通过。查明 `.next/standalone/node_modules` 是指向 `red200/node_modules` 的目录链接，旧 staging 将整个开发依赖目录展开复制。已改为按 Next 构建入口及 NFT 输出重新跟踪跨 worktree 的实际依赖，只复制跟踪到的普通文件，不展开目录链接。开发依赖原目录保留。

- 新目录：`pr-tools/RED-202-IDE/binary-update-lean`，原 0.1.1 / 0.1.2 产物未覆盖。
- 运行依赖 2,109 文件 / 131,325,107 字节；完整客户端约 5,635 文件 / 759 MB（原 56,680 文件 / 约 1.3 GB）。
- 安装包：0.1.3 为 232,833,836 字节，0.1.4 为 232,833,933 字节；比旧约 365 MB 减少约 36%。两版均通过包内容校验。
- 0.1.3 → 0.1.4 真实单区间差量：exe 响应正文 672,006 字节；含清单和 blockmap 共 1,139,448 字节；重建 SHA-512 与新包一致。
- 缺少旧缓存时完整下载 232,833,933 字节且校验一致；已为 0.1.4 时只请求 355 字节清单。两版本仅版本标识不同，不能将节省比例用于预测所有代码改动。
- 目录链接/缺失文件回归 2 项，现有打包与更新回归 35 项通过；定向 ESLint、PowerShell 语法、重新 fetch 后 main-baseline 通过。
- 新实际安装目录中的服务启动、首页、ping、3 个静态资源及生产环境 QA 页面拒绝访问通过。所测路由的 CommonJS 依赖解析禁止越出 staged runtime；这不等于所有业务路由和 ESM 解析已全部验证。NFT 133 条动态/可选依赖追踪警告保存在 dependency-trace-report.json，未隐藏。
- 独立审查发现旧 18990 测试源可能被新启动器误复用，已要求服务版本为 0.1.4，否则明确拒绝启动。
- 实际安装时间、训练营和用户确认后的重启升级仍待手动验收。自动测试没有执行任何安装器，也没有关闭旧安装进程。

手动步骤：关闭旧 0.1.1 安装器后，在新目录运行 01 安装 0.1.3，再运行 02 打开客户端，检查并确认升级至 0.1.4。详细步骤见新目录 README.md。下文为保留的旧版本下载实验记录。

## 多区间诊断与人工配置

额外 multipart 探测首次触发完整回退，追加诊断重跑成功，不能据此声称其不稳定问题已修复。已核对当前 electron-updater 的 GitHubProvider 明确禁用多区间合并，因此正式验收固定单区间。可选探测由 `RVB_BINARY_QA_MULTIPART=1` 启用，记录保留于 `download-results-multipart-probe.json` 和原诊断目录。

已生成 QA exe 没有重写；入口 02 在确认独立 QA exe 和精确 loopback generic 配置后，为已安装 QA 的 app-update.yml 设置 `useMultipleRangeRequest: false`。构建脚本也为之后的 QA 构建加上该选项。缓存差量仍基于原 exe，完整重建校验不变。
