# RED-240：普通移动路径实验与动画衔接

用户要求试做可选路径的普通移动，并加快动画衔接。随后明确 PVE 暂不处理，等待独立重做。

- base_branch: main
- base_sha: 9d1b0c30801cd733ec4cede37ce1ef0889a2313a（fetch 后与远端核对）
- 风险：Medium。复用现有动作、位置提交、接触结算与表现队列，不引入新架构。
- 新规则替代 RED-30 的“单次普通移动只能直线”：每一步仍为上下左右，可在一次移动内转弯，路径长度不超过 moveRange。
- AP 仍为一次普通移动 1 点；部署免费首移保持。不可行走地形、存活棋子阻挡，原地、非相邻、重复或失效路径拒绝。
- 不包含斜向、路线效果等价归类、教程/AI、PVE 重做、技能位移、经济/随机/存档/依赖升级、合并或发布。

## 交互与权威边界

选棋子、选终点、查看推荐路线；可添加途经点、恢复推荐路线或取消，确认后才提交移动。推荐路线使用公开距离与通行事实，不用隐藏效果为路线评分。路径不尝试去重归类或判断两条路线效果是否相同。

普通移动命令携带逐格路径，排除起点、包含终点。规则入口和统一位置提交器重新检查同一路径；不能在确认后静默寻找另一条路线。实际接触与动画来自已提交的 positionChanged 路径。冲刺和传送继续使用原有语义。

## 人工验证

1. 在本分支候选页面新开普通练习对局，选择完整 8 枚棋子的棋组。
2. 部署并选中己方棋子，点击需要转弯才能到达的高亮格；确认尚未移动、未扣行动点，棋盘显示路线。
3. 添加途经点，使同一终点改为另一条合法路线；检查步数与可见路线同步变化。
4. 取消或恢复推荐路线；切换棋子、技能、回合后检查旧路线不残留。
5. 再次选终点并确认；检查棋子沿所选路线移动，行动点只扣一次，免费首移不扣。
6. 对超出移动范围、被活棋子或地形阻挡的途经点尝试编辑；应提示无法形成路线，不提交动作。
7. 连续动作、多段伤害、2×、跳过与减少动态下，检查事件顺序和最终位置/血量一致；衔接更快，仍能看清移动和结果。

## 验证记录

实现前路径动画回归确认失败：实际拐弯路径没有进入根动作的 presentation.pathCells。补充权威路径投影后，该回归与现有位置接触/表现采样共 34 项通过。

实现前原始动画测试存在 17 项失败（vignette 7、sequential playback 10），测试仍使用约 1100/2200ms 的旧等待，源码已为每段 200ms；renderer 原测试通过。现更新为 140ms 普通/复合、100ms 状态/资源节拍；保留多段伤害 20→17→14、两个独立浮字、顺序、响应等待、跳过、倍速与最终状态断言。原测试的同步状态批次预期也与基线逐事件播放不符，改为明确验证 0→1→2→3（移除反向）的权威顺序；没有改源代码的批次语义、快照或固定规则哈希。

最终候选验证：14 个相关测试文件共 228 项，227 通过、1 项下述基线失败。包含规则路径、权威拒绝/原子性/AP、真实 PracticeSession 路径接触、浏览器生成引擎、表现投影和 UI 顺序/动画测试。类型检查、相关源文件与新增测试 ESLint、编码检查（1414 文件）、`git diff --check` 通过。游戏浏览器引擎和练习引擎构建成功。验收前 `check:main-baseline` 通过，behind=0。

浏览器冒烟：候选 `http://127.0.0.1:38683/battle.html?mode=practice`，8 枚棋子的棋组、开阔原野、先手；塔尔斯部署在 (1,9)，终点 (4,10)，加入 (1,10) 途经点后路线明确变为下→右。草稿、重置和取消没有消耗 AP。确认后到 (4,10)，免费首移 AP 仍为 1；第二次从当前位置 (4,10) 规划到 (5,8)，2× 确认后 AP 变为 0。选路虚线可见、路线上限显示 4/5，控制台 error/warn 为空。截图保存在本地 `output/RED-240/route-draft.jpg` 与 `paid-move-2x.jpg`（未提交测试产物）。

独立审查修复的发现：禁锢的合法目标提前拒绝、联合途经点搜索回溯、旧 walk 调用保持直线、动作动画起播/剩余时间、倍速路径网格坐标、路线虚线遮挡及第二次移动起点。新增回归覆盖转弯路线中途改倍速在剩余时限内完成，并逐帧检查没有离开所选路径。最终审查没有未解决的实质代码发现；产品体验仍待人工验收。

已确认的基线问题：`turn.test.ts` 的 `does not pay or execute a skill when the resumed trigger blocks` 抛出 `BattleRuleError: blocked`，在归档自上述 origin/main 的独立源码中同样失败，审查者复核一致。本任务不修复该中断技能问题。`turn.test.ts` 整文件 ESLint 的 80 个 explicit-any 错误为原有测试用法；本次新增路径测试没有增加同类问题。

默认终点使用确定性的公开 BFS；带途经点的联合搜索有共享节点预算和棋盘深度上限。极复杂的途经点组合可能在预算内找不到路线，界面应拒绝草稿，不回退为另一条路线。没有尝试判断路线效果相同。

本次浏览器候选验证覆盖普通练习模式，PVE 内容/AI 未修改。Android 旧跟踪渲染副本与 canonical 页面已有大量基线差异，本任务未将这些无关差异带入 PR，未做 Android/Electron/远端双客户端体验验收。
