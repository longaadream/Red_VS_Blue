# PVE 设计与场景基准

2026-09-09，RED-181。最新会话决定优先于旧节点路线、外置流程页面和训练营场景预览方案。以下完整方向仍为设计目标；当前落地范围单列如下。

## 已落地的首个可玩切片

独立 `adventure.html` 入口进入 `battle.html?mode=adventure`。同一张 32×32 原生棋盘上，猎空带乌瑟尔预备队探索金币补给与同行者、触发断墙哨站封锁战、回营治疗或付费强化数值，再前往旧城核心。正式技能、移动和核心胜负走原生引擎，敌方执行预先公开的固定行动计划。清场解锁并保留伤势、金币和已处理地点，清除本场临时效果。

本切片为单人、固定初始棋组、按种子生成地图与招募候选。尚无视野迷雾、完整构筑奖励、三幕推进、多人、保存和社区内容装载。刷新或关闭页面会丢失本次进度。不要把下面的完整产品设计当作本版本已实现功能。

### 随机地图与同行者（2026-09-10）

- 每次新冒险选择一个种子，在手记中显示。营地、哨站、核心区在作者限定范围内变化位置，道路与沿途障碍重新生成，可整体镜像。保留据点的局部阵形与先后顺序；保证营地附近有补给和招募、必要地点可达。回营、休整和战斗结算不重生成地图。
- 两处同行者设施各有三名固定候选；从安娜、死神、莉亚德琳、安度因的共享资料中选取。每处可以花 15 金币招募一名，直接加入预备队；可以不招募，回来时候选不刷新。
- 探索仍只显示队长，招募成员在战斗中沿用每轮一次、队长附近免费部署；胜利后收回预备队并保留伤势。营地可遣散所选预备队员，费用从 10 金币起，每次增加 10，不能遣散队长。数量/价格是资源包中可调整的框架默认值，未完成平衡。
- 棋子站在营地、补给或招募格上时，点击脚下格子可打开事件；技能选目标、权威待选流程和部署优先。

## 当前敌方与预告规则（2026-09-09 修订）

- 初始六名敌人全部在地图上。哨站由死神 PVE 精英、僵尸和骷髅组成；旧城由阿尔萨斯 PVE 首领、僵尸和骷髅组成。保留各 IP 身份，使用独立 PVE 技能，不直接继承 PVP 技能组。
- 只有玩家使用行动点：探索固定 3 点，战斗从 1 点逐轮增长。敌人没有行动点经济；每轮每个符合条件的敌人最多执行一条程序化行动，无合法行动时等待。
- 玩家行动前公开本轮敌方顺序、移动路径、攻击格和召唤格。蓝色虚线表示移动、红格表示攻击、紫色墓印表示召唤。预告后不重新瞄准；来源死亡、路径被占等使计划失效时直接取消，不临时换目标。
- 首领第 2 轮起可预告召唤食尸鬼，同时最多 1 个在场，技能冷却 3 回合。击败据点核心后清除该据点剩余敌人，不影响另一个据点。
- 敌方技能仍遵守正式技能编写标准：正文保留目标、射程、伤害倍率/类型及特有条件；地形阻挡引用可点击的“弹射物”关键词，统一执行时机、落空与取消规则放入“记录与规则”，不逐技能重复。界面只隐藏敌方行动点，保留冷却与完整效果；实际伤害、召唤和状态由原生规则执行。
- 金币在顶部独立常驻显示；队伍与部署放在左下栏，战斗中可打开敌情。营地、搜索、地点列表和手记采用居中的纸页弹窗，支持关闭按钮、Esc 和遮罩关闭。地点图标、预告格、顺序编号和战区边界都作为棋盘平面贴花渲染，随镜头同步平移缩放。原生合法移动与部署优先，地点菜单也可打开被棋子占用的设施。

## 共享资料与探索资源（2026-09-10）

探索地图、地点、遭遇区域、敌方阵容和构筑目录使用独立的探索配置，随原有资源包一起打包并检查引用。旧 PVE 节点流程保留；新探索模式从自己的配置启动。共用的是内容和打包机制，不转换旧节点图或旧存档。旧客户端也不会仅靠安装资源包获得新探索玩法。社区一键安装、联机一致性与完整三幕仍不在本次可玩切片内。

## 当前产品方向

- 三幕；每幕一张持续存在的大棋盘。同幕回营地后继续原图，新幕才换地图。
- 撤离代表回营地休整后继续同一局，不产生局外成长。
- 营地操作推进世界回合，事件按回合预告与触发。
- 队伍共享视野；已探索地形保留，当前敌情仅在视野内实时展示，离开后只记录最后位置及回合。
- 计划提供整队赶路与单棋子操作，但要沿用现有原生移动能力与交互，不能另造一套操作逻辑。
- 此前已确认的局内构筑、消耗卡、伤势、多人和社区内容规则仍以当前会话/Linear合同为准；不把未落地的规则写成现有实现。

## 已确认：地图就是冒险流程

探索、搜刮、遭遇战、撤离回营、休整和再次出发共用同一张地图。走地图就是推进冒险，不通过外置地图页、事件页、营地页串联流程。事件选择、物品整理和营地服务以棋盘旁的上下文面板承载。独立 PVE 入口负责进入冒险，不借用训练营入口。

战斗发生在当前地点，结算后队伍留在原地图；同幕回营后保留探索和地点处理记录，新幕才换地图。大地图总览用于查看，不代表点地点传送或固定节点选路。

## 已确认：正式开战后封锁战区

1. 开战前预告战区范围；正式开战时锁定本次遭遇的边界与参战玩家。
2. 区域内的参战棋子不得离开战区或返回营地。移动、传送和位移均须遵守封锁，不能通过技能绕过。
3. 尚未参战的队友可以继续探索，也可以进入战区支援；进入后同样受到封锁。
4. 封锁按玩家约束：该玩家仍在区域外的棋子不得继续探索或操作营地，只允许赶来支援；不将这些棋子强制传送进场。
5. 战斗结算后解除封锁，原地处理奖励、跨战斗伤势和本次遭遇的临时效果。不能仅因敌人离开视野就结束战斗或刷新临时卡牌。
6. 沿用既定的敌方核心胜利条件；某位玩家战败不强制结束其他玩家仍在进行的战斗。

边界沿现有棋盘格以粗线标记；越界尝试强调边界并显示原因，镜头仍允许观察区域外。具体动作校验必须进入规则层，不能仅用 UI 禁止点击。

### 后续技术设计需要覆盖的边界情况

- 晚加入的援军如何影响人数难度和敌方阵容，避免通过延迟加入绕过难度。
- 区域外棋子赶来途中路径阻断、遭遇其他敌人或碰到另一个战区的处理。
- 战区重叠或合并时的参与者、边界和结算归属。
- 强制位移触碰边界时具体采用失败还是截断，以及资源消耗语义；目前只确认不得越界。
- 多个遭遇同时存在时，临时效果和结算按所属遭遇处理，不能清除其他仍在进行的战斗状态。

这些是待细化项，不应把实现者自行选定的参数写成用户已经确认的规则。

## 大地图与完整流程设计提案

本节是基于上述已确认方向的实施建议。尺寸、数量、成本、调度方式及边界处理尚未作为最终规则确认，也未实现。设计采用“一张持续地图、一个世界时钟、多个独立战区”；地图是游玩空间，界面围绕地图展开。

### 地图尺度与空间组织

- 首轮规模测试建议 64 × 64 格，为当前 20 × 16 棋盘面积的 12.8 倍；使用 16 × 16 的内部加载分块。分块不是房间、节点或场景切换，玩家跨块不读条、不结算、不重置状态。
- 在行进节奏和性能验证后再评估 96 × 96 或 128 × 128。地图越大不应自动要求更多战斗；每幕完成主要目标即可推进，无须清完整张图。
- 每幕建议 5–7 个有辨识度的地理区域：主营地及近郊、适合早期搜索的旧聚落、连接区域的河道/桥梁、危险据点、可选高风险遗迹和幕末核心区。它们以连续地形及多个入口连接，不构成固定分岔节点路线。
- 营地附近保障一处低风险收益和一个明确地标；中远处提供机制不同的收益。高风险区域在靠近前有可读线索，避免探索未知一格就无预告地锁入必败战区。
- 建议每幕先测试 8–12 处有实际选择的交互地点，包含 2–3 处普通/精英据点以及一个幕末据点；玩家不必逐一完成。事件、敌群与据点的奖励不能简单叠加成过量收益。
- 重要区域有绕行路径和可开启捷径，例如修好桥梁、打开侧门、清除路障。回营后再次出发应受益于之前的探索；第一版先靠真实捷径缩短路程，不默认加入任意传送。
- 近处显示棋格、棋子和交互范围；远视角简化为地貌和已知地标，放大后仍是同一处地图。当前未知敌情不会因缩放或总览被揭示。

### 从开局到结束

| 阶段 | 玩家正在做什么 | 地图与状态变化 |
| --- | --- | --- |
| 建立冒险 | 从独立 PVE 入口选择冒险内容、队长与初始队伍；多人集合并核对内容版本 | 创建本次冒险与种子；无局外成长奖励；初始队伍可只有队长 |
| 幕初落地 | 队伍进入营地，查看本幕主目标、已知地标和事件预告 | 生成并保持本幕地图；营地以外按既定视野规则揭示 |
| 探索与构筑 | 选择方向、搜集物资、解锁捷径、招募、查看敌情 | 地点记录持久化；各玩家持有自己的队伍、卡牌、遗物与货币 |
| 遭遇预警 | 靠近敌群或触发明确标注的危险交互，看到战区及敌人信息 | 给出触发原因和封锁范围；预告不能泄露未知区域内的隐藏敌人 |
| 正式交战 | 在原位置使用现有战斗操作；区域外队友决定是否支援 | 锁定边界和参与者；各自回合后统一推进敌方阶段 |
| 原地结算 | 查看真实战斗结果，选取奖励和处理溢出 | 不换地图；按遭遇结算一次；保留伤势，清理所属临时状态 |
| 撤离回营 | 自主返回营地或使用地图作者配置的撤离设施 | 已参战者须先结束所属战斗；撤离不结束本次冒险 |
| 营地整理 | 使用治疗/强化、交易、付费复活等设施 | 按既定个人资源规则结算；有成本的休整推进世界回合 |
| 再次离营 | 返回未完成区域，利用已解锁捷径和情报 | 保留同幕地点处理、已探索地形和当前世界进展 |
| 幕末与换幕 | 消灭幕末敌方核心，完成幕末结算并共同推进下一幕 | 提议换幕要求所有仍在进行的战斗先结算；携带局内构筑，换地图 |
| 冒险结束 | 第三幕完成或触发既定全队失败条件 | 展示本局记录；不发放局外成长奖励 |

只在创建冒险和最终总结时允许必要的入口/记录界面。运行中事件、奖励、营地操作使用地图侧边面板。查看说明不消耗回合；执行动作才消耗或推进对应时间。

### 行进与世界时间

探索沿用原生棋子移动几何、阻挡、行动点和技能规则，不以大地图为理由直接赠送远距离免费移动。远处点击首先显示行程意图；后续若实现赶路队列，也只提交规则允许的移动，并在未知地形边缘、新敌情、战区预警、事件或资源不足时停止。队列不擅自结束玩家回合或替玩家触发开战。

建议始终只有一个世界回合计数。同一轮展示玩家顺序，每名玩家完成自己的行动后，统一处理敌方动作及到期世界事件。局部遭遇有参与者和结算状态，但不另建能被菜单加速的独立时钟。多个遭遇不能给同一玩家重复补充行动点、重复推进冷却或遗物生成。

远处敌群按路线、到达回合和事件记录更新；进入观察或交战范围后细化到棋格与战术 AI。细化必须继承确定的位置与记录，不能在镜头靠近时临时刷到玩家旁边。远端与近端切换算法需确定性测试。整个敌方阶段共享耗时预算，避免每个战区各自用满此前讨论的 10 秒目标。

多人阅读道具说明不会暂停其他人。需要选择奖励、处理手牌溢出时，该玩家暂不能提交后续行动；其余玩家可以继续本轮，轮末按明确的就绪状态等待。休整作为玩家的耗时选择，由统一时钟处理，不能一个人的营地按钮直接把全地图推进数轮。首版不自动跳过离线玩家的回合，需要房主明确将其置为缺席。

### 战区组成及边界处理建议

战区由地图内容预置的候选范围、入口、敌方核心位置、增援位置和触发条件组成。范围可以贴合庭院、街区或洞穴，不必总是矩形；内容作者须提供可容纳参战棋子的空间。锁区不搬动已在里面的棋子，不切到另一张战斗地图。

| 情况 | 建议处理 | 需要验证的事项 |
| --- | --- | --- |
| 触发正式开战 | 根据进入范围、敌人警戒或危险交互的明确条件触发；被玩家动作触发前给出可见预告 | 触发与注册参与者原子完成，不能先领奖励后补锁区 |
| 移动或传送越界 | 主动命令校验失败，执行前返回原因，不消耗资源 | 包括冲刺、中间经过区域、传送落点和召唤位置；沿用各技能既有路径语义 |
| 被强制推出边界 | 提议停在边界内最后合法位置；没有合法位置则不发生位移，其他技能效果按正式规则处理 | 不额外发明撞墙伤害；需逐类审核特殊技能，不可简单吞掉整次效果 |
| 区域外攻击或支援区内 | 提议禁止跨封锁边界攻击、治疗或施加效果；支援者须先正式加入 | 防止站外面输出并绕过参战人数；跨区弹道和范围技能也检查 |
| 队友晚加入 | 增援加入与难度调整同一结算点登记；以本场历史最高参与人数保持难度，增加尚未出现的敌方增援组合 | 不临时给现有敌人加血；下一敌方阶段前给出增援预告；人数增长处理方案尚待验证 |
| 同一玩家部分棋子在外 | 为其显示支援集合目标，只允许支援行进及必要自卫，不允许开箱、营地服务或主动开启第二场遭遇 | “必要自卫”是对被阻断情况的建议补充，不是允许继续探索 |
| 赶来路线无法通行 | 使用生成器保证的支援通道并禁止动态事件完全截断所有通路；异常时明确提示，不静默传送或永久卡回合 | 后续须确定地图变化超出约束时的恢复方案，作为正式切片阻断问题 |
| 两个战区接近或重叠 | 第一版内容生成禁止候选战区重叠、禁止同一玩家同时属于两个遭遇；后续才实现合并 | 不在锁区后悄悄扩大边界吞入无关玩家 |
| 某一战区结束 | 仅对该遭遇发出一次结算与解除封锁事件 | 不全图恢复、清牌或刷新技能；保持其他战区正常运行 |

敌群增援通过已定义入口和站位进入所属遭遇；第一版避免在同一地点同时使用独立遭遇和巡逻群两套奖励来源。玩家级核心、队长和死亡处理仍需按已确认规则接入，不能擅自把队长改为新的失败核心。

### 地图上的功能组件

每个交互物应具有统一的可见状态（未知/已发现/可操作/占用/已完成）、交互范围、耗时、参与权限、奖励归属、状态记录及失败提示。作者再按类型配置专属效果。

| 组件 | 玩家用途 | 主要状态/约束 |
| --- | --- | --- |
| 主营地 | 本幕集合、恢复和再次出发 | 稳定安全位置；参战玩家不可使用；不暂停世界 |
| 补给箱/废弃车队 | 搜索卡牌或资源 | 首次搜索、已领取、可能的噪声事件；显示个人或共享归属 |

| 营地帐篷/训练设施 | 全队恢复或单棋子数值强化 | 二选一服务、耗时、个人使用记录；不是战斗临时治疗卡的使用入口 |

| 幕间出口 | 主目标完成后共同换幕 | 未完成/已解锁/等待队伍/可出发；不误把普通撤离当成结束本局 |

### 内容生成与社区组件

推荐“手工设计的小区域 + 受约束的种子拼装”，先保证每个区域可玩。地块模块描述边缘接口、入口、可走区、视线阻挡、营地/交互槽位和候选战区；幕配方决定地理组成、主目标、危险分布和内容池；事件组件描述触发回合、预告、条件和结果。接口连通不代表只存在一条推荐路线。

生成时先搭可达骨架，再放营地、幕末目标、捷径和支援入口，最后填可选收益与装饰。验收至少覆盖：营地到主目标可达、必要交互可达、战区有足够空间、候选战区不重叠、支援路径存在、初始位置安全、内容引用完整。不要靠反复换 seed 掩盖坏图；保留失败 seed 和原因。

地图、奖励、事件可采用有记录的独立随机流，防止镜头加载、读取说明或重新连接消耗随机数并重抽。保存本局内容身份与已实现的世界变化，不能仅存种子后重新生成一切。多人内容必须保持用户已确认的完全一致；一键下载与脚本扩展按独立后续阶段实施。

### 性能、保存与联机边界

- 仅渲染镜头附近分块与必要标记，状态始终完整存在；用空间索引查询附近实体和交互物，避免每次选中扫描全图。
- 视野在实际移动/阻挡变化时更新，静态格子合批、远处标记简化、棋子贴图复用。性能测试必须包括四人分散和多个战区，不只测试空地图。
- 建议保存完整世界修订、各玩家构筑与伤势、地图变化、已领取记录、进行中的遭遇和临时状态、回合顺序、事件队列及随机流位置。不能用重新触发开战的方式恢复存档。
- 在一致的命令结算边界保存；房主权威继续校验内容版本和命令去重。离线/缺席与重新加入时机沿用既定结算边界政策，但需在同图框架下明确映射到所属遭遇和其他可提交状态。
- 对正在交战的缺席玩家不立即消失棋子或降低已锁定难度；具体托管/等待策略须在联机切片中确定。其他玩家能够继续不等于可以绕过尚未结算的规则动作。

### 实施顺序与验收

1. 同图单人闭环：独立 PVE 初始化、约 32 × 32 的小地图验证、一个营地、两处搜索点、一个封锁遭遇、一个幕末目标。完成原地交战/结算/回营/再次出发；复用正式动作和美术，禁止训练模式代替。小地图只是验证顺序，不是最终规模。
2. 大地图切片：扩大到建议的 64 × 64，增加分块、视野、区域组合、捷径和世界事件。统计整局耗时、空走回合、有效选择与渲染/AI耗时，据此调整尺度和密度。单人约 40 分钟、四人约一个多小时的既定节奏目标用于后续整局校准。
3. 多人多战区：玩家级锁区、区域外支援、人数增援、独立奖励、同时探索/战斗及缺席恢复。先用两人交叉状态验证，再扩大四人。
4. 三幕与社区内容：完整幕切换、内容装配工具、版本匹配下载、保存恢复和可扩展事件。保存所需状态边界在第一阶段设计，完整跨进程/多人恢复在交付前验证，不能延后到结构无法支持时再补。

关键验收场景：主动/强制位移不能越区；加入支援不能绕过难度；已参战玩家区外棋子不能购物搜刮；路径阻断不永久卡死；结算不会影响其他战区；重复命令不重复发奖；回营同图保留、新幕换图；卸载分块不重置宝箱和敌群；存读后进行中的遭遇、事件和随机流一致；迷雾不泄露实时敌情；PVP 选择和连续移动仍正常。
