# RED-102 纸偶剧场战斗界面风格指南

## 目标与边界

RED-102 将现有 2.5D 战斗页统一为“手工纸偶 DND 桌面剧场”。角色本体保留各自 IP 的身份锚点，纸张、笔触、裁切边和 UI 材质负责统一风格；红蓝阵营只由独立底座、状态条和交互高亮表达。

本任务只改变表现层。棋盘坐标、规则、行动点/充能点计算、状态字段、地格字段、技能合法性、回合倒计时和 RED-69 动画触发保持不变。

## 跨 IP 统一方法

每名角色必须先保留五类身份锚点，再套统一纸偶材质：

1. 头部轮廓与发型。
2. 面部识别特征。
3. 代表性服装大色块。
4. 一件代表性武器或道具。
5. 角色原本的主色，不叠加阵营色。

统一层使用粗黑毛笔轮廓、可见铅笔底稿、低饱和彩铅/干式套印、暖色纤维卡纸和不均匀米白裁切边。不得用写实 PBR 金属、光滑古典棋子或整洁无瑕的矢量边缘。角色缩到约 120 px 高时，仍应靠轮廓和主色辨认。

## 角色输出规格

| 项目 | 规格 |
| --- | --- |
| 文件 | 透明 PNG，sRGB |
| 画布 | 512 × 1024 px |
| 安全区 | 四周至少 32 px |
| 脚底基线 | y = 932 px |
| 角色占高 | 建议 78%–84% |
| 轮廓线 | 512 px 画布上约 7–10 px，允许自然抖动 |
| 裁切边 | 暖米白 6–12 px，不使用阵营色 |
| 阴影/底座 | 不烘焙进角色图，由运行时独立生成 |
| 命名 | 与 templateId 一致：`public/standees/<templateId>.png` |

透明背景必须是真实 alpha，不能把棋盘格烘焙进 PNG。武器、头发和衣摆不得越过安全区；脚底必须落在统一基线，避免不同 IP 上棋盘后忽高忽低。

## 运行时展示规格

- 角色图使用竖直纸片网格，默认高约 1.24 个地格、宽约 0.62 个地格。
- 角色纸片不接收阵营染色。红蓝识别保留在独立椭圆底座、无色盲依赖的单点/双点标记和合法行动高亮。
- 纸偶加载成功后隐藏旧椭圆头像；缺图、映射缺失或纹理加载失败时立即保留旧头像，不发起猜测文件名的请求。
- 点击和触摸仍按权威地格坐标判定，不以纸片透明像素作为命中区域。
- 角色受击、治疗、死亡、待确认和状态变化仍作用于现有角色根节点。

## 棋盘与 UI

- 棋盘基材为暖灰牛皮纸；地格线、掩体和墙面使用墨线、铅笔排线和少量手工错位感。
- 掩体仍保留原本的高度语义，但降低硬质 3D 光泽，以纸板叠层和手绘符号表达。
- 墙与掩体使用独立 512 × 512 透明纸板插画；原始逻辑高度继续作为射线命中体，方块本体仅以 10% 透明度存在，视觉高度与规则高度分离。
- 当前地形资产为 `public/standees/terrain-wall.png` 与 `public/standees/terrain-cover.png`；缺图时保留浅色纸面地格，不影响格子可点击性。
- 回合、行动点、充能点、状态栏、地格信息栏和点击角色后的行动菜单继续使用现有布局槽位。
- 大标题使用楷体/手写感字体栈，小字与数字使用清晰的宋体或等宽字体栈；不依赖远程字体。
- 按钮必须保留 44 px 触控目标、键盘焦点、禁用态和 `prefers-reduced-motion` 处理。

## 三张样板来源

三张样板使用内置图像生成工作流分别生成，随后只做两项机械处理：移除生成图中的浅色棋盘格背景、按统一比例缩放为 512 × 1024 并保留 alpha。原始生成文件保留在 Codex 生成目录，项目内使用标准化副本：

- `data/pages/public/standees/blue-naruto.png`
- `data/pages/public/standees/jaina.png`
- `data/pages/public/standees/arthas.png`

三张图进入全量角色生产前必须由项目负责人确认：角色身份是否准确、跨 IP 是否足够统一、纸张和笔触是否够“手工”、小尺寸轮廓是否清楚。

纸张底纹、墙与掩体也由内置图像生成工作流分别生成；项目副本只做透明通道保留与 512 px 标准化。运行时不裁切图集，地形缺失时回退到同一纸张色板。

## 回退与回滚

单个角色回退：把其清单项设为 `portrait-fallback` 并移除 `src`，旧头像立刻接管。

整套回滚：移除 RED-102 纸偶清单脚本与纸张皮肤样式引用，渲染器继续保留旧椭圆头像路径。不得删除 RED-68 的头像实现，直到所有角色素材完成并单独验收。
