## 1. 合同地位与适用范围

- 本合同仅适用于 Demo v0.1 的 1v1 核心对局。
- 本合同不设计未来棋子、地图或正式发行规则，也不修改任何代码、数值或内容数据。
- 产品规则的后续变更必须通过新的决策记录和任务修订；不得静默覆盖本文。

## 2. 座位、阵营与所有权

- 对局有两个座位：`red` 与 `blue`。座位决定先后手，不代表内容阵营。
- 每名玩家独立选择光方或暗方内容阵营；允许光对光、暗对暗、光对暗。
- 内容阵营与先后手无关；后手获得幸运币。
- 玩家所有权指玩家对其选择、控制的棋子及其效果生成实体的控制关系。

## 3. 阵容构成与核心身份

- 每名玩家从所选内容阵营的候选棋子池中选择正好 8 枚、且彼此不同的棋子。
- 候选池由受控角色清单与独立准入任务持续维护，不锁定光方或暗方角色数量，也不要求双方数量相等；毒液经 RED-89、黑崎一护与宇智波鼬经 RED-120、维伦与图拉扬经 RED-121、蓝染惣右介、乌尔奇奥拉·西法与葛力姆乔·贾卡杰克经 RED-163 准入。毒液决策见 [ADR-0009](../decisions/ADR-0009-venom-demo-admission.md)，RED-163 机制决策见 [ADR-0026](../decisions/ADR-0026-dark-character-target-rules.md)。每次准入必须同步清单、角色矩阵与跨端验证。
- 初始 8 枚棋子均为核心棋子。核心身份在复活或变身后保留。
- 新建对局开始时，非基尔加丹的普通核心棋子先进入各自预备区；开局双先锋初始化再从双方普通预备区各抽取 1 枚并召唤到棋盘，其余普通核心继续留在预备区。
- 对局初始化完成后，核心存活只看场上存活核心。普通预备区中的核心不计入存活条件，也不能阻止该方因场上核心为 0 而败北。
- 基尔加丹保留其稳定核心实例身份，但初始化时由棋子模板声明的预备区初始化技能移入按 owner 隔离的 `battle.extensions.kiljaedanPiecesByPlayerId` 仪式暂存区，因此镜像阵容不会互相覆盖、不会进入回合候选，也不在暂存期间计为存活核心；被仪式实际召唤后重新按场上核心棋子结算。单值 `kiljaedanPiece` 只作旧内容兼容。
- 召唤物不属于初始 8 枚核心棋子，且不计入核心存活条件。

## 4. 地图与对局初始化

- 正式可选地图状态 ID 恰好为 `large-hole-arena`、`open-expanse`、`winding-pass` 与 `narrow-corridors`；`large-battlefield` 已退役。
- 上述四张正式可选地图均只允许普通地板、墙、掩体与洞穴；不得包含或引用熔岩、充能台、治愈泉，以及对应伤害、充能、治疗数值或效果字段。
- 房主在创建房间时从受控目录选择地图；创建成功后 `Room.mapId` 冻结，来宾、房间内操作与开战请求都不能覆盖。
- Windows/Electron 的 LAN 与 Relay 玩家入口通过同一 WebSocket 目录和校验语义；旧玩家 HTTP 入口禁用，完整快照与重连恢复不使用 HTTP 后备。Android 当前 action-log 只保留 legacy 状态解释能力，`progressive-reserve-v1` 在 RED-81 完成前属于 unsupported，不进入 RED-138 私有投影、发布或跨端一致性验收；Android 与独立 Relay 的后续迁移仍须保持相同受控目录和失败关闭语义。
- 服务端在创建房间与开战前分别验证 `mapId`；缺失、未知、已退役、目录外或不可部署地图失败关闭，不得创建房间、替换地图、生成 seed、消费随机流或写入战斗状态。
- 引用已退役地图的等待/就绪房间不能开战并须重建；已在进行中的序列化战斗继续使用自身保存的完整地图状态。
- 新建 `progressive-reserve-v1` 对局先建立双方普通预备区并移出基尔加丹，再按标准化玩家 ID 的稳定顺序，为双方各用独立命名 seeded 随机流抽取 1 枚普通核心先锋，并用另一条独立命名流随机放到当时空闲的可行走格；因此不会重叠，也不消费旧部署流的 16 次出生随机。
- 双方随机先锋都经过正式的 `beforePieceSummoned` → 入场 → `afterPieceSummoned` 召唤边界，但不获得回合部署的免费首移 statusTag。只有两枚先锋及其触发队列均完成后，对局初始化才完成并首次检查核心终局。
- 渐进式部署的空间候选取地图中全部空的 `walkable === true` 格；墙及其他不可行走格不能成为部署位置，存活棋子占据的格子不能重叠部署。
- 相同 `mapId`、seed、玩家、阵容与权威动作序列必须产生相同的随机先锋、先锋落位、回合候选、后备落位、随机流 cursor 和战斗状态。

## 5. 渐进式预备区部署

- 新建对局默认使用 `progressive-reserve-v1`。初始化完成时双方场上各有且仅有 1 枚随机先锋；此后每个自己的回合若普通预备区仍有棋子，必须先完成本回合部署，才能进入正常回合开始结算和行动阶段。
- 第一名玩家的第 1 个自己的回合仍先结算一次 `gameStart`，但预备区棋子不会因此被视为已经召唤。`gameStart` 完整触发队列后先检查场上核心终局；仍未终局时，服务端才从当前玩家的普通预备区用命名 seeded 随机流生成至多 3 枚互不重复的候选。少于 3 枚时全部进入候选。后手的第 1 个自己的回合遵守同一候选规则。
- 对于不含基尔加丹、无死亡且由 8 枚普通核心组成的标准阵容，设 `t` 为玩家自己的第 `t` 个回合；该回合部署完成后的场上核心数量为 `N(t)=min(t+1,8)`。即初始化为 1 枚，第 1 个自己的回合部署后为 2 枚，此后每个自己的回合最多增加 1 枚。
- 玩家从候选中选择 1 枚，并在服务端给出的安全落点中选择目标。选棋与选格在客户端保持为本地选择，最终由一条携带当前 `expectedDeploymentRevision` 的原子权威命令完成校验和部署；旧 revision 在任何克隆、随机或修改前失败。部署消耗 0 行动点，失败命令不得产生半部署状态。
- 安全落点必须为空、可行走，并且与每一枚存活场上棋子的曼哈顿距离都严格大于 5。场上没有存活棋子时，所有空可行走格均为安全落点。
- 如果没有任何安全落点，客户端只提交所选棋子；服务端从按稳定顺序排列的全部空可行走格中确定性随机选择 1 格，且不允许重投。如果连空可行走格也不存在，则本次部署失败关闭，不能移出预备区或污染状态。
- 原子部署依次结算 `beforePieceSummoned`、重新按本次安全/兜底分支校验触发器调整后的最终坐标、把同一稳定核心实例从预备区移至棋盘、再结算 `afterPieceSummoned`。任一召唤触发需要玩家交互时，整条部署命令保持在权威事务的待结算状态，触发队列全部完成前不移出预备区，也不允许正常行动。`afterPieceSummoned` 队列完成后先检查场上核心终局；只有仍未终局时，本次被召唤的核心才获得 `deployment-first-move-free` statusTag，并直接继续 `beginTurn` 等回合开始结算和正常行动，绝不进入独立免费移动或跳过阶段。
- statusTag 公开显示“本回合首次移动免费”，只持续棋子被放置的这个当前回合。它只影响该棋子所属玩家提交的普通 `move`：第一次被权威接受并实际提交的普通移动消耗 0 行动点并原子消费标签，第二次及后续恢复现有费用。非法、过期、错误玩家、被拒绝或在 before-move 阶段阻止且没有实际提交的移动不消费标签或行动点；实际提交后即使 after-move 效果把棋子移回原位、移出战场或改变位置，也不返还标签。未使用标签必须在该部署回合结束、行动权交接前清除；技能/强制位移、召唤落位、开局先锋、复活、变身、基尔加丹仪式召唤及其他非三选一召唤均不享受或消费。
- 候选内容与安全落点只向已验证为当前输入玩家的接收者公开；其他玩家、观战者和仅自行声明 player/viewer ID 的读取只获得公开预备区数量，不获得预备区实例或候选详情。棋子实际上场后，其场上状态与 `visible=true` 的 statusTag 按普通战场可见性公开。
- `aiEnvironmentV1` 与 `aiEnvironmentV2` 按当前 AI `playerId` 使用同一部署权限边界：公开部署
  mode、阶段、revision 与双方 `reserveCounts`；只有当前输入 AI 能看到自己的 `offerPieces` 和
  `legalPositions`。对手 AI 与其他 viewer 不得看到这些
  私有字段，也不得读取完整预备区实例。
- AI 合法动作接口必须表达 `deployReservePiece`，并携带观察时的当前 `expectedDeploymentRevision`。有安全格时只枚举
  offer 与权威合法格的组合；安全格为 0 但仍有空格时只提交不带坐标的部署动作，由服务端 seeded
  fallback 决定最终格；无空格时无合法部署动作并失败关闭。
- 桌面 WebSocket 实时 bot 房使用 `progressive-reserve-v1`，并采用固定、可回放的最小策略：部署时
  提交 AI Environment 稳定排序后的第一个 `reserve-deployment` 候选，之后直接进入既有普通行动逻辑。
  statusTag 对普通移动的 0 AP 结果完全由权威 reducer 表达；动作必须重新提交现有房间 authority/CAS，
  不能写回隔离模拟状态、复制扣费规则或复用旧 revision。
- 上述最小 bot 策略只保证规则流程可操作，不定义位置估值、角色估值、难度或胜率目标。RED-117
  formal PVE adapter 与 Android mobile-server/旧协议继续显式 `legacy-reroll-v1`，不在本任务中
  迁移为渐进部署。
- 泰兰德与提里奥·弗丁的相关效果在每次该棋子本人结算 `afterPieceSummoned` 时触发，而不是在 `gameStart` 或仅首次上场时触发。需要“首次”语义的内容由 `battle.extensions` 自行记录，本合同不增加通用首次召唤生命周期字段。
- 基尔加丹的仪式召唤也必须经过 `beforePieceSummoned` 与 `afterPieceSummoned`，但不属于回合预备区部署，因此不获得部署免费首移 statusTag。
- 旧的初始 16 枚全图部署、公开重投与 45 秒锁定只保留为历史状态和显式 `legacy-reroll-v1` 兼容路径，不再是新建对局默认规则。详细决策见 [ADR-0024](../decisions/ADR-0024-progressive-reserve-deployment.md)。

## 6. 回合、行动点与时限

- 基础行动点从每名玩家自己的第 1 回合 1 点开始；此后每次自己的回合增加 1 点，最高 10 点。
- 每个自己回合开始时，行动点恢复至当前基础上限；未使用的基础行动点不保留。
- 临时行动点不设上限，但不跨回合保留。
- 完整轮次指双方各完成一个自己的回合。成长回合时限按完整轮次为：1–2 轮 45 秒、3–4 轮 60 秒、5–6 轮 75 秒、7–8 轮 90 秒、9 轮起 105 秒。
- 每个成长回合的最后 15 秒为烧绳阶段。
- 预备区候选与部署使用该玩家本回合的同一成长时限，不再拥有独立的 45 秒部署计时；超时由服务端按权威合法动作完成必要部署，再直接继续既有超时结算。没有额外的免费移动输入窗口。

## 7. 行动、移动与技能

- 游戏没有通用普通攻击。
- 零冷却技能可以重复使用。
- 同一棋子可反复移动；正常行动阶段的每次移动消耗 1 点行动点。第 5 节规定的三选一新部署棋子仅在被放置的当前回合第一次成功普通移动消耗 0 点，是唯一的通用例外。
- 普通移动只允许横向或纵向，受该棋子移动值限制。所有存活棋子都阻挡移动路径。
- 默认距离使用曼哈顿距离。
- 召唤物与复活棋子默认可立即行动；若不能立即行动，必须由具体技能文本明确声明。
- 【万花筒】是技能关键词：每次友方角色发生死亡事件，己方所有【万花筒】技能的当前充能消耗永久降低 1，最低为 0。召唤物死亡计算；同一角色复活后再次死亡再次计算。
- 【万花筒】技能降至 0 充能后仍是充能技能，继续使用 `useChargeSkill`，并遵守行动点、冷却、目标与每局次数限制。
- 【灵压】是技能目标条件：技能的主要目标当前攻击力必须低于施法者，否则该目标不合法。没有合法目标时技能不能使用，且不支付行动点、充能、冷却或次数。
- 【灵压】由技能 `statusTag` 引用可复用 rule 表达；权威目标查询、UI 与 AI 使用同一候选集合，核心流程不得按关键词、技能 ID 或角色 ID 硬编码。
- 单体技能在 `beforeSkillUse` 可由规则申请改写主要目标。替代目标必须通过申请规则声明的权威候选校验；整条根技能只执行一次并只支付一次成本。若规则申请回合外选择，则复用统一 pending 事务与 15 秒响应计时。
- `visible=false` 的棋子 statusTag 只向其所有者公开；对手与观战者只能看到对应的公开状态，不得从快照、AI 观察或重连状态读取秘密目标。

### 7.1 RED-163 暗方角色

- 蓝染惣右介：`HP 9 / ATK 4 / DEF 0 / MOVE 4`。镜花水月消耗 1 AP，秘密标记 4 格内 1 名友军；对方下回合用单体技能指定该角色时，蓝染可把目标改为蓝染 3 格内另 1 名敌人（包含原施法者）。瞬步与黑棺是【灵压】技能；黑棺立即造成 150% 魔法伤害、禁锢目标，并在目标回合结束时再造成等量伤害。
- 乌尔奇奥拉·西法：`HP 12 / ATK 4 / DEF 1 / MOVE 3`。每次造成或受到正伤害后恢复 2 点生命并累计 1 次归刃进度；达到 3 次后在自己的下个回合开始归刃，攻击与移动各 +1。虚闪造成 75% 魔法伤害；归刃后可使用【灵压】黑虚闪，造成 200% 魔法伤害。
- 葛力姆乔·贾卡杰克：`HP 5 / ATK 4 / DEF 0 / MOVE 4`。附近敌人移动或使用技能后可回合外移动至 2 格内空格，若与该敌人相邻则连续攻击 2 次；每次攻击后自身受到 1 点真实伤害，且狩猎本能没有每回合次数上限。首次死亡事件正常派发后原地归刃为 `HP 10 / ATK 5 / MOVE 5` 并复活，王虚的闪光替换为【灵压】豹王之爪；再次死亡正常结算。

## 8. 弹道与技能效果

- 弹道与技能效果分离：引擎返回确定性的轨迹与碰撞，技能代码决定友军伤害、穿透、爆炸等效果结果。
- 空掩体阻挡弹道。
- 掩体上存在棋子时，弹道先与该棋子碰撞，再由掩体终止。
- 洞穴不阻挡弹道，弹道可以通过。

## 9. 伤害与防御

- 物理与魔法伤害会减去防御；真实与毒素伤害默认无视防御。
- 正数的普通有效伤害最低为 1。
- 免疫或完整抵挡可以使伤害为 0。
- 死亡事件以一个起始存活角色结算至 0 生命并派发 `onPieceDied` 为准；即使该事件随后立刻复活，已发生的死亡仍结算一次。
- 强制移除不是伤害或死亡，不派发死亡、击杀或复活事件，也不进入墓地。

## 10. 终局

- 开局双先锋初始化期间暂停核心全灭检查；只有按稳定玩家顺序完成双方先锋召唤及其完整触发队列后，才设置 `openingVanguardsInitialized`、跨过初始化屏障并执行第一次核心终局检查，不能在第一枚先锋完成后提前结算。
- 初始化完成后，只有场上存活、具有数值坐标且 `isCore=true` 的棋子计入该方核心存活。普通预备区、当前候选以及 `battle.extensions` 中尚未被仪式召唤的基尔加丹均不计入，也不能挽救场上已无核心的一方。
- 在任一权威结算边界，若只有一方场上存活核心为 0，该方立即败北，另一方获胜；若双方在同一结算边界均为 0，则判平局。部署 after-summon 队列构成即时边界，终局必须先于授予免费首移标签、`beginTurn`、下一回合/候选与下一次随机消费；之后的普通移动沿用既有动作终局边界。
- 基尔加丹经仪式实际召唤至棋盘后，恢复按场上核心棋子结算。
- 第 40 个完整轮次结算后仍未分胜负时判平局。
- 投降立即判负。
- 核心棋子被强制移出战场后视为不再存活，仍可导致核心全灭；引擎保留最小移除记录用于确认其核心身份。
