# 产品设计文档

状态：草案  
负责人：项目负责人  
最后更新：待填写

本目录用于记录 Red VS Blue 已经确认的产品设计，包括游戏愿景、核心循环、规则、术语、版本目标和玩家体验。

## 当前产品目标

当前阶段的目标是完成一个：

- 可以正常运行。
- 核心玩法流程完整。
- 主要规则能够稳定执行。
- 主要 UI 界面达到可测试水平。
- 可以邀请真实玩家参与测试。
- 能够发布公开测试消息的 Demo。

当前不以内容数量为第一目标，优先解决结构混乱、调试困难、运行不稳定和 UI 表现较差的问题。

## 计划建立的文档

后续在本目录中逐步建立：

- `VISION.md`：游戏愿景、目标玩家和产品定位。
- `CORE_LOOP.md`：玩家核心循环和单局流程。
- `GAME_RULES.md`：完整游戏规则和胜负条件。
- `TERMS.md`：游戏术语与统一命名。
- `DEMO_SCOPE.md`：当前 Demo 的范围和明确不做的内容。
- `FEATURE_STATUS.md`：功能现状、完成度和待验证事项。

## 文档状态

每份产品文档使用以下状态之一：

- 草案：仍在整理，不能作为最终实现依据。
- 待验证：来源于旧版本或口头描述，需要结合最新代码确认。
- 有效：已经由项目负责人确认，可以作为开发依据。
- 已废弃：不再适用于当前版本，仅保留历史记录。

## 维护规则

- 未经确认的旧版本玩法必须标记为“待验证”。
- 修改核心玩法、规则或胜负条件时，必须同步更新对应文档。
- Linear 任务应引用与其相关的产品文档。
- 文档不能确定的内容使用“待确认”标记，不得由 AI 自行补全。
- 重要产品方向变化需要记录到 `docs/decisions/`。
