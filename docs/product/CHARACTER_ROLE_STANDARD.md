# 角色主副定位、构筑标签与复杂度标准

状态：待人工确认

关联任务：[RED-39](https://linear.app/redvsblue/issue/RED-39/定义角色主副定位构筑标签与复杂度标准)

适用范围：Demo v0.1 的角色内容描述与后续角色矩阵

> 本文是角色分类标准，不是规则、数值或强度评估。对局规则仍以 [Demo v0.1 核心对局合同](./DEMO_V0_1_CORE_MATCH_CONTRACT.md) 为唯一权威来源；现有数据文件仅用于本任务的示例，不据此补充未写入合同的规则。

## 1. 标注对象与边界

每个“角色形态”是一条独立标注记录。一个角色的普通形态、变身形态、复活形态或其他可独立选取/展示的形态，均可分别标注；它们可分别进入善、恶或中立内容阵营。阵营只说明该形态所属的内容池，不推导座位、先后手或敌我关系，参见 [术语表](./TERMS.md) 与 ADR-0002。

每条记录必须包含：

| 字段 | 约束 |
| --- | --- |
| `主定位` | 必须且只能有 1 个，取自第 2 节词表。 |
| `副定位` | 0–2 个，取自第 2 节词表，且不得与主定位相同。 |
| `构筑标签` | 0 个或多个；必须分属第 4 节的三个类别之一，并写出协同对象与触发关系。 |
| `复杂度` | 必须为 1–4 级；按第 5 节可观察判据判定。 |
| `阵营` | 按该具体形态标注为善、恶或中立；不从角色名称或其他形态继承。 |

`rarity`、强度、胜率、人气、美术复杂度和开发成本不参与上述任何字段的判定。

## 2. 定位词表

定位描述角色在一局中最稳定、最值得围绕其部署和使用资源的贡献，不描述单次技能效果。先从下列互斥优先顺序中选择主定位；只有当另一职责持续存在、会改变部署或资源决策，才添加副定位。

| 优先级 | 定位 | 当前战棋语境中的职责 | 不应仅因……而选择 |
| --- | --- | --- | --- |
| 1 | **保护** | 持续阻止友军或自己被击杀、受伤或被限制；其核心价值是维持存活。 | 单次自保、单次治疗。 |
| 2 | **控制** | 持续限制敌方的移动、行动、选项、区域或时序，以创造局面优势。 | 只有伤害附带的轻微减益。 |
| 3 | **支援** | 持续提升友军、治疗友军、提供行动/手牌等可由队友转化的资源。 | 只强化自己。 |
| 4 | **进攻** | 主要通过直接、稳定的伤害或击杀压力推进胜利。 | 以铺设、限制或资源循环为主要目标的伤害。 |
| 5 | **机动** | 主要以位移、换位、传送或位置重构取得价值，且该价值不依附于单次伤害。 | 单一短距离移动，或移动只是接近攻击目标。 |
| 6 | **体系** | 主要价值来自建立、转换或消耗可复用的专属资源/实体/循环，而非上述单一战场职责。 | 只有一个普通状态或一张独立卡牌。 |

### 2.1 主定位判定流程

1. 列出角色在不依赖特定队友时，能重复提供的战场贡献。
2. 若贡献满足多个定位，按上表优先级选主定位；这是为了让两个评审者在边界案例中得到可比较的结果，不表示强弱排序。
3. 仅当另一个定位的贡献跨多个技能、被动或回合存在，并会改变玩家的部署、目标或资源决策时，作为副定位记录。
4. 副定位最多两项；若第三项看起来也合理，改写为构筑标签或在“标注说明”中说明其为偶发效果。

### 2.2 快速反例

- 造成伤害并击退的技能，若角色整体仍以近战伤害取胜，主定位是“进攻”，击退通常只是效果，不自动成为“控制”。
- 有一项治疗技能的伤害角色，不自动成为“支援”；治疗必须是可重复且影响队友决策的核心贡献。
- 有被动标记的角色，不自动成为“体系”；标记必须形成可循环的资源、实体或转换链。

## 3. 主副定位记录格式

采用以下格式，保证可审查性：

```text
主定位：<词表项>
副定位：<0–2 个词表项>
依据：<列出支持主定位的技能/被动/循环，以及副定位为何达到门槛>
未选原因：<至少说明一个容易混淆但未选为定位的效果>
```

## 4. 构筑标签

构筑标签只表达“与什么协同、靠什么触发或消耗”，不得重复表达“擅长伤害/治疗/控制”等定位结论。每个标签须采用 `类别:名称` 格式，并附一条可验证的关系说明。

| 类别 | 定义 | 合格示例 | 不合格示例 |
| --- | --- | --- | --- |
| 通用机制标签 | 跨阵营、跨角色可以复用的规则机制。 | `机制:圣盾`（消耗、失去或获得圣盾会改变该角色收益） | `机制:进攻`（重复主定位） |
| 阵营体系标签 | 仅在某一内容阵营的多名角色/组件间可共享的体系。 | `体系:圣光手牌`（与同阵营可生成或消耗的圣光手牌协同） | `体系:善阵营`（没有协同资源或触发关系） |
| 角色专属资源标签 | 由该角色或该形态创建、累积、消耗或转换，且其他角色不能等价替代的资源、实体或状态。 | `专属:飞雷神锚点`（水门创建、上限管理并消耗的地图锚点） | `专属:伤害`（不是可管理资源） |

同一事实只选最具体的一类。例如“飞雷神标记”由水门独立创建和消耗，应标为 `专属:飞雷神标记`，而不是再重复标为通用“标记”。标签不能因角色有某个关键词就自动添加；必须写明“来源 → 触发/消耗 → 受益者/结果”。

## 5. 复杂度量表

复杂度衡量首次正确使用角色所需的规则理解和决策负担，而非角色强度、稀有度或受欢迎程度。先检查五个维度，再按命中的最高级别定级；若两个评审者仅相差一级，记录造成差异的维度并由人工裁定。

| 维度 | 观察项 |
| --- | --- |
| 可见技能 | 首次使用时需要理解的主动、被动、超级技能数量。 |
| 专属对象 | 需要跟踪的专属状态、手牌、充能、召唤物、形态或地图对象。 |
| 时序与条件 | 反应触发、跨回合记忆、随机结果、条件分支或可选响应。 |
| 空间规则 | 位置、弹道、射线、区域、传送落点或区域边界的额外判断。 |
| 构筑依赖 | 是否须配合其他角色或特定构筑组件，才可理解或稳定发挥核心循环。 |

| 等级 | 可观察判据 |
| --- | --- |
| **1：入门** | 至多 2 个需要主动理解的可见技能；无专属对象；无反应/跨回合记忆；最多一种直观的单目标或自身空间判断；不依赖构筑组件。 |
| **2：基础** | 3 个左右可见技能，或出现 1 个短时状态/简单区域或弹道规则；没有需要玩家同时管理的专属资源链；至多一个明确条件。 |
| **3：进阶** | 具备以下任一项：需要管理 2 个以上对象/状态、持续跨回合效果、反应触发、两步目标选择、非直观的区域/弹道/位置判断，或明确的构筑协同；但核心循环仍可用少量规则说明完整表达。 |
| **4：专家** | 同时涉及多个维度，且玩家必须在回合外或跨回合管理专属资源/手牌/形态/地图对象，并处理反应触发、条件分支、空间落点或构筑依赖，任一遗漏都会明显改变结果。 |

## 6. 五枚现有棋子示例（非正式矩阵）

以下示例仅验证本标准可用，**不构成其余 20 枚棋子的最终标注**。阵营按当前形态数据记录；主副定位和复杂度须在人工确认本标准后，才可用于正式 25 人矩阵。

| 角色形态 | 阵营 | 主 / 副定位 | 构筑标签及关系 | 复杂度 | 判定依据 |
| --- | --- | --- | --- | --- | --- |
| 提里奥 (`blue-tirion-fordring`) | 善 | 进攻 / 保护、控制 | `机制:圣盾`：开局获得圣盾，消耗圣盾后以伤害和击退兑现。 | 2 | 三个可见技能；需理解圣盾前置和近身击退，但没有持续专属资源或跨回合选择。 |
| 安娜 (`ana`) | 善 | 支援 / 控制 | `机制:区域治疗`：生物手雷在区域内分别治疗友军、伤害并禁疗敌军；`机制:弹道`：麻醉镖按直线首个命中结算。 | 3 | 三个可见技能，包含 2×2 区域、弹道遮挡、睡眠提前解除与友军强化目标选择。 |
| 水门 (`blue-minato`) | 善 | 机动 / 进攻、体系 | `专属:飞雷神锚点`：每回合创建、最多保留 3 个并被传送技能消耗；`专属:飞雷神标记`：标记目标后可在其成为技能目标时选择反应。 | 4 | 四个可见技能；同时管理锚点和标记，存在跨回合上限、可选反应、传送落点、条件击杀和随机目标。 |
| 莉亚德琳 (`liadrin`) | 善 | 体系 / 支援、进攻 | `机制:圣盾`：萃取或失去圣盾触发资源转化；`体系:圣光手牌`：生成、累积、弃置圣光惩击/治疗/充能，并由哀鸣转化为群体效果。 | 4 | 三个可见技能但需管理手牌、圣盾触发与弃牌阈值；核心结果依赖圣光手牌循环，而非单次施放。 |
| 拉法姆 (`red-rafaam`) | 恶 | 控制 / 体系、保护 | `专属:诅咒手牌`：伤害被免疫后按伤害值创建并交给对手，跨回合结算且可被增幅。 | 4 | 三个可见技能，包含每回合限制、受伤反应、记录数值、对手手牌决策、回合末随机目标和行动点操控。 |

## 7. 两轮独立复标记录

复标按第 2、4、5 节进行。两轮分别以“先读棋子与技能描述”和“再读关联规则、卡牌及效果定义”的顺序独立完成；第二轮不修改标准，只记录差异。

| 角色 | 第一轮结果 | 第二轮结果 | 不一致项与处理 |
| --- | --- | --- | --- |
| 提里奥 | 进攻 / 保护、控制；2 | 相同 | 无。 |
| 安娜 | 支援 / 控制；3 | 相同 | 无。 |
| 水门 | 机动 / 进攻、体系；4 | 相同 | 无。 |
| 莉亚德琳 | 体系 / 支援、进攻；3 | 体系 / 支援、进攻；4 | 第一轮未计入“圣光手牌的生成—弃置—阈值结算”这一跨技能资源链；按第 5 节专属/构筑对象与跨回合资源管理，定为 4。 |
| 拉法姆 | 控制 / 体系、保护；4 | 相同 | 无。 |

唯一不一致来源是第一轮遗漏了莉亚德琳的手牌资源循环。该记录说明：复标时必须检查关联卡牌和规则，不能只按技能数量评分。

## 8. 评审检查清单

- [ ] 每个角色形态有且仅有一个主定位，副定位不超过两个。
- [ ] 主定位来自词表，并按优先级流程作出选择。
- [ ] 每个构筑标签均标明类别、资源/组件与触发或消耗关系，且没有重复定位。
- [ ] 复杂度为 1–4 级，能回指第 5 节的具体维度。
- [ ] 标注没有使用 rarity、强度、人气或美术判断。
- [ ] 形态的阵营按其自身记录，未从座位或其他形态推导。
- [ ] 将标注结果交由另一名评审者独立复标，并记录差异来源。

## 9. 后续使用

RED-40 的正式 25 人矩阵必须引用本文，并在开始标注前获得人工确认。若新增定位词、标签类别或复杂度维度，应先更新本标准并记录评审理由，不能在矩阵中临时创造术语。
