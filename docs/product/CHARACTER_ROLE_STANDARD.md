# 角色主标签、副标签与复杂度标准

状态：已按最新产品决定更新

关联任务：[RED-39](https://linear.app/redvsblue/issue/RED-39/定义角色主副定位构筑标签与复杂度标准)

适用范围：Demo v0.1 的角色内容描述与后续角色矩阵。

> 本文是角色分类标准，不是规则、数值或强度评估。对局规则以 [Demo v0.1 核心对局合同](./DEMO_V0_1_CORE_MATCH_CONTRACT.md) 为唯一权威来源；静态数据只可作为标注依据，不能补充未写入合同的规则。

## 1. 标注对象与字段

每个“角色形态”是一条独立记录。普通、变身、复活或其他可独立选择/展示的形态可分别标注；内容阵营按该形态自身记录为光方、暗方或中立，不从座位、先后手或其他形态推导。

| 字段 | 约束 |
| --- | --- |
| 主标签 | 必须有 1 个，最多 2 个，取自第 2 节词表，标签不得重复。 |
| 副标签 | 可为 0 个或多个；只使用第 3 节定义的 `体系:<名称>` 与 `专属:<名称>` 格式。 |
| 复杂度 | 必须为 1–4 级，按第 5 节可观察判据判定。 |
| 阵营 | 按具体形态标注为光方、暗方或中立。 |
| 判定依据 | 必须列出支持主标签及每个副标签的技能、被动、资源、实体或规则。 |

副标签不设上限，但只记录角色的体系资源或专属资源；不记录通用机制，也不记录协同对象、触发链或实际协同说明。`rarity`、强度、胜率、人气、美术复杂度和开发成本均不得参与标签或复杂度判定。

## 2. 主标签词表

主标签描述角色在一局中稳定、值得围绕部署和资源使用的战场职责，不描述孤立的一次性效果。

| 标签 | 职责 | 不应仅因……而选择 |
| --- | --- | --- |
| **保护** | 持续阻止友军或自身被击杀、受伤或限制，核心价值是维持存活。 | 单次自保或单次治疗。 |
| **控制** | 持续限制敌方移动、行动、选项、区域或时序，以创造局面优势。 | 伤害附带的轻微减益。 |
| **支援** | 持续提升、治疗友军，或提供可由队友转化的行动、手牌等资源。 | 只强化自身。 |
| **进攻** | 主要通过直接、稳定的伤害或击杀压力推进胜利。 | 以铺设、限制或资源循环为主要目标的伤害。 |
| **机动** | 主要以位移、换位、传送或位置重构取得价值，且价值不依附于一次伤害。 | 只用于接近攻击目标的短距离移动。 |

“体系”不是主标签；资源循环、共享组件与角色专属对象只能按第 3 节记录为副标签。

## 3. 副标签

副标签补充“角色依赖什么可管理资源或循环”，不重复主标签职责，也不描述角色之间的实际协同关系。

| 格式 | 使用条件 | 示例 |
| --- | --- | --- |
| `体系:<名称>` | 多名角色或组件可共享、生成、消耗或转换的资源/循环。 | `体系:圣光手牌`、`体系:恶魔召唤`。 |
| `专属:<名称>` | 仅由该角色或形态创建、累积、消耗或转换，不能被其他角色等价替代的资源、实体、状态或形态。 | `专属:飞雷神锚点`、`专属:诅咒手牌`。 |

同一事实只记录最具体的一项副标签；若资源既是体系又是专属，按实际可共享性选择其一。不得以“伤害”“治疗”“控制”“圣盾”等主标签职责作为副标签。

## 4. 标签判定流程

1. 列出角色不依赖特定队友时能反复提供的战场贡献，并记录相关技能、被动或规则。
2. 从第 2 节选择最能改变部署、目标或资源决策的职责作为主标签；可选择第二个不同职责，但总数不得超过 2 个。
3. 列出角色创建、累积、消耗或转换的资源、实体、手牌、状态与形态；每项符合第 3 节定义者记为副标签，数量不限。
4. 删除通用机制与任何协同说明；这些内容只能作为判定依据，不是标签字段。

## 5. 复杂度量表

复杂度衡量首次正确使用角色所需的规则理解和决策负担，不衡量强度或稀有度。检查可见技能数量、专属状态/手牌/充能/召唤物/形态、时序与条件、空间规则及构筑依赖后，按命中的最高等级定级。

| 等级 | 可观察判据 |
| --- | --- |
| **1：入门** | 至多 2 个需主动理解的可见技能；无专属对象、反应或跨回合记忆；至多一个直观单目标或自身空间判断。 |
| **2：基础** | 约 3 个可见技能，或一个短时状态、简单区域或弹道规则；没有需要同时管理的专属资源链；至多一个明确条件。 |
| **3：进阶** | 有两个以上对象/状态、持续跨回合效果、反应触发、两步目标选择、非直观区域/弹道/位置判断，或明确资源循环之一；核心循环仍可用少量规则完整表达。 |
| **4：专家** | 同时涉及多个维度，且玩家必须跨回合管理资源、手牌、形态、召唤物或地图对象，并处理反应、条件分支、空间落点或资源循环；遗漏任一项会明显改变结果。 |

下例只验证标准可用性，不构成其余角色的最终标注。

## 7. 评审清单与后续使用

- [ ] 每个角色形态有 1–2 个不同主标签，均来自第 2 节词表；不存在“体系”主标签。
- [ ] 每个副标签均为 `体系:<名称>` 或 `专属:<名称>`；数量不限，且有资源、实体、状态、形态或循环依据。
- [ ] 不存在通用机制、副标签协同对象或实际协同说明字段。
- [ ] 复杂度为 1–4 级，并能回指第 5 节具体维度。
- [ ] 标注未使用 rarity、强度、人气或美术判断；阵营按形态自身记录。
- [ ] 结果由另一名评审者独立复标并记录差异。

后续矩阵应引用本标准，并把旧定位与协同字段迁移为“最多两个主标签 + 不限数量副标签”后再用于正式标注。新增主标签词或副标签类别时，须先更新本文并记录评审理由。
