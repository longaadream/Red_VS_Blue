# 棋子技能描述语言标准

状态：RED-192 语言标准初稿，供角色文案审核与后续编辑器实现使用。本文示例尚未批量写入技能 JSON；本轮只按用户确认修正灵魂汲取的正文、预览和日志文字。玩法以已确认的[基础规则词典](RULE_DICTIONARY.md)为准。图编程接入见[实施方案](../technical/SKILL_GRAPH_AUTHORING_PLAN.md)。

## 1. 描述需要回答的问题

玩家应能顺着一句话读懂：何时生效、影响谁、做什么、多少、多久。只写该技能需要的信息，不要求每个技能填满同一种长句。

技能卡分为三个展示层次：

1. **参数栏**：技能类型、行动点消耗、充能消耗、冷却、每局次数。由数据生成，不在正文反复抄写；界面暂未展示的关键限制仍须留在正文。
2. **效果正文**：固定句式，保留关键选择、先后顺序与特殊限制。名称和角色特色用语可以保留。
3. **词典解释**：点击或悬浮查看定身、圣盾、真实伤害等通用含义，以及计时、叠加、取整规则。

“率先出阵”继续使用用户确认的短句：“当阵容中有鸣人时，鸣人首先上场。”多个率先出阵候选只随机选一个，放在部署公共规则中，不补到每张角色卡上。

## 2. 固定句式

| 用途 | 句式 | 示例 |
| --- | --- | --- |
| 主动效果 | 对／使／将【目标】【效果】。 | 使3格内1个敌方棋子获得定身，持续1回合。 |
| 手动选择 | 选择【数量、范围、关系】；【对选定目标执行效果】。 | 选择1个其他友方棋子，将其传送至指定地格。 |
| 事件被动 | 【明确事件】后，【效果】。 | 自身造成实际伤害后，恢复等同于实际伤害50%的生命。 |
| 回合触发 | 【谁的回合开始／结束】时，【效果】。 | 你的回合开始时，准备进度减少1。 |
| 条件 | 若【条件】，则【效果】。 | 若准备进度归零，则结束打坐并获得奖励。 |
| 顺序 | 【效果A】，然后【效果B】。 | 满血复活，然后攻击力提高50%。 |
| 限时效果 | 【状态或效果】，持续N回合。 | 使目标获得定身，持续1回合。 |
| 限时复合效果 | 持续N回合：【同一状态的效果清单】。 | 持续2回合：自身受到的伤害减少50%；…… |
| 延迟一次 | 【明确的未来结算点】，【效果】。 | 目标的下一个回合结束时，结算该效果。 |
| 选择模式 | 选择一项：【模式A】；【模式B】。 | 多模式的效果分开列出，秘密选择明确写“秘密”。 |
| 玩家级持续规则 | 游戏开始时，在本局游戏中每当【事件】，【效果】。 | 古尔丹的裂魂，保留用户确认的原句。 |

这是作者写法，不是增加一批玩家需要记忆的新关键词。事件的“时／后”应对应运行时阶段；正文不能把伤害发生前的修改写成伤害发生后的响应。

## 3. 对象与动作词汇

| 统一用语 | 使用规则 |
| --- | --- |
| 自身 | 拥有／施放此技能的棋子；“自身恢复生命”。 |
| 你／你的 | 对应玩家；“你获得行动点”“你的回合开始时”。不写“你7格内”指棋子射程。 |
| 目标 | 本步骤明确选定或由事件给出的对象。有多个目标时命名“选定友军”“目标地格”“伤害来源”，不连续用“其”让指代改变。 |
| 友方棋子／敌方棋子 | 对象类型明确。允许或排除自身必须有选择器字段；排除自身时正文写“其他友方棋子”。旧内容不能仅凭“友军”一词推导是否包含自身。 |
| 全部／随机／选择 | 分别对应集合、随机筛选、玩家输入。“生命值最低”等自动选择与手动选择分开。并列最值的处理必须有规则依据。 |
| 普通攻击／造成伤害 | 普通攻击是动作类型，造成伤害是结算结果。技能、持续伤害、反伤不能被“攻击者”含混代指。 |
| 造成／受到 | 明确伤害源和承受者。来源可为棋子、玩家规则或环境；只有棋子来源才有可反冻的棋子。 |
| 恢复生命／获得护盾 | 分别使用治疗与数值护盾能力。圣盾使用“获得圣盾”，不叫“1点护盾”。 |
| 主动走格／冲刺／传送／推拉／换位 | 移动种类分开。技能专属路径、距离、碰撞效果仍须写明；不能仅靠“冲刺”两字猜测是否穿过单位。 |
| 死亡／复活／强制移出战场 | 生命周期动作分开。强制移出战场不造成伤害、不视为死亡；复活会先发生死亡。 |
| 获得状态／移除状态／延长时长 | 对应不同操作。重复获得遵循状态定义，明确延长才直接表达延长操作。 |

资源用“行动点”“充能”；紧凑参数栏可用 AP、CP 并提供中文说明。属性统一称“攻击力”“防御力”“移动力”“生命值”“最大生命值”，不在同一系统混用移速、速度和移动力。

“获得一张灵魂残片”等生成手牌的效果，不改写成“抽一张牌”。

## 4. 时间与数值

- **持续时长**：使用“持续N回合”，含义引用词典；正文不逐次解释“施加当回合不计入”。
- **触发时点**：必须写“你的回合开始时”“目标的回合结束时”等；禁止以“每回合”“N回合后”代替未确定的阶段和计时方。
- **准备进度**：明确初始值、更新时点、每次变化量和完成效果。进度不是状态持续时长，鸣人的6点准备不叫“持续6回合”。
- **冷却与次数**：使用现有参数，不和持续时长互换。每局次数须保持可见，不能因缩短正文丢失。
- **永久性**：不能把未写时长自动解释成任意“永久”。作者需在结构化定义中选明持续方式；既有技能按代码与设计核对。棋子身上的无期限效果和“本局玩家规则”不是同一种生命周期。
- **固定与百分比**：“攻击力+2”和“攻击力提高50%”区分；后者默认按生效前当前值计算。伤害倍率写“造成等同于自身攻击力250%的物理伤害”，类型和计算对象不能省略。
- **实际伤害**：用于吸血、反冻等已经发生的结果；不包含护盾吸收和过量伤害。界面显示预估伤害时，应注明这是预估值，不能冒充已扣除的生命。
- **取整、最低伤害和叠加**：统一走词典，不重复塞进技能正文。状态强度、实际到期点、来源仍必须在作者数据中完整保存。

多效果按明确执行顺序描述。“同时”仅用于已经支持的同批伤害、治疗、召唤或死亡，遵守 [ADR-0022](../decisions/ADR-0022-deterministic-effect-batch-queues.md)。不得把逗号或“并”自动编译成同时结算；图中的顺序和批次须显式保存。

## 5. 哪些信息可以省，哪些不能省

可以放进公共词典：定身允许传送、真伤仍受减伤、圣盾不叠加、持续时长的默认计时、每步向下取整、复活的默认状态清理。

必须让玩家看见：伤害类型和倍率、目标范围和数量、关键排除项、延迟的结算点、可选模式、秘密选择、每局限用、特殊停止条件、区别于通常效果的例外。

地图边界、权威提交校验、已被预留的落点、重复输入等实现保障放在公共规则与错误提示中。不能为了省字把某个角色特有的限制误当成公共规则。

正文、参数栏、关键词提示和预览共用定义。临时缺少某种展示控件时，先保留必要正文；控件落地并验证可见后再删重复文字。

## 6. 现有角色的审核示例

以下是描述改写提案，不代表已修改技能或增加玩法。范围、费用和冷却仍取各技能数据。需要玩法裁决的案例单独列在下一节。

### 鸣人：率先出阵

> 当阵容中有鸣人时，鸣人首先上场。

原句保留。来源：[naruto-vanguard.json](../../data/skills/naruto-vanguard.json)。

### 鸣人：仙人模式

> 进入打坐状态，准备进度为6。打坐期间，不能主动走格或使用技能。
>
> 你的回合开始时，准备进度减少1，每个存活的友方影分身额外减少1。准备进度归零时，结束打坐，你获得3行动点和1充能。

将进入、推进、完成分成三部分；保留打坐设定与每个分身的加速。来源：[naruto-sage-mode.json](../../data/skills/naruto-sage-mode.json)、[推进规则](../../data/rules/rule-naruto-sage-tick.json)。

### 带土：神威·转移

> 选择自身7格内1个其他友方棋子，将其传送至自身7格内1个空的可行走地格。

两个7格都以带土为中心。“传送”即时结算无需另写“立即”；特殊延迟传送才标注时点。来源：[obito-ally-teleport.json](../../data/skills/obito-ally-teleport.json)。

### 带土：神威

> 万花筒。选择地图上1个敌方棋子，将其强制移出战场。每局限用一次。

保留“万花筒。”前缀；强制离场的通用含义进词典。现有参数栏尚未证明展示每局次数，示例保留这句限制。来源：[obito-space-time.json](../../data/skills/obito-space-time.json)。

### 古尔丹：裂魂

> 游戏开始时，在本局游戏中每当一个棋子死亡，获得一张灵魂残片。

用户确认原句保留。机器定义拆成“开局授予玩家规则”和“该规则响应棋子死亡”，不能改成古尔丹登场后才生效。来源：[soul-fracture.json](../../data/skills/soul-fracture.json)。

### 死神：收割

> 自身造成实际伤害后，恢复等同于实际伤害50%的生命。

明确恢复者与数值来源，不写过量伤害、取整等补充条款。来源：[reap.json](../../data/skills/reap.json)、[reap-heal.json](../../data/skills/reap-heal.json)及公共伤害管线。

### 阿尔萨斯：寒冰坚忍

> 持续2回合：自身受到的伤害减少50%；受到实际伤害后，使伤害来源的敌方棋子获得冰冻，持续1回合。

前者是自身状态的2回合，后者是被反冻目标的1回合。作者数据必须将两份时长分别绑定持有者。来源：[arthas-icebound-fortitude.json](../../data/skills/arthas-icebound-fortitude.json)。

### 阿尔萨斯：巫妖誓约

> 使自身3格内1个友方棋子获得巫妖誓约。该棋子死亡后满血复活，然后攻击力提高50%，并重置所有技能冷却。

保留正式死亡与后续顺序；复活清除旧状态、恢复初始能力的默认行为由词典解释。来源：[arthas-lich-covenant.json](../../data/skills/arthas-lich-covenant.json)。

### 安娜：纳米激素

> 使自身10格内1个其他友方棋子防御力+3、移动力+1，造成的伤害+1。

固定加值不写成百分比增幅。重复施加各项相加由纳米激素状态定义提供。来源：[nano-boost.json](../../data/skills/nano-boost.json)。

### 基尔加丹：灵魂汲取（已按用户确认修改）

> 对生命值最低的敌方棋子造成999点真实伤害，然后对所有存活的敌方棋子造成等同于该目标最大生命值30%的法术伤害。

用户确认保留999点真实伤害，允许修正描述。正文和预览不再承诺消灭目标，日志不再无条件声称已消灭。第二段按现有代码覆盖所有仍存活的敌人，包含未死亡的主目标或其复活实例；本轮不改变筛选和结算。来源：[kiljaedan-soul-drain.json](../../data/skills/kiljaedan-soul-drain.json)。

## 7. 核对中发现的问题

| 内容 | 当前差异 | 处理 |
| --- | --- | --- |
| 基尔加丹·灵魂汲取 | 原描述保证“足以消灭”，代码造成999真实伤害，可能被圣盾挡住；第二段包含仍存活的主目标。 | 用户已确认保留999真伤；文案按当前行为修正。未来迁移自动选择节点时，还须显式记录并列最低时的现行稳定数组顺序，不能改成随机。 |
| 末日铁拳·火箭重拳 | 描述“路径上的敌人”像多目标，代码只击中首个敌人，友军也会阻挡；选定地格用于方向，代码并不以该格为终点。 | 单独确认路径选择与碰撞意图后，再定最终句子；不为统一文案擅自改成范围攻击。 |
| `keywords` / `effectTags` | 中英文和用途混合，例如仙人模式为 `control/resource`，其他技能使用中文。描述性标签可能被误认为实现了对应机制。 | 制定稳定ID与显示名映射后迁移，不能靠批量替换文字改变规则。 |

来源：[灵魂汲取](../../data/skills/kiljaedan-soul-drain.json)、[火箭重拳](../../data/skills/rocket-punch.json)、[关键词目录](../../data/skill-keywords.json)。以上为发现记录，未执行额外玩法变更。

## 8. 作者审核清单

1. 每个代词能指向唯一对象；玩家与棋子不混用。
2. 每个回合触发点都有阶段与所属玩家；触发时点、持续时长、准备进度分别填写。
3. 伤害、治疗、护盾、死亡和离场使用对应动词；百分比写明计算对象。
4. 描述能追溯到目标选择器、效果与状态定义；无法映射的内容列为缺失能力或待确认问题。
5. 通用边界进入词典，角色特有限制保持可见；参数栏与预览不能和正文各有一份独立数值。
6. 改写不改玩法。发现描述与代码冲突时先给出具体反例，请设计者确定意图，再修改与验证。
