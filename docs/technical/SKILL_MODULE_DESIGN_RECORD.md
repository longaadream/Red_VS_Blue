## 已确认的公共接口与执行语义

### 变量与选择

```text
新建【棋子】变量【tmp】 = 目标选择器（
    范围：5，筛选条件：{关系：敌方}，类型：棋子
）
新建【数值】变量【数值】 = 当前棋子.攻击力 × 1.5
```

使用属性访问写法，如 `当前棋子.攻击力`。棋子变量保存引用，数值赋值保存当时计算值。支持字面量、变量、表达式及嵌套调用。地格筛选使用明确字段：

```text
目标选择器（范围：5，筛选条件：{可行走：true，被占用：false}，类型：地格）
```

用户已确认集合统一使用泛型 `集合<T>`，例如 `集合<棋子>`、`集合<手牌定义>`、`集合<状态>`、`集合<伤害结果>`，不为每种元素创建独立集合数据结构。旧讨论中的“棋子集合”等均应改为此写法。排序、取项、随机选择等共用集合模块，仍根据元素类型校验输入与输出；显示写法包含 `<T>` 不代表类型校验被省略。此处早期“集合有序可索引”的决定已被最新Set/vector区分覆盖，不能作为当前规范。

跨触发器数据保存在持有对象的 extension。必须先创建有类型的变量，再存储；extension 不自动留位置。局部变量只在当前执行中可用。

### 伤害

```text
新建【伤害结果】变量【结果】 = 造成伤害（
    目标：tmp，类型：普通，伤害量：数值，伤害来源：当前棋子
）
```

- 类型只提供普通、真实；不区分物理、法术，不新增毒素类型。真实伤害只无视防御。
- 目标可为棋子或棋子集合；集合伤害同时结算，返回逐目标结果。
- 伤害来源可为棋子实例、玩家实例或卡牌实例。卡牌指具体手牌，不是定义/名称；来源棋子死亡时整条伤害语句无效，不自动转为玩家。卡牌进入弃牌区不等于棋子死亡；历史身份规则不变。独立延迟伤害从创建时就保存玩家来源。
- 返回值包含 `是否击杀`，表示本次伤害导致目标死亡，不等同于目标已离场。
- 未被阻挡的伤害最少为1；被 blocked 不产生 afterDamageTaken。状态的处理顺序遵循状态优先级与现役排序方向。
- 整数数值由引擎在写入或结算时自动向下取整，技能代码不必显式调用取整。计算表达式保留正常小数运算，不将每个中间运算擅自截断。

已确认：伤害结果.实际伤害量表示本次直接生命扣减，不含护盾吸收和溢出，被blocked为0；不是所有后续反应结束后的生命差。

### 状态

```text
新建【状态】变量【状态实例】 = 附加状态（
    目标：目标，类型：状态引用（燃烧），强度：3，持续时间：2，
    来源：当前棋子，可见玩家：所有玩家
）
```

目标支持棋子与棋子集合，批量附加生成独立状态实例。状态关联规则可以引用外部文件。状态来源支持棋子/玩家，用于历史身份和叠加分组，不套用伤害来源回退；实际出伤使用各效果显式声明的来源。

已确认：支持按玩家指定状态可见性；可见就是可驱散，不另设独立开关。具体查看者下的驱散权限仍须在实施时写成明确契约。

此前确认的状态计时与叠加：附着在棋子上的状态按当前所属玩家回合结束褪层，技能冷却也按所属玩家回合结束减少；新附加的本回合不计。持续时间在对应回合结束自动减1。最新补充合并前提：同类型、同来源或双方都无来源；满足前提时，同持续时间加强度，同强度加持续时间，两者相同则两者都加，两者都不同则分别存在。不同来源保留独立实例；声明不叠加的状态仍按既定忽略新状态处理。移除只针对可见状态。

### 规则与控制

Rule 显式声明触发器，而不是笼统标记“被动”。一个 Rule 可以有多个触发器共用执行内容。主动技能入口对应使用本技能。

`结束` 类似 return：结束当前效果执行，保留已经结算的效果。伤害没有成功不自动停止后续独立的附加状态。

目标引用失效后，引用该目标的语句自动无效；其他独立语句继续。引擎负责依赖传播，不要求作者重复编写目标存活或传送成功的 fallback。预期目标失效不是吞掉程序异常；非法类型、未声明引用等契约错误仍应报错。
