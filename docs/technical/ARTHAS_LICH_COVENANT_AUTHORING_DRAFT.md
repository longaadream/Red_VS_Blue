## 死亡后组合

Rule使用当前棋子.死亡后，保留基线优先级-100。首先查询只读死亡记录是否有巫妖誓约；没有则结束。读取当前事件.棋子.初始定义、死亡时所属玩家、阵营、核心/召唤物身份及各技能剩余次数；位置使用当前事件.死亡位置。此处为死亡事件允许的历史只读访问，不赋予死者行动权限。

随后声明棋子模板：初始定义的名称/外观/最大生命/防御/移动/技能/规则/初始状态，当前生命为初始最大生命，攻击为初始定义.攻击力×1.5。保留死亡时核心/召唤物身份、归属及阵营，不继承临时强化和额外挂载技能/状态。巫妖誓约本身不作为临时状态带回，因此不自动无限复生。只调用通用召唤创建新实例，不取消原死亡，不用治疗或直接写坐标代替召唤。

已确认恢复的每个初始技能冷却为0，但每局剩余次数保持死亡前值。不能召唤后再循环修改：召唤后Rule、首次UI展示可能已经读取重置后的次数。也不能把整份死亡棋子技能实例塞给新棋子：会带入旧冷却、临时技能与旧持有者关系。

用户决定将上述技能冷却/次数恢复放在引擎层默认执行，不要求模板逐技能填写初始化值。撤回Skill初始化结构体提议。恢复时引擎依据原实例历史成员保留每局剩余次数，默认冷却0；全新成员无历史则按定义初始次数。全部在召唤后事件与首次显示之前完成。

作者声明本技能的初始能力模板与攻击加成，恢复来源保留历史身份供引擎对应成员；不通过名称匹配，不循环复制次数。内部成员和Cluster归属重建属于引擎实现责任。

```text
        结束
    新建【棋子定义】变量【初始定义】 = 当前事件.棋子.初始定义

```

模板中的基础定义表达以原初始配置创建属性、技能、规则、初始状态和extension声明默认值；恢复来源仅提供历史成员对应及次数，不意味着继承死亡前全部临时数据。两个字段是将已确认恢复政策写入通用模板的作者命名，不是新的巫妖专用引擎节点。静态定义本身不能提供某个实例的历史次数，因此必须保留这个历史身份上下文；作者无逐技能初始化代码。

原记录始终只读，召唤创建新棋子和成员身份，初始化默认冷却0/历史次数在所有召唤后响应之前生效。只传离场棋子直接回场的接口仍保留原实例，不能代替这里的初始模板创建。位置失败时召唤失败，既有死亡继续完成。保留核心身份不代表取消死亡或跳过通用判负；胜负检查点须由生命周期统一验证。
