# 神威及万花筒费用作者核对

基线obito-space-time、rule-mangekyo-friendly-death、getEffectiveChargeCost与ultimate使用限制。此文是作者草案，动态费用表达式及按需UI更新已确认，不代表运行实现。只改设计文档。

## 已核对行为

神威：AP5，基础CP3，冷却0，每局1次，选择范围99的敌方棋子，将其出局，不触发死亡。maxCharges=0没有覆盖ultimate实例的usesRemaining/每局次数限制；已核对turn.ts的ultimate支付会扣减剩余次数。因此作者次数写1，不漏写或依赖大招分类标签隐式限制。

出局复用已确认通用模块，保留原实例历史身份与原核心/召唤物属性。基线宿主移出battle.pieces并清理相关流程，额外记录removedPieces；新模块不得通过直接改坐标或清HP假扮死亡，也不能把移除核心棋子自动当成判负豁免。

基础CP3由chargeCost提供；chargeCostModifiers读取battle.extensions.contentCounters.mangekyoDeaths[施法玩家]，逐次减免并钳制最低0。相同减免也用于佐助须佐能乎，不能只在神威作者代码写死3而忽略公共万花筒费用行为。

基线死亡记录要求当前玩家有隐藏万花筒见证者，同玩家多个见证者只由首个记录；旧onPieceDied发生于离场前。用户最新明确取消见证者要求，改为玩家级常驻Rule整局计数，详细代码见MANGEKYO_AUTHORING_DRAFT.md。作者仍使用己方死亡前的已确定死亡阶段，不由出局触发；没有带土/佐助在场也会累计，这是用户指定的行为变化。

## 神威主体草案

```text
技能：神威
触发器：使用技能
行动点消耗：5
充能点消耗：最大值(0, 3 - 当前棋子.所属玩家.extension.万花筒减免)
冷却：0
每局使用次数：1

code：
    新建【棋子】变量【目标】 = 目标选择器(
        类型：棋子，范围：99，筛选条件：{关系：敌方}
    )
    出局(棋子：目标)
```

费用字段表达式已获用户确认。最大值为纯数值函数的展示名称，不注册神威专用费用节点。玩家extension计数须先由对局初始化配置显式声明为数值0，后续同名同类型声明复用；缺变量不偷偷分配或替代0。计数映射从现有全局按玩家索引形式映射到作者玩家extension，不新建全局状态源；实际迁移和存读对齐未实施。

已确认费用支持纯数值表达式，由引擎统一用于按钮提示、可用性检查与正式扣费；费用非负整数、整数写入向下取整，表达式无副作用。不在技能code里手动调整CP，不把本次费用减免变成返还CP，也不把局部变量写共享定义。资源不足的拒绝仍在效果提交前。已确认费用按展示/准备使用/依赖变化更新，禁止轮询，最终确认重新校验；选择期间依赖变化通过通知更新，不宣称仅有表达式即可完成交易实现。

该提议先解决常驻状态/玩家extension驱动费用；Rule在使用前临时改本次费用、触发器与局部变量准备顺序等仍按公共释放流程待定，不擅自扩展成任意阶段反复重算或读写共享Skill定义。

待验证：友军死亡减免0/1/3/超过3、同玩家多个技能不重复、同阵营队友死亡、无见证者仍计数、中途获得使用历史减免、CP不足与减免后足够、预览/扣费一致、取消不耗费、每局一次、出局不触发死亡、核心出局判负、来源失效及目标改写。当前未运行游戏测试。

## 已确认UI更新与玩家级Rule

玩家选定的技能/Cluster声明万花筒玩家规则依赖时，对局初始配置为该玩家准备一份计数Rule和extension字段；可后续授予/复制/偷取的所选内容也可声明该依赖，引擎不按万花筒名称/ID硬编码；完整代码见MANGEKYO_AUTHORING_DRAFT.md。无带土在场仍计数，之后获得神威使用已有累计减免，不在神威Cluster获得时重新安装或清0。同一死亡该玩家只记录一次，减免字段改变使相关费用UI缓存失效。首次展示、准备使用和数据变化时更新，不轮询；提交时同一引擎计算再校验资源。技能转移后使用新所属玩家的计数，不迁移旧玩家计数。当前没有运行实现或性能验收。
