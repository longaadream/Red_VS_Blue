# 在编辑器里修改技能与规则代码

打开内容项目，选择技能、规则或卡牌，再切换到「代码」。
代码页显示普通 JavaScript，而不是 JSON 中带 `\n` 和转义引号的字符串。
直接粘贴 AI 输出的代码正文，不要带 Markdown 的三反引号。

- 技能：`code`，入口 `function executeSkill(context) { … }`。
- 卡牌：`code`，入口 `function executeCard(context) { … }`。
- 规则：`skillCode`，直接写规则语句，不额外包装函数。
- `effectCode`：已有延迟效果代码，匿名函数 `function(ctx) { … }`。
- 旧资源中的 `previewCode` 仍可查看以保持兼容，新建技能不再生成此字段。

代码页提供行号、语法高亮、括号匹配、代码折叠、搜索/替换、撤销/重做和格式化。
快捷键：Ctrl+S 保存，Shift+Alt+F 格式化，Ctrl+F 搜索，Ctrl+Z 撤销，Tab 缩进。
需要把键盘焦点移出代码区时，先 Esc，再 Tab。

「导入文件」可以选择多个 UTF-8 `.js` 或 `.txt`；「导入文件夹」只读取第一层这些文件。
一次最多 50 个文件，单文件最多 800 KB / 200,000 字符，总计 2 MB。
导入后先选择文件，查看内容以及「文件 → 当前 JSON → 当前代码字段」的目标提示，
再按「替换当前入口的草稿」。不会根据文件名猜测目标后批量覆盖资源。
不同技能/规则需要分别打开相应条目，导入到对应入口。
这只是一次性文本导入，不建立文件监听或双份源码同步。

格式化和导入均可 Ctrl+Z 撤销，直到「保存 JSON」才写盘。
保存程序自动处理 JSON 引号、换行和反斜杠，其他字段保持不变。
语法错误时格式化保留原文，保存改过的错误代码会失败并保留草稿。
外部程序改过同一个 JSON 时，原有 revision 冲突检查仍生效，不强制覆盖。

由类型化流程图生成的文档，其代码区只读。需要手写代码时，在「流程图」页选择
「解除图关联，保留代码」，然后进入代码页。

这里的语法检查不等于技能入口检查、Helper 类型检查或玩法测试；仍需按照
[SkillCode 作者标准](SKILLCODE_AUTHORING_STANDARD.md) 编写，并在训练营验证实际效果。
导入、编辑与结构检查不会执行脚本，也未接入 AI 服务。点击「训练营与反馈 → 打开训练营」时，已接受版本的技能与规则在独立试玩窗口执行；窗口显示版本，可自行配置场景。JSON 内的技能和规则代码可以随 `.rvbpack` 打包发布，
无需拆出 `.js` 文件，也无需改成单独的数值参数表。见 [资源包发布步骤](RESOURCE_PACK_PUBLICATION.md)。
