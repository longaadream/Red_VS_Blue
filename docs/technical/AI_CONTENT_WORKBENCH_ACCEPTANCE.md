## 验收流程

1. 打开管理器，从官方内容复制出普通内容项目文件夹，或新建空白项目。
2. 外部 AI/文本工具修改角色 JSON、贴图及技能代码；管理器刷新可见并校验。非法 JSON 显示具体文件/位置，不能覆盖源文件。
3. 一键加载到客户端测试，实际执行修改后的技能；目标选择/取消及失败无半提交行为有效。
4. 导出完整社区包，在另一内容安装中导入，不要求 GitHub 登录；一次只启用一套内容。
5. 切换或回退内容；失败激活恢复旧版本。有活动对局时给出明确提示。
6. 官方发布需要作者明确确认；本地未发布改动不进入玩家检查更新结果。

### 已验证的编辑器入口

本 worktree 的 `dist/editor/RED vs BLUE Editor 0.1.0.exe` 为 portable 候选；安装版为同目录 `RED vs BLUE Editor Setup 0.1.0.exe`。这两个文件均为本地候选，没有发布。

1. 启动 portable，点击“复制官方内容”，选择新项目保存位置。管理器会在该位置建立独立子目录，不覆盖原有目录。
2. 点击“文件夹”，让 AI 直接修改其中 `data/pieces/*.json` 或 `data/skills/*.json`。点击“刷新 AI 修改”重新读取磁盘。技能源码可编辑，但外部技能包的客户端运行仍属于未完成项。
3. 若在编辑器中已打开某个文件，再从外部修改该文件，旧编辑器内容保存会明确报冲突，保留磁盘上的 AI 修改。刷新前遇到未保存内容会提示是否丢弃。
4. “空白项目”只建立基础目录与空 manifest；不会在打开时补回官方内容。“打开项目”读取包含 `rvb-content-project.json` 的项目，并记住位置。
5. PVE JSON 同样采用版本检查保存。贴图导入与静态 SVG 校验沿用集成编辑器。现有根目录 public 中的旧版客户端美术不属于 `public/images` 内容包命名空间，因此不会伪装成可热更新素材复制进去。
