# 在编辑器中发布资源包

资源包保留 JSON 内的 `code` / `skillCode` 等代码字段。编辑器代码页显示正常换行的 JavaScript，保存时自动处理 JSON 转义。技能逻辑和数值一起随包交付。

## 第一次修改与发布

1. 用「导入原包」选择完整 `.rvbpack`，创建独立内容项目。
2. 修改内容，保存 JSON。
3. 在「待接受修改」查看差异并「接受选中修改」。只有已接受的版本会试玩和发布。
4. 在「训练营与反馈」点击「打开训练营」，选择阵营、棋子并开始对战。窗口标题显示接受版本；未接受草稿不会混入。修改并接受后，重新打开训练营测试新版本；原窗口保留原版本。试玩完成可在工作台记录场景和反馈。
5. 「版本与发布」→「导出资源包」得到可继续编辑、交换和备份的原包；不需要 GitHub 凭据。
6. 「发布测试更新」使用已接受快照，自动构建、签名、校验并上传 GitHub Release。首次填写仓库、Contents 写权限凭据和签名身份，之后沿用。

训练营使用编辑器附带的训练页面和引擎，加载已接受内容；不需要安装或启动游戏客户端。窗口关闭即结束本次试玩，不改变玩家存档和已安装资源。预览限本地训练，不测试联机同步。打开成功不代表玩法已通过，请实际操作技能后记录结果。

当前例子有四处修改：

| 条目 | 字段 | 修改 |
| --- | --- | --- |
| 棋子 `dark-aizen` | `stats.attack` | 4 → 5 |
| 技能 `ulquiorra-high-speed-regeneration` | `description` | 恢复2点 → 恢复1点 |
| 规则 `rule-ulquiorra-damage-dealt` | `skillCode` 中 `heal: 2` | 改成 `heal: 1` |
| 规则 `rule-ulquiorra-damage-taken` | `skillCode` 中 `heal: 2` | 改成 `heal: 1` |

小乌技能条目仅描述被动效果；真正的回血分别在造成伤害、受到伤害两条规则中。不要改归刃阈值或归刃后的攻击、移动属性。

## 玩家收到什么

首次发布包含 `content.rvbpack` 和 `content-update.json`。后续保有本机上一版发布记录时，还会自动生成 `content-patch.rvbpack`，并实际解析父版本链验证补丁。补丁必须匹配指定旧版本；新玩家或版本不匹配时使用完整资源包。

已发布版本不可变；重复点击会核对同一发布记录，不另发一份。还未接受的草稿不进包。
本次新版客户端已接入官方资源更新（须先安装包含该功能的新客户端）。启动 15 秒后及每 15 分钟检查官方公共仓库 `longaadream/Red_VS_Blue`，在主菜单可手动「立即检查」。资源包下载完成后，主菜单、Next/PVE 无占用且本机 Colyseus 无任何房间时才应用。房间服务在整个切换期间禁止创建新房间；失败保留原稳定版本或沿用既有回滚流程。手动导入候选未处理时，自动更新等待人工处理。

两条版本流独立：资源读取 `content-test-<内容哈希>` 下的 `content-update.json`；客户端由 electron-updater 读取 GitHub 稳定版本下的 `latest.yml`。资源 Release 保持 prerelease，不能设为 Latest。旧清单的 `automaticClientDiscovery: false` 只是当时客户端能力说明，不是禁用开关，仍兼容读取。编辑器可向任意配置仓库发布，客户端自动发现只认上述官方仓库。

资源版本从已验证 Profile 的最后一个补丁读取（无补丁时读取 Base），重启后也不重复安装。补丁仅父 Profile 哈希一致时下载；下载失败退回同版本完整包。签名/安装/激活失败不会绕过校验，候选保留供资源管理排查。菜单「自动检查并下载更新」可关闭后续自动检查及等待中的应用；已开始的应用仍完成。

客户端 Windows 发行改用 NSIS 安装包。`npm run build:electron:client` 会安装隔离 updater 依赖并生成安装程序、`.blockmap` 和 `latest.yml`，默认 `--publish never`，由开发者手动发布。每次客户端正式发行必须提高 package.json 版本，并把这三项一起上传到同一个稳定 Release；仅上传 zip/资源包不会成为客户端升级。首次安装后，后续可用二进制差量下载，服务器不支持范围请求或旧 blockmap 缺失时由 electron-updater 回退完整安装程序。下载后用户在主菜单点击「重启并安装」确认；普通退出不会偷偷安装。开发版、解压目录和非 Windows 版本显示不支持客户端自动安装。

## 一次性的客户端兼容升级

旧客户端一律拒绝资源包里的脚本，因此需要先发布一次包含本次安装支持的客户端。
客户端和编辑器构建均携带 `config/content-script-publishers.json`，列出受信发行者的公钥 ID。正式包只携带公钥 ID，不携带私钥。

本机「生成签名身份」将私钥保存在编辑器用户目录 `signing/official-content.key`。沿用同一身份并妥善备份；不要把该文件放进内容项目、仓库或 Release。更换身份需要先更新客户端信任配置。上传前编辑器会检查签名者与当前宿主配置一致，防止生成玩家无法安装的脚本包。

含脚本的玩家更新包必须有效签名且发行者受信；普通无签名导出仅供编辑。未签名、未知签名者、内容被篡改的脚本包不能安装。启动、激活和回滚也会重新检查原始签名链和当前信任配置。
签名确认发行者身份，不代表任意代码安全，也不是沙箱；只发布经过自己检查的内容。
