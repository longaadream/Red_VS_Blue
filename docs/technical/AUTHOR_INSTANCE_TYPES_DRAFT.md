# 作者运行实例类型

用户要求补齐Rule与Skill类型；本文件为作者框架设计，不代表运行实现完成。已有泛型集合、extension、实例比较与复制/应用信息约定继续适用。下列新字段名称与精确数据契约为展示草案。

| 类型 | 含义 | 主要接口/字段 |
| --- | --- | --- |
| Skill类型 | 一个具体Skill运行实例，不是定义 | 定义引用、持有者、当前冷却、剩余使用次数、所属Cluster、extension |
| Rule类型 | 一条具体Rule运行实例，不是定义 | 定义引用、挂载对象、来源、触发器、优先级、所属Cluster、extension |
| Cluster类型 | 一次获得的技能组合实例 | 定义引用、持有者、技能列表：元组<Skill>、规则列表：元组<Rule>、extension |

定义引用定位配置；实例引用定位本次运行对象。同定义多个实例彼此独立。集合为不可重Set，不支持索引；元组按vector提供有序可重复元素与索引，用户已确认下标从1开始，实例比较按身份，不按显示名称。持有者/挂载对象支持已确认的棋子或玩家情形；独立Rule不必属于Cluster，所属Cluster可为空。Skill次数无限/有限的具体表示尚待对齐，不臆定0或-1即无限。Skill定义中的费用和基础冷却不因修改一个实例而改变。

```text
获得技能(目标：棋子实例，技能：Cluster定义引用) → Cluster类型
移除技能(技能：Cluster实例)
附加规则(挂载对象，规则：Rule定义引用，来源？) → Rule类型
移除规则(规则：Rule实例)
Skill实例.当前冷却 = 数值表达式
```

获得Cluster添加其Skill与Rule；移除Cluster仅移除该实例带入的专属成员，不删除其他实例或共享通用Rule。引用StatusTag定义不自动给棋子附加状态，也不产生状态与Rule隐式关联。Skill/Rule单实例操作与Cluster整组操作不得混同。

此前提议重复获得同Cluster默认返回已有实例，不重建成员、不清空冷却/extension；用户接着要求补齐这套类型，但未逐项确认重复策略全部边界，恶魔变形具体案例已经确认复用既有Cluster并保留冷却，随后显式刷新剩余次数为2；不等于所有重复来源/多实例策略全量获准。定义/来源/归属等字段的可写范围、Rule优先级动态改写和Cluster多Skill操作继续对齐权威入口，不授权任意对象写入。

## Rule默认去重（最新确认）

同一挂载对象、同一Rule定义只保留一份Rule实例。附加规则返回新建或已存在的实例，重复调用不注册新监听、不重置extension/来源；无需作者检查或定义可重复字段。挂载对象不同的实例互相独立。重复延迟任务应使用元组/映射保存数据，不能依靠多份同定义Rule。此政策不意味着重复获得同Skill/Cluster实例默认行为全部获准，也不使Rule与状态关联。

## 复杂类型统一为结构体

用户确认自定义结构体，也明确棋子、Skill、Rule等现有复杂类型本来就是结构体。其有类型字段/extension、实例身份和有效性契约继续适用；不是构造一个同字段对象就取得合法运行身份。普通任务记录可直接构造，有实例引用的字段保持引用，不复制整个棋子或Rule。自定义结构体可作为元组/映射成员，复杂类型不另用字符串保存引用。


## 当前冷却直接字段写入：最新确认

用户撤回独立设置技能冷却模块，采用技能.当前冷却 = 数值表达式。接收内部Skill运行实例，权威引擎校验并通知UI；不改共享定义的基础冷却或使用次数。棋子.技能列表为可读元组<Skill>，不允许直接增删列表绕过Cluster获得/移除。

## 使用资格归属：莫提斯最新决定

蝙蝠增援的可用资格属于实际Skill实例，由Skill定义声明限制，只有可用/不可用，不叠加。资格耗尽保留禁用按钮，不用删Skill或状态强度表示。现有剩余使用次数/每局次数与可反复解锁资格不能直接混为一谈；作者字段与通用配置见下节，运行映射待实施。费用/冷却/合法目标检查不被解锁豁免。伤害进度可放extension，已可用期间继续累积已获用户确认；再次达到阈值时减3并重新设为可用已确认。

## 二态资格作者字段规范化

采用 `Skill实例.使用资格：布尔` 表达可重复解锁但不叠加的机会；定义可声明初始值及使用时自动消耗。该字段只代表额外资格，不代表最终按钮可点击（费用、冷却、其他条件仍检查）。成功提交时先消费，效果中可以重新解锁且不被结尾覆盖；不会重置冷却，不等于每局次数。关联实例通过实际Cluster成员定位。字段名称是作者规格，尚未实现。莫提斯满3扣3、已可用继续计数且不叠资格已全部获用户确认。

## Cluster初始化声明区（已确认）

Cluster提供初始化声明区，在获得时完成其中显式变量声明并部署指定Rule，随后才开放费用、资格与冷却预览和使用入口。初始化语句仍使用现有有类型extension声明、附加规则等模块，不按角色名硬编码，不把使用Skill正文或有副作用Rule拿到UI渲染时执行。

初始获得、中局获得/复制均走同一部署入口；成员实例先分配，初始化可以引用该Cluster的实际Skill/Rule及持有者。普通获得创建新实例，复制沿复制合同继承的数据不能被初始化清空。同名同类型extension重复声明保留旧值，同宿主同Rule定义重复部署复用已有实例；不同类型同名字段报契约错误，不伪造0或false。必须重置的数据用作者显式赋值。

绑定的所属玩家发生变化时，在新上下文首次依赖读取前准备该玩家的数据，保留原玩家记录；不会将原玩家累计减免复制到新玩家。该步骤沿依赖初始化处理，不伪造第二次游戏开始或重复召唤。恢复已有对局不重放普通获得副作用，按恢复/实例复制合同恢复后验证声明依赖。初始化完成前不暴露半初始化按钮；错误需报定义/成员/字段上下文，不能吞错后运行。

声明区部署什么Rule由作者明确指定。只依赖玩家减免变量的主动技能声明该变量即可，不因此自动获得被动受伤计数Rule。独立Rule与StatusTag的关系不变；移除Cluster成员沿既有成员归属合同，玩家extension不因移除技能自动清空。初始化UI/编译与运行支持尚未实现。

## 主动使用：默认提交先于效果代码（已确认）

顺序为准备选择与校验通过 → 费用、每局次数/使用资格及默认冷却提交一次 → 执行效果code → 使用后响应。效果结束不再用默认值覆盖作者写入的实际Skill冷却。准备失败/取消不提交，效果中成功结束不退款；已发生效果后不能返回使用失败来回滚。正文中的目标选择和用于准备的局部纯计算仍归准备阶段，不能按文本先后提前扣费，也不能为了提前找失败返回执行有副作用的效果。

Skill当前冷却直接写入继续有效；设置0允许后续按正常入口检查使用，写3进入真实冷却，不是假显示。冷却本回合不递减的既定规则同样适用于正常提交和作者权威写入；提交/挂起恢复不能重复付费或重复写默认冷却。此为通用协议，运行编译、准备阶段与引擎调度待实施验证，不引入相位专属许可机制。完整案例见[MAX相位偏移器](MAX_PHASE_AUTHORING_DRAFT.md)。

## 状态剩余持续时间直接写入（用户已确认）

`StatusTag实例.剩余持续时间 = 数值表达式`，接收实际状态实例，不修改共享定义。正值刷新保留实例身份、来源及extension，不移除重加、不触发状态移除/重新附加、不走叠加计算，也不重新部署Rule。无效实例沿缺失引用规则跳过；权威字段变化通知显示，不靠轮询。

本次具体确认是暗影步将原状态刷新为2。创建回合不递减仍按既定规则；刷新不伪造重新创建，暗影步另存标记回合来判定下个所属玩家回合开始。对永久状态改为有限状态，以及直接写非正持续时间的精确移除原因暂未冻结，本例不使用这些边界。状态强度耗尽的既有契约不变。

## 可组合代码块（用户已确认）

代码块是由现有语句/表达式模块构成的结构化程序值，不是JavaScript源码字符串。代码块可声明有类型参数，保存在变量、元组和extension中；存入时不执行。`执行代码块(代码块：代码块引用，参数：有类型结构体)`在调用时绑定显式参数并执行。护甲案例签名为`代码块<(目标:棋子),无返回值>`；编辑器用参数槽及语句列表表示，用户不需要输入源码。

本例只声明参数目标，不自动捕获组装技能的当前棋子、目标或局部变量。不同调用的局部变量各自独立；参数中的棋子保持实例引用，有效性遵守公共规则。片段通过正常治疗、附状态、附Rule、字段写入等模块产生效果，不能绕过引擎权威入口。手牌取得时初始化自身extension效果元组，使用时才遍历执行。

代码块本身不是Skill、Rule或Cluster，执行它不额外扣费、不伪造使用技能/手牌事件，也不自动获得Cluster成员。普通主入口仍统一负责选择、费用、冷却、弃牌和日志。代码块中的控制流不得成为绕过准备失败/效果提交边界的后门。

本次确认覆盖无返回值、显式参数、顺序执行的护甲片段。可带返回值的完整函数签名、片段内return如何退出调用者、递归/捕获变量与片段内部交互挂起等额外能力尚未逐项冻结，本例不使用。持久化需保存结构化定义/引用及版本，不能保存宿主函数对象；实际编译、保存、复制及编辑器支持待工程实施。

手牌可变extension及元组按既有逐实例独立原则保存，复制卡牌不共享可变元组；相同代码定义的只读引用可以复用，不能编辑一张牌就隐式改掉所有同名牌。定义热更新与已有对局版本策略不在本轮擅自修改。

## 状态extension参与合并与创建时初始化（用户已确认）

`附加状态(目标,类型,强度,持续时间,来源?,extension?:有类型字段结构体,可见玩家?,显示配置?)`增加extension初始化参数。引擎先按声明类型构造新状态的extension，再查找可合并实例，不能合并后才补字段。

可合并须同时满足：同状态类型、来源相同或均无来源、extension内容相同；任一不满足就保留独立实例。满足后再执行原强度/持续时间叠加规则。声明不叠加的状态仍按既有忽略新状态政策处理，不因本次增加“永不合并但可重复”的隐式模式。

extension按有类型内容比较，实例引用按身份比较，不按名称或对象展开后的字段相似度比较。双尾飞行使用`extension:{飞行任务:本次任务}`，不同任务引用不会合并，同任务仍遵守普通叠加。任务引用保留本次记录身份，不用时间戳或字符串模拟；任务从队列出队不会把仍被局部变量/状态引用的记录立即变成不可比较身份。

来源类型仍是原棋子/玩家，不采用此前扩展任务来源的提议。任务关联是普通extension字段，不产生StatusTag与Rule自动绑定。省略extension按定义声明初始化；比较的是最终内容，不是调用参数是否省略。直接修改现有extension不追溯自动合并既有状态。容器、循环引用的可保存编码与比较实现仍待工程验证，不能用JSON字符串化比较替代实例身份。
