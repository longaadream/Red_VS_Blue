# 鸣人：影分身与仙人模式作者草案

核验固定基线`082166c6b803b2e838bce5f0f6824c5bbc714dd6`的naruto-shadow-clone、naruto-sage-mode及分身脆弱/打坐Rule，按已确认新规则整理。作者代码不是已接入运行引擎的实现。

## 影分身之术

```text
Cluster：影分身之术
成员：影分身之术Skill
引用定义：影分身受伤消散Rule

Skill：影分身之术
触发器：使用技能
行动点消耗：1
充能点消耗：0
冷却：3
每局使用次数：不限
code：
    新建【布尔】变量【传送本体】 = 选项选择器(
        选项：映射<字符串,布尔>{"在目标格召唤分身":false，"传送并在原地留下分身":true}，
        可见玩家：集合<玩家>{当前棋子.所属玩家}
    )
    新建【地格】变量【落点】 = 目标选择器(
        类型：地格，范围：5，筛选条件：{可行走：true，被占用：false}
    )
    新建【玩家】变量【创建玩家】 = 当前棋子.所属玩家
    新建【地格】变量【原位置】 = 当前棋子.位置
    新建【棋子】变量【显示副本】 = 复制实例(实例：当前棋子)
    新建【棋子模板】变量【分身模板】 = {
        基础副本：显示副本，移动力：0，核心棋子：false，
        初始技能：元组<Skill定义>{}，初始状态：元组<状态定义>{}，
        初始规则：元组<Rule定义>{影分身受伤消散Rule}，
        extension：{影分身：布尔 = true}
    }
    新建【结构体】变量【伪装显示】 = {
        查看者条件：(玩家) => 玩家 != 创建玩家，
        名称：显示副本.名称，外观：显示副本.外观，
        当前生命值：显示副本.当前生命值，最大生命值：显示副本.最大生命值，
        攻击力：显示副本.攻击力，防御力：显示副本.防御力，
        移动力：显示副本.移动力，护盾：显示副本.护盾，
        技能列表：显示副本.技能列表，状态列表：显示副本.状态列表，
        核心棋子：显示副本.核心棋子

    如果 传送本体：
        位移(
            棋子：当前棋子，起点：原位置，终点：落点，
            敌军可通过性：true，友军可通过性：true，
            不可通行地格可通过性：true，中间地格是否经过：false

挂载对象：棋子
触发器：当前棋子.受到伤害后

    消灭(目标：当前棋子，来源：当前事件.伤害来源)
```

模板在技能内声明；Rule引用外部通用定义。复制副本不入场，模板覆盖技能/状态为空、规则仅受伤消散、移动力0，真实其他基础数值取创建时本体值。分身是普通召唤物，不增加第三种胜负身份；无普通死亡结晶掉落，不参与核心判负。显示技能不构成可使用的真实技能，不安装显示副本中的Rule/Cluster。

受伤后由引擎保证正实际伤害且未blocked才触发；直接致死后已进入死亡流程的实例不会再重复死亡。来源传递本次实际伤害来源，不凭空换成本体；额外击杀奖励按统一伤害/死亡归属处理，具体嵌套死亡结果须运行验证。这里不在代码重复写伤害量判定，不用生命值直接写0替代消灭。

传送分支的原地召唤沿用户已确认契约，属于前一次位移的依赖后续；位移失败由引擎使该依赖召唤无效，作者不写成功判断或fallback。模块编译/执行必须保留这项依赖，不能把两句编译成无条件独立执行。原地仍被本体占用时权威召唤本来也不能重叠，但不能仅依赖占用巧合实现失败传播。实际落点与原地都由生命周期检查，失败不追溯为准备阶段拒绝。

## 显示与识别

用户明确同阵营队友不能辨认；仅所属玩家看到真实分身，其余玩家（含队友）看到伪装。上面的查看者条件是显示配置的作者表达，所属玩家不适用覆盖，沿真实数据普通显示；不是隐藏信息字段列表。显示值取本次副本快照，不持续读取本体变化；后续真实变化允许暴露。首次出现、动画、面板和日志均按相同查看者规则，不能先出现真实分身再套皮肤。未设置的显示字段不特殊化。

只读显示副本中的技能/状态容器为快照，不能用活本体引用让冷却或层数继续跟随。查看者判定不得依赖后来失效的本体引用；实现应在创建时保存所属玩家身份。普通观战不授予所属玩家权限。公开数据不能通过extension.影分身、实例ID、核心标记或传送动画泄露秘密选择；具体投影映射须验收，不声称仅替换文字即可保密。

识别分身用模板声明的extension.影分身布尔字段，无需新增StatusTag或比较不同召唤模板的字符串ID。仙人模式按此字段筛选在场友军；缺失该声明的棋子不匹配，不自动创建字段。其他技能若有意创建同类分身，可显式复用该数据约定。

## 仙人模式

```text
Cluster：仙人模式
成员：仙人模式Skill
引用定义：仙人打坐StatusTag、打坐积累Rule、打坐限制Rule
初始化声明区：
    在【当前棋子.extension】中新建【数值】变量【打坐进度】 = 0

Skill：仙人模式
触发器：使用技能
行动点消耗：1
充能点消耗：0
冷却：10
每局使用次数：不限
code：
    如果 获取长度(容器：获取状态(目标：当前棋子，类型：仙人打坐)) > 0：
        返回技能释放失败(原因："已经处于打坐中")
    当前棋子.extension.打坐进度 = 6
    附加状态(目标：当前棋子，类型：仙人打坐，强度：1，持续时间：永久)
    附加规则(挂载对象：当前棋子，规则：打坐积累Rule)
    附加规则(挂载对象：当前棋子，规则：打坐限制Rule)

Rule：打坐限制
挂载对象：棋子
触发器：当前棋子.普通移动前、当前棋子.使用技能前
code：
    如果 获取长度(容器：获取状态(目标：当前棋子，类型：仙人打坐)) > 0：
        阻止当前事件

Rule：打坐积累
挂载对象：棋子
触发器：本玩家.回合开始
code：
    新建【元组<StatusTag>】变量【打坐状态们】 = 获取状态(目标：当前棋子，类型：仙人打坐)
    如果 获取长度(容器：打坐状态们) == 0：
        结束
    新建【元组<棋子>】变量【分身们】 = 目标选择器(
        类型：元组<棋子>，方式：自动，范围：全图，
        筛选条件：{关系：友方，条件：(棋子) => 棋子.extension.影分身 == true}
    )
    当前棋子.extension.打坐进度 = 当前棋子.extension.打坐进度 - 1 - 获取长度(容器：分身们)
    如果 当前棋子.extension.打坐进度 > 0：
        结束
    新建【玩家】变量【奖励玩家】 = 当前棋子.所属玩家
    当前棋子.extension.打坐进度 = 0
    遍历【打坐状态们】中的每一项【打坐状态】：
        移除状态(状态：打坐状态)
    调整资源(玩家：奖励玩家，资源：行动点，变化量：3，允许超过上限：true)
    调整资源(玩家：奖励玩家，资源：充能点，变化量：1，允许超过上限：true)
```

进度是独立extension字段，不把准备6误写成6层状态。永久打坐可见可驱散；驱散后Rule因无状态不再推进或奖励，重新发动覆盖进度为6。两个Rule独立去重，状态不自动挂卸Rule。保留声明字段归零，避免重复声明/删除破坏类型；不轮询，值和状态变化通知显示。奖励前清进度与状态，防止响应恢复重复结算；移除引发反应不重跑该次奖励。

当前所属玩家回合开始推进，队友回合不推进；友方分身按已确认阵营语义计数，允许同阵营其他玩家分身贡献，不要求分身来自本鸣人。仅在场有效棋子匹配，出局/死亡不算。模板变化不靠名称识别。移动限制只阻止普通移动，不阻止外部传送或冲刺；复用已确定事件分类。

基线直接增加行动点3/充能点1，本草案用正常调整资源模块并显式允许超过上限保留该行为。不存在的旧分身回合末充能、仙人护盾兼容功能不恢复。两项完整作者主体转A；显示配置查看者表达与位移依赖的运行映射必须统一验证，不声称运行兼容。
