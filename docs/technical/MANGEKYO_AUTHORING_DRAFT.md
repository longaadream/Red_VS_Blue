# 万花筒玩家级计数作者代码

来源：origin/main的rule-mangekyo-friendly-death及用户最新决定。用户明确取消场上见证者要求：该局可能出现万花筒技能时，为相关玩家准备玩家级常驻Rule，整局记录友方棋子死亡。此文只为作者草案，未修改运行引擎。

## 对局初始化配置

当玩家选择的技能/Cluster配置声明需要万花筒玩家Rule时，在游戏开始、首个死亡事件和首次费用求值之前，为该玩家执行以下初始化配置。可授予、复制或偷取相关技能的已选内容，也可以声明这种依赖，覆盖之后获得技能的路径。依据是实际选用内容的配置或依赖声明，不是引擎识别万花筒名称/ID，也不是只因整个资源库存在该技能就给所有玩家添加。

```text
新建【数值】变量【玩家.extension.万花筒减免】 = 0
附加规则(
    挂载对象：玩家，规则：万花筒计数Rule，来源：玩家
)
```

此段是对局初始化配置中的作者操作，不是每个技能释放时的code，也不是新增“获得Cluster时”触发器。玩家变量由初始化配置提供。安装清单为每个玩家列出且仅列出一份计数Rule；不依赖通用附加规则自动去重，也不在后续获得每份Skill/Cluster时重复安装。引擎只执行通用的选定内容依赖准备流程，不含万花筒专属判断。具体声明字段和递归依赖展开仍属后续实施工作；可能获得技能的所选配置应声明依赖，不能省略准备却声称已有历史计数。未声明路径在局中临时引入技能的初始化和历史追溯未定，不擅自补历史。

同名同类型extension声明复用现值，重复准备不能将已有计数清0；重复安装本Rule仍是配置错误，不能用变量声明的幂等性冒充Rule安装幂等。新对局初始化为0，读取/恢复同一对局保留已保存计数和Rule，不重放初始化安装或历史死亡。字段先声明再展示费用，不静默补缺字段或默认取0。

## 玩家级常驻Rule

```text
Rule：万花筒计数
挂载对象：玩家
来源：该玩家
触发器：己方.死亡前

code：
    来源.extension.万花筒减免 = 来源.extension.万花筒减免 + 1
```

己方按来源玩家的阵营判定，包含自己的棋子、同阵营队友棋子及召唤物。每个已确定的友方死亡事件使该玩家计数加1；敌方死亡和出局不计。各玩家分别保存计数，同阵营两名玩家均有计数Rule时，各自加1，不共用一个阵营计数器，也不把全局计数新增为玩家资源。

采用死亡前保留旧onPieceDied的离场前时点，此Rule不取消或阻止死亡。死亡前/死亡后沿用公共死亡生命周期，撤销的死亡不能记为已确定死亡。玩家Rule不依赖任何见证棋子：带土/佐助不在场、死亡、出局、隐藏万花筒标签移除或技能Cluster移除，都不停止玩家计数。计数Rule不作为每份棋子技能Cluster的挂载成员；Cluster可以声明对该玩家准备数据的依赖。

只有一份玩家监听Rule，所以删除旧草案的当前事件.extension.万花筒已记录玩家及见证者排序。一次死亡只派发/提交一次本Rule；连续、嵌套死亡分别计数，回放或挂起恢复不能重复提交已执行语句。这是公共调度需要验证的不变量，不在技能code里补事件去重开关。

## 使用该数据的费用

```text
神威.充能点消耗 = 最大值(0, 3 - 当前棋子.所属玩家.extension.万花筒减免)
须佐能乎.充能点消耗 = 最大值(0, 2 - 当前棋子.所属玩家.extension.万花筒减免)
```

这些是Skill元数据表达式，不修改共享Skill定义，也不直接添加或扣减玩家CP。减免计数不消耗，可超过基础费用；只有最终费用最低为0。后来获得技能能使用该玩家此前累计计数。技能转移到其他玩家时读取新所属玩家的计数，不复制原玩家extension、不重置任何一方计数。

同一引擎计算用于显示、可用性和最终支付。计数真实变化由权威状态通知相关费用缓存失效，只更新相关可见或正在使用入口；首次展示、准备使用、最终确认按公共费用合同求值，无轮询。Rule只改权威数据，不直接调用React。具体依赖追踪与渲染性能尚未实现验证。

## 与基线的差异及验证边界

基线要求当前玩家有隐藏万花筒标签见证者，并按实例ID只让首个见证Rule记录。新设计明确取消见证资格和在场条件，这是用户指定的行为变化，不宣称保持旧限制。旧棋子见证Rule必须停止执行，不能与新玩家Rule并行导致重复计数；隐藏StatusTag如为显示兼容保留，也不再控制计数资格。
