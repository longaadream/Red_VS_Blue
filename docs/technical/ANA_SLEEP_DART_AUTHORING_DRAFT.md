## 受伤解除全部可见睡眠：已确认

基线sleep-remove仅splice第一个睡眠实例，随后删除所有睡眠控制Rule/内部Skill；新框架Rule独立且每次执行检查状态，不能照搬删除全部控制规则导致仍有睡眠却能行动。普通叠加允许不同强度与时长组合保留多个状态实例，因此这不是只有一种状态的假问题。

用户确认受实际伤害后解除全部可见睡眠实例，而不是只移除第一份。可以用既有获取状态返回元组及遍历移除状态，无需新增模块；伤害被挡无受到伤害后事件，因而不唤醒。此数量行为已确认，完整唤醒Rule为：

```text
Rule：睡眠受伤解除
触发器：当前棋子.受到伤害后
code：
    新建【元组<StatusTag>】变量【睡眠状态】 = 获取状态(
        目标：当前棋子，类型：睡眠
    )
    遍历【睡眠状态】中的每一项【状态】：
        移除状态(状态：状态)
```

只移除睡眠，不移除定身/其他状态或别的技能；控制Rule在无状态时无效，不与状态自动绑定。完整作者code已补。运行测试未执行，旧状态/Rule清理缺陷只静态记录，未修改引擎。

阻断Rule只需判断是否存在任何睡眠，故用获取状态返回元组及获取长度，不依赖尚未定稿的多实例状态强度聚合。解除时逐个移除现有实例，只有可见状态可被移除，遵守现有移除语义；睡眠定义本身可见。一次受伤清空所有睡眠后，重复唤醒响应查得空元组，不再重复移除。所有睡眠阻断Rule仍独立，不删除其他技能/规则。
