# RED-252：统一玩法模块说明书草案

状态：用户已确认模块化原则。PR #240 已开始实现 `rvb-gameplay-modules/v1` 作者层、注册表、编译与编辑器；下列完整领域目录仍包含待迁移能力，不能把部分实现当作全量完成。原 v1 内容图继续承担兼容性基础。

## 已落地的执行边界

- `lib/skill-graph/module-types.ts` 定义类型端口、参数、入口权限和副作用声明。作者图只包含模块调用、条件、集合迭代、返回及显式数据引用。
- `module-compiler.ts` 校验已注册 ID/版本、端口、参数和组合图，再展开组合模块，生成原 SkillCode 宿主接受的代码。这里没有第二套伤害、状态或位移规则解释器。
- `module-registry.ts` 提供原子能力及不含原生实现的编辑器目录。修改或扩展原子能力仍属于代码开发，不能由内容文件提交一段源码来登记。
- `module-document.ts` 将作者图保存在 `gameplayModules.entries[字段]`，并校验生成字段与图一致。模块拥有的字段不能通过编辑器保存时删除元数据而变回自由脚本；旧内容仍允许逐批迁移。
- 技能、卡牌、规则加载校验模块声明；保存入口校验原有字段归属。公开预览移除作者图元数据。
- `electron-editor/ui/gameplay-module-editor.js` 使用同一注册目录生成参数及输入控件，并提供组合模块的进入、返回和子流程编辑。JSON 是存储格式，生成代码不是第二个作者来源。

此实现不表示原有全部内容已改用新模块。兼容图与语义模块的覆盖数量分开报告，动态生成内容、pending 子图及复杂状态记录仍必须逐项验证闭合性。原文字段保持不变；完整自然语言模板绑定仍不能由模块目录本身推导为已完成。

## 目标与范围

卡牌、技能、状态附带效果、地格效果、触发规则、生成内容和等待选择后的执行，全部通过同一套模块体系表达。复杂功能必须能展开成模块组合。以后新增内容只组合模块；缺少通用底层能力时，先新增并验证原子模块，再供内容使用。

本轮只迁移当前普通对局已有行为。冒险内容及讨论中尚未落地的新规则不在范围内。原有 UI、动画、日志、语言、目标选择、随机调用、结算顺序和数值仍以冻结基线为准。

模块化不意味着编辑者可以任意改写游戏状态。非法组合必须明确报错，不能悄悄转为脚本执行或忽略效果。

## 三种定义

### 技能 Cluster（2026-10-10 用户确认）

编辑器以技能 Cluster 作为完整能力的操作单位，同时覆盖主动技能和被动技能。Cluster 汇聚 Skill、StatusTag、Rule、续接与表现配置，内部仍可展开成模块；不是把旧执行代码包装成一个不可展开节点。普通编辑展示中文效果与条件，高级选项保留类型、接口、引用和完整流程。

2026-10-12 用户纠正：Skill 是主动技能，不能与 Cluster 画等号。技能菜单展开的单位为 Cluster，其成员允许为 Skill、Rule、StatusTag、Card 相关内容与 extension；被动能力可以由 Rule 作为作者入口，不要求附带主动 Skill。状态通过所属 Cluster 编辑，不单独设置顶层状态目录。历史被动 Skill 文件继续保留原存储/执行兼容，但不能据此把新的被动能力设计为虚构的主动入口。作者目录扩展不增加运行调度或重复注册规则。

Cluster 是作者层的版本化关联定义，不是新的战斗调度器。既有 Skill 入口、被动特征、棋子常驻 Rule 和状态关联 Rule 继续经过原有权威生命周期；仅因同一 Rule 在多个 Cluster 中可见，不能重复注册或执行。

必须区分三类关联：技能自身定义、明确共享的依赖、仅用于理解技能的相关内容。棋子上的常驻 Rule 不得凭名称相似自动归属某个 Skill；来源未确定时保留显式独立被动能力或待核对项，不得在复制技能时默认携带。动态生成的状态与规则须记录来源及生成流程，不能只汇聚磁盘独立文件。

运行时需要区分能力定义、持有实例和已经产生的效果实例。复制、偷取、替换等未来操作以 Cluster 为边界，但不会据此默认复制或转移既有召唤物、状态和延迟效果。复制／偷取的冷却、次数、归属与清理语义尚未商定，本次兼容迁移不新增这些行为，也不改变存档格式。

验收分别报告 Cluster 归组覆盖、可展开语义模块覆盖与编辑器操作覆盖。只有归组不代表全部可视化完成；旧兼容图入口必须继续标为待迁移。保留原技能 ID、执行代码、文案、目标协议、动画和日志，使用迁移前后差分验证没有功能变化。

| 定义 | 能包含什么 | 不能包含什么 |
| --- | --- | --- |
| 原子模块 | 注册的宿主能力；稳定 ID 和版本；具名的类型端口；参数、权限、时机、副作用及失败契约 | 以具体技能名包装整段玩法逻辑；开放任意对象路径、函数或源码参数 |
| 组合模块 | 对已注册模块的调用、数据与流程连接、声明过的局部记录、显式子流程 | 隐藏脚本、原生回调、动态方法名、直接修改战斗对象 |
| 内容定义 | 模块图的入口、参数绑定、模块引用、原有数值和文案 | 自己另写一套规则实现；以“特殊技能”绕过模块校验 |

“双尾飞行”可以是方便复用的组合模块，但展开后必须能看到选择、记录、状态、计时、位置检查、传送和清理。“执行双尾飞行代码”不允许登记成原子模块。

原子模块内部仍需要程序代码，执行现有宿主提供的规则。拆分的边界不是每一行 TypeScript，而是能独立说明、独立校验、独立测试且可复用的规则能力。原生模块不得按卡牌/技能 ID 分支承载整段专属玩法。

## 作者层与执行层

作者层：内容定义 → 组合模块展开 → 原子模块与类型校验。

执行层：已校验的模块图 → 编译中间表示 → 现有权威引擎 → 原有状态、日志、表现事件及 UI。

v1 的 `bind/set/invoke/function/source` 等可以保留在编译器内部，但不能继续作为设计者实现效果的出口。它们被编译器生成不等于允许作者自行填写。可编辑文档必须与生成产物绑定；不匹配时拒绝保存或构建。

本轮不改变旧资源包的信任和签名策略（ADR-0033），不声称旧脚本资源自动满足模块要求。旧脚本兼容入口与完成模块化的内容必须明确区分，不能用兼容入口完成新内容的验收。

具体迁移决定：

- 新作者层注册表归公共 `lib/skill-graph` 模块所有，编辑器和编译器共同使用；它不等于直接重命名现有 `CONTENT_GRAPH_CAPABILITIES`。
- 不新增战斗解释器或状态源；模块通过编译适配调用现有权威宿主。v1 仅供内部 lowering 和旧资源分析，不能作为模块图的任意子节点输入。
- 已转为模块定义的内容不再提供“解除关联后继续编辑执行代码”的作者出口；保存、构建与载入检查声明类型、版本和产物一致性。迁移中的旧内容明确标为 legacy，最终普通对局完成门槛要求这一范围内的 legacy 为零。
- 原子能力返回类型化值或不透明句柄，选择续接保存模块引用及绑定；如旧宿主必须使用代码字段，由编译器单向生成。不得直接改变现有对局存档格式或资源信任策略。
- `skillcode-runtime/abi-v1.ts` 是可参考的受限能力资料，不自动取代现役执行器；它与当前允许能力的差异须逐项核实。

## 每个模块的统一登记信息

| 字段 | 要解决的问题 |
| --- | --- |
| `id`、`version`、名称、说明 | 精确引用模块；固定行为版本；编辑器可检索 |
| 输入、输出及数据类型 | 哪些对象可以连接；可空、集合、单位和数值范围是什么 |
| 参数结构及默认值 | 编辑器生成数字框、枚举、对象选择器、列表与资源引用控件 |
| 执行入口与权限 | 主动技能、卡牌、触发规则、选择续接、预览能否调用 |
| 流程出口 | 成功、无效目标、取消、失败、等待分别如何衔接 |
| 副作用 | 改动哪些领域；是否消耗随机数；产生哪些原有事件与日志 |
| 时机与批次 | 创建时还是结算时取值；顺序、批次或位置整组提交 |
| 引用与生命周期 | 来源离场、目标失效、所属玩家变化、到期清理如何处理 |
| 参数术语与文案绑定 | 同一个“范围”“数量”“持续时间”不在三个地方各写一遍 |
| 验证与示例 | 正常、拒绝、失效、恢复和重放场景 |

数据端口至少区分数字、布尔、文本、棋子引用、玩家引用、地格、路径、卡牌实例、内容定义引用、状态实例、事件事实、选择结果与记录句柄。集合携带元素类型。实体引用是不透明身份，不能被当作可变 JS 对象。

读取属性使用已登记的属性枚举；修改规则状态使用相应模块。局部计算和有版本结构的模块私有记录不等于允许读写 `G.extensions` 的任意路径。过滤器、公式和排序条件也必须由纯模块组合，不能输入 JavaScript 回调。

## 模块目录第一版

以下是职责分组，不是“一类只做一个万能节点”。每个分号隔开的能力都需要单独明确输入输出及副作用；名字仍可随实现调整。

| 分组 | 通用能力 | 关键边界 |
| --- | --- | --- |
| 上下文与引用 | 获取施放者、持有者、来源、目标、当前玩家、事件玩家；解析/验证引用 | 不暴露整个 `G` 或 `context`；引擎传播失效引用，作者无需连接防御分支，独立后续继续 |
| 查询 | 查找棋子/玩家/卡牌/状态；枚举集合；读取登记字段与占位事实 | 返回引用或只读事实，不返回可写对象；敌我关系由阵营字段与普通比较组合 |
| 数值与条件 | 常量、读属性、四则运算、比较、与/或/非、向下取整、范围限制 | 具名类型端口；保留原运算顺序，不能因优化改变结果 |
| 集合与顺序 | 筛选、映射、稳定排序、数量、首项、去重、逐项执行 | 子流程仍是模块图；保留基线遍历顺序 |
| 随机 | 种子随机数、按原规则选择候选、按原规则排列 | 明确随机调用次数与顺序，不偷换算法或空集合行为 |
| 玩家选择 | 选择棋子、地格、方向/路径、选项；确认、取消、等待及继续 | 使用现有权威 pending 协议；候选、提示与执行来自同一选择定义 |
| 流程 | 顺序、分支、有限重复、调用组合模块、返回结果 | 显式控制流；组合调用环必须拒绝或经专门的有界循环表达 |
| 伤害与治疗 | 请求伤害/治疗；读取实际结果；规则阶段提交后续请求 | 复用原调度器；不得用“减生命”旁路替代伤害生命周期 |
| 事件与反应 | 注册原有事件处理图；读取事件事实；受限改写或阻挡当前事件 | 改写字段按事件类型登记；不能任意触发事件或改写历史事实 |
| 状态与附着规则 | 创建、查找、添加、移除、调整状态；附加/移除关联规则 | 圣盾、护盾等表现为状态与规则组合；不新增专属内置捷径 |
| 属性与资源 | 读取/调整攻击、防御等已登记属性；调整行动点、充能 | 明确加法、比例、设值等不同语义；不能把任意字段名当参数 |
| 技能配置 | 添加、移除、替换技能；读取/调整冷却和使用次数 | 保留当前重置语义与持有者生命周期；不直接改数组对象 |
| 位置与路径 | 查询路径/落点、检查落点；走格、冲刺、传送、换位/整组位置提交 | 使用唯一位置提交器；路径接触和触发时机遵守 ADR-0034 |
| 生命周期 | 召唤请求、死亡处理请求、原有复活流程、原有强制移除 | 核心/召唤身份显式数据；不得用删除数组模拟死亡 |
| 卡牌与区域 | 查询手牌、加入、移动/弃置、使用已有定义、生成实例 | 不引入“抽牌”新概念；保留现有容量、费用、弃牌和使用事件 |
| 内容生成 | 选择模板、绑定类型参数、组合效果图、实例化卡牌/技能 | 生成的是定义引用、模块图与绑定，不是可编辑源码字符串 |
| 地形与地格附着 | 查询地形、改变地形、创建/清理地格效果、查询占位与落点标记 | 地形和附着效果分别处理；不私自改变两者联动 |
| 记录与时间 | 创建/读取/更新有结构的记录；计数；监听指定回合时点；取消/到期清理 | 参数明确所有者与创建时/结算时取值；不直接追加隐藏自定义状态字段 |
| 批次与协调 | 构造既有伤害/治疗/召唤/死亡批次；提交原有整组位置请求 | 不能建立“任意效果同时执行”万能模块；四类批次遵守 ADR-0022 |
| 描述、预览与结果 | 绑定原消息模板、参数和术语；生成模块预览；沿用统一表现事件 | 预览无副作用；不创建第二份规则；不为每个模块另造动画系统 |

伤害、死亡和位置提交的宿主事务拥有既定生命周期。内容通过这些模块提交请求和订阅允许的阶段，不自行重排内部提交顺序。未来若开放更多内部阶段，也需要登记为通用模块、明确可组合条件和不变量，不能用“高级代码”绕过。

2026-10-12 作者验收纠正：不能把“先读取存活，再执行效果”当作所有技能必须编写的模板。需要存活棋子输入的原生接口以可信描述符 `livingReferences` 声明该要求，编译器在运行边界验证并产生无效依赖；作者不能覆盖这项元数据，也不需要另加 `piece.alive`。失效条件不会被当成普通 `false` 而执行另一分支，独立后续仍可运行。明确以存活情况选择不同玩法结果时，存活查询本身仍是合法功能。

最新作者边界（2026-10-12）：可以用字段与基础表达式组成的判断，不再注册成面向作者的独立玩法函数。敌我判断使用 `当前棋子.阵营 == 目标.阵营` 或 `!=`；本玩家判断使用所属玩家引用的相等比较。飞雷神读取棋子阵营，回溯读取事件玩家和记录所属玩家的阵营，随后都使用普通文本相等/不等运算。

棋子字段复用 `attribute.text@2`（名称、阵营），玩家字段使用 `attribute.player-text@1`，不新增“是敌人”“是队友”谓词。棋子字段读取在引擎边界要求存活，失效继续传播；玩家字段不依赖原棋子存活。作者的“阵营”表示现有权威队伍身份，来自对局队伍及归属规则，不能把内容善恶阵营或不同玩家 ID 当成敌我关系。

上一轮新增的 `query.same-relation@2` 与旧 `@1`、`compare.allied-players` 均退出正常和高级新增目录，仅供历史图读取。旧字段读取和死亡事件语义保留，不全局改写 `hasPiece`、状态来源或历史位置读取。本轮不据此宣称其他历史图已全部改成字段表达式。

## 复杂模块必须如何表达

下列分解同时保留早期兼容迁移记录，其中双尾飞行、图拉扬和连续攻击示例仍提到显式存活或落点复检。它们不能作为最新版作者模板的要求：纯引用失效和操作合法性应由引擎处理，作者只声明玩法条件。2026-10-12 本轮已落实四类原子样例中的存活保护清理；其他历史图须另行核验，不能据此报告全仓库已完成。

### 延迟双人传送（双尾飞行）

主入口：选择其他友军 → 选择两个合法相邻落点 → 建立本次效果记录并保存双方及落点 → 创建落点标记 → 为双方添加原有状态 → 返回原消息。

回合结束入口：读取对应记录 → 按当前基线推进计数 → 到期时重新解析双方及落点 → 检查占位、存活和落点合法性 → 按原顺序分别请求两名棋子传送或进入对应取消分支 → 清理本次标记、状态与记录。

用户于 2026-10-10 确认保留现有规则：到期分别检查并提交两名棋子的传送，一个落点失效不阻止另一名棋子成功；两次提交及其反应保持原有顺序。标记不能被新模块误实现为禁止其他棋子进入的占位锁。选择范围、两个落点邻接、倒计时与状态期限必须来自现有内容，不能照示意图重新发明数值。

### 动态卡牌/技能组合

选择效果片段 → 按类型规则组合成图 → 绑定创建时参数 → 生成内容定义或实例 → 加入原有手牌/技能入口。

使用时：读取实例绑定 → 执行组合图 → 通过原有资源、目标、效果和结果模块结算。

“效果片段”本身可展开。加强效果通过明确的可调整参数端口；若原内容有旧兼容差异，必须显式登记映射和验证，不能对编译后的 JavaScript 字符串做替换。不能为塔尔斯或拉法姆保留私有代码生成器作为最终作者接口。

### 等待玩家选择后继续

主图到达选择模块时，声明候选、提示、玩家、取消规则，以及继续图与需要保存的类型化绑定。恢复只凭原有权威选择事务推进继续图；校验过期、重复、错误玩家及失效目标。

继续图可以再进入选择模块，但不得附带任意 `effectCode` 字符串。当前宿主如仍需要源码字段，由编译适配器生成并维护兼容，作者层不接触该字段。已有旧对局的恢复边界仍由原协议保证，不在此迁移中变更存档格式。

图拉扬的实际分解：选择 1–3 个存活友方核心棋子 → 保存引用 → 恢复时重新验证 → 查询范围内合法中心格 → 选择中心 → 计算中心与上下左右的编队落点 → 重新验证占位 → 现有整组位置提交 → 为每名棋子附加圣盾状态及对应规则。编队形状是偏移列表与地格查询/过滤的组合，不登记一个图拉扬专属执行器。

水门的锚点流程使用“有序标记集合”组合：查询/消耗标记 → 查找范围内敌军 → 按原随机调用选择 → 查询相邻落点 → 传送和伤害 → 调整原印记 → 等待选择新标记地格 → 插入记录与地格标记 → 超过原数量上限时移除最早记录及标记。不会新增一个只能服务水门的 `executeMinato` 原子模块。

### 已核实的宿主落点

| 原子模块领域 | 当前权威实现 | 适配时不能遗漏 |
| --- | --- | --- |
| 状态及关联规则 | `lib/game/status-lifecycle.ts` | 叠加、到期、清理与原有事件，不能简单 push/splice 状态数组 |
| 位移及整组落点 | `lib/game/position-change.ts`、`lib/game/spatial.ts` | 统一验证/提交、位置事件与接触，不能直接写 x/y |
| 伤害及事件阶段 | `lib/game/skills.ts`、`lib/game/triggers.ts` | 原始调用时机、拦截与队列、伤害来源、日志和表现 |
| 玩家选择及续接 | `lib/game/targeting.ts`、`lib/game/turn.ts` | 版本/玩家/重复输入检查、取消、恢复和重放 |
| 通用能力适配 | `lib/game/flow-runtime.ts` | 复用能力但收窄可变对象与任意记录路径 |

原先 3 个生成家族与 2 个 pending 字段的证明保留用于新旧执行对照。比如拉法姆的复制目前包含 JSON 克隆和 ID 更新，新的实现必须保留对应绑定及完整效果图；塔尔斯护甲的六种片段要分别表达属性/状态/规则能力。不能只证明生成卡首次加入手牌成功，必须继续验证它实际使用或触发后的效果。

## 三者统一的具体含义

模块定义提供参数结构、类型、名称、术语、合法性与执行适配；编辑器据此生成控件，编译器据此校验并生成执行，描述绑定读取同一组参数。

内容保留原有文字模板与句式。初期只做可验证的参数绑定和一致性检查，不宣称可以从任意组合自动生成自然语言。公式和复杂条件本身也以模块图编辑，不能在文字框中藏代码。

已实现的文字绑定位于 `gameplayModules.textBindings`，支持 `description` 与 `targetText`。模板使用 `{{amount}}` 这样的占位符，每个占位符显式引用一个执行入口的静态根输入，或唯一节点的字面量输入/参数；值必须是数字、文本或布尔值。修改图参数时，共享文档适配器重新生成文字并检查保存内容，删除仍被文字使用的输入会报错。不能引用任意状态路径、运行中节点输出或执行表达式。幸运币已将行动点增量、执行日志和描述绑定到同一数值输入，并用实际技能宿主验证改为 3 点时三者一起变化。

旧内容已明确声明 `targeting.steps` 时，实际编辑开头目标节点可建立 `gameplayModules.targetBindings`（`rvb-gameplay-target-binding/v1`）。绑定记录入口、唯一节点标识、选择步骤和目标序号；只有原图与原声明的对应约束一致，才同步范围、筛选和地格约束。选项前缀、距离算法和其他额外限制保持原值。保存/加载时校验绑定与图、声明一致。未修改目标的旧内容不被自动修复或新增绑定；没有旧声明的图继续使用既有图目标准备机制。

范围说明仅在旧 `targetText` 的范围 token 唯一、描述中的对应片段唯一时自动建立文字绑定；同源的字面量预览一起重新编译。自定义或歧义文案保留，并在编辑器显示提醒，合法图仍可保存；不得用全局数字替换猜测文本。已有文字绑定继续保留，包括其他根输入。筛选或地格约束变更无法由现有模板表达时同样提醒检查说明。影分身范围从 5 改 6 的回归检查实际 `prepareAction` 候选，不只检查图保存成功。

普通伤害的作者类型仍为 `normal`。旧内容日志中使用的“物理”或“法术”字样通过兼容参数保留，以维持本次迁移的既有事件与日志；此参数不建立两套防御计算或新的伤害分类。

迁移原 `dealDamage` 调用时，伤害模块明确使用 `inputPolicy: host`，将原始有限数值交给权威流程。取整仍由原阶段处理，不能提前到 `beforeDamageDealt` 之前；例如原始 10.5 点经暴怒翻倍应先得到 21，再由宿主结算。该策略也不提前将负数截成零，负伤害仍按原宿主校验拒绝。既有 flow 调用省略策略时保持原行为。

### 结算来源与有效目标

目标棋子引用仍在每个使用节点检查有效性。已开始的多段效果如果按原规则不要求施放者继续在场，可在有效时使用 `source.capture` 保留本次执行的来源，再由 `effect.damage-many-captured` / `effect.heal-many-captured` 继续结算。圣光降临依次结算各圈时采用此方式：第一圈反应移除施放者，不会漏掉后续圈。

来源句柄由当前执行的 WeakMap 持有，不写入战斗状态、不跨保存或等待恢复使用，不允许伪造或借用另一次执行的句柄。它不使离场棋子重新有效，也不授权其移动、恢复生命或使用新技能。除伤害/治疗归属外，兼容已经开始的恶魔仪式时，可完成原对象的攻击/防御/移动范围属性记账、读取名称，并使用原来源 ID 提交既有召唤队列；这些操作不重新插入棋子，也不跳过宿主召唤验证。玩家归属、名称等明确的创建时事实可提前读取；不得因为之后棋子离场而无故取消不依赖该棋子的玩家资源效果。

死亡事件可能在棋子进入墓地后才执行。`source.capture-event-piece` 只能保留当前事件中 `sourcePiece`、`targetPiece`、`piece` 或 `rulePiece` 的既有对象；不提供按任意墓地 ID 寻址的能力。反击意志和裂魂使用这些事件引用，保留死亡来源归属与名称。需要伤害结算时仍调用权威伤害宿主，不能通过句柄直接执行死亡、复活或位置写入。

### 执行内累计值

`local.counter-create`、`local.counter-add`、`local.counter-read` 用于逐次循环中累计伤害、治疗与命中次数。计数器属于当前执行的 WeakMap，有限数值检查在写入前完成，不进入对局状态、存档或全局变量。复制句柄、跨执行复用均拒绝。需要跨选择阶段保存累计值时，应读取数字并写入声明过的 continuation payload，不能保存计数器句柄。埃德加双击治疗和普里莫连续挥拳由循环、存活检查、伤害、治疗与计数器组合，分别保留原技能对施放者离场的不同处理。

玩家既有计数兼容访问仅接受已登记的 `contentCounters` 与 `contentCounters.elPrimoChargeDiscount` 路径，并验证玩家、键名和有限数值；不是通用对象路径读写接口。

### 多阶段选择与事务恢复

`defer-choice` 的标题、候选、人数上下限、消息和取消后继续标记均为有类型的数据，续接代码只能由已登记的 continuation 图生成。触发器与待选择入口统一接收生成的选择结果；候选、payload、来源和取消策略必须在聚合结果及下一阶段保留。

事务回放执行规则起始图一次，再按已记录回答逐阶段执行生成的续接图。不得在拿到回答后反复重新启动起始图而重复结算或再次弹出同一选择。仍使用旧式回答上下文的规则保留原恢复路径。实际落点验证、费用、状态提交与失败回滚继续由现有权威操作事务负责。

### 状态与事件写入边界

常规状态操作走既有生命周期。迁移原本直接修改状态数组的内容时，使用显式的记录追加/移除兼容模块，保持原先不发事件、不自动清理关联能力的行为；不能将这种兼容语义暗藏在普通驱散模块中。通用状态数值 setter 只接受 stacks、intensity、value；持续时间与次数通过专用生命周期或兼容计数模块处理。

事件改写除了检查 before 阶段，还校验具体字段归属：damage 只在伤害结算前事件，heal 只在治疗结算前事件，落点坐标只在移动、技能使用或位置变化的前置事件。没有登记字段权限的事件拒绝写入。无事件的生命恢复入口拒绝把生命设为零或使死亡棋子复活，死亡与复活仍必须使用对应的权威流程。

预览使用同一选择、公式和查询定义，只输出原有预览投影；禁止重复消耗随机或执行真实效果。动画继续消费原引擎的统一表现事件。

## 早期差距与迁移顺序（历史记录）

1. 先登记原子模块、类型、状态结构和组合图规则，再建立递归展开与权限校验。现有 v1 编译器作为内部后端保留。

4. 编辑器提供模块选择、类型端口、结构化参数、组合模块进入/返回及跨层定位。JSON 只保留为存储和调试视图。

6. 模块覆盖、行为等价、编辑器可操作三项分别验收，全部通过后才能将任务重新转为待验收。

原有 276/276 与 360/360 是 v1 编译图覆盖；语义模块覆盖目前尚未审计完成。现有生成/续接家族的源码证明也只证明兼容，不证明上面的模块化实现。

## 语义依赖与生成内容证明补充（RED-252）

Cluster 在校验作者图与编译源完全一致后，追踪模块图中的 Rule 应用及实际传入 `status.apply-record` / `status.apply-player-record` 的状态记录。未使用的记录不计为状态；续接图独立解析局部记录，避免同名节点跨图混淆。计算生成的状态在 Cluster 中只读展示，修改仍进入所属技能图。

事件来源句柄只能引用本次事件或已捕获的棋子；可读取稳定标识、所属玩家、封闭数值字段和状态类型，不提供任意对象路径。事件中的对象已离场时仍按原规则处理，不自动重新插入棋盘。例如寒冰坚忍反冻允许已离场的受击者完成当前事件，但造成伤害的目标必须仍在棋盘且存活。

覆盖审计对已登记的动态内容迁移独立重建作者图和编译源，逐字匹配当前产物后才能沿冻结源验证候选集合；报告同时记录当前源码哈希和冻结来源哈希。护甲组装的六种卡牌模板分别校验实际模板图和编译源，不能仅凭父技能成功编译计为生成内容完成。Pending 的 `defer-choice` 与实际 continuation 子图单独记录，不计成旧源字符串节点。

## 表现批次与状态关联字段（RED-252）

`foreach.presentation` 可选值为 `statusAdded`、`statusRemoved`、`tileEffectAdded`、`tileEffectRemoved`。当前仅主动技能 `skill` 入口可用，编译为既有 `context.presentationQueue.push` 作用域；其中各项效果仍按原顺序执行，只为匹配的表现事实保留同一批次。未指定时保持原有逐项行为。纯集合计算、预览入口、作用域内跳出返回或挂起选择、直接或跨组合模块的嵌套批次被拒绝，不能利用回调改变作者图控制流。

`status.replace-related-rules` 只替换首个匹配状态（同时匹配 ID 与类型）的关联规则列表，不安装或移除规则。安装和移除继续使用独立规则模块。该显式操作用于保留原内容的字段替换语义，避免状态叠加时自动合并列表导致后续清理变化。
