# 血肉再生作者代码

基线muzan-flesh-regeneration、rule-muzan-regeneration-damage和rule-muzan-regeneration-end。被动，AP0/CP0/CD0；每局最多实际成功恢复3次，不是最多触发检查3次。治疗结果与实际恢复量已获用户确认，此为完整作者草案，未修改运行引擎。

## 基线核查

每个全局回合结束，棋子存活且已受伤、当前回合未损失实际生命，尝试恢复2。回合标记为battle.turn.turnNumber，包含双方/所有玩家回合，不是仅所属玩家回合。afterDamageTaken只记录实际正生命损失；伤害被挡不记录。旧代码另扫描权威damage actions作为漏事件的兜底，新框架应由权威伤害事件保证记录完备，不让技能轮询/扫描日志成为第二套事实来源。

旧endTurn代码记录lastCheckTurn防同回合重复，再检查损伤回合及成功次数；heal结果blocked或heal<=0不增加成功次数。恢复满血差1时恢复1，也属于成功恢复并消耗1次；自身满血不尝试、不消耗。本局累计成功恢复3次后停止。

## 可表达部分

Cluster包含被动Skill、实际受伤记录Rule和全场回合结束Rule。每份Cluster的extension声明成功恢复次数=0和最近受伤回合=-1，重复声明复用现值；不同棋子/不同技能实例不共用一个计数，复制/寄生获得的新组合按对应实例初始化，不能按技能名称覆盖所有实例。使用当前回合.编号，不维护自己的全局回合计数。

```text
Rule：血肉再生·受伤记录
触发器：当前棋子.受到伤害后

code：
    新建【数值】变量【当前规则.所属Cluster.extension.最近受伤回合】 = -1
    当前规则.所属Cluster.extension.最近受伤回合 = 当前回合.编号
```

此Rule使用引擎仅实际正伤害才派发的事件，不再写伤害量>0。若未来有直接非伤害生命扣除，本例的记录入口应按当时对应权威生命损失事件扩展，不自行把本轮afterDamageTaken泛化成尚未讨论的全部生命变化事件。

## 完整结算代码

```text
Rule：血肉再生·回合结束
触发器：全场.回合结束

code：
    新建【数值】变量【当前规则.所属Cluster.extension.最近受伤回合】 = -1
    新建【数值】变量【当前规则.所属Cluster.extension.成功恢复次数】 = 0
    如果 当前棋子.当前生命值 <= 0 或 当前棋子.当前生命值 >= 当前棋子.最大生命值：
        结束
    如果 当前规则.所属Cluster.extension.最近受伤回合 == 当前回合.编号：
        结束
    如果 当前规则.所属Cluster.extension.成功恢复次数 >= 3：
        结束

    新建【治疗结果】变量【结果】 = 恢复生命(
        目标：当前棋子，数值：2，来源：当前棋子
    )
    如果 结果.实际恢复量 > 0：
        当前规则.所属Cluster.extension.成功恢复次数 =
            当前规则.所属Cluster.extension.成功恢复次数 + 1
```

治疗结果/实际恢复量已列入正式作者接口，运行结果映射尚未修改。UI剩余次数从本Cluster的成功恢复次数计算，不与引擎另一个自动扣次机制重复消费；精确被动剩余次数显示适配尚待实施。公共回合结束派发需一次提交/挂起恢复防重复；不以删除旧lastCheckTurn保证为由允许一回合多次回血。

不使用治疗前后生命差，避免其他反应伤害/治疗污染本次结果。恢复生命被阻挡或无实际增加返回实际恢复量0；目标非法仍语句失效。集合治疗结果结构不为本例扩展。正式接口和本页代码状态已经同步，运行实现与对应测试仍待进行。
