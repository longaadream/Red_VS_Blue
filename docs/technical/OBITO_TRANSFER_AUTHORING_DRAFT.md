# 神威·转移作者代码

基线obito-ally-teleport，AP1、CP0、CD3、不限次数。作者组合草案，未修改引擎。复用目标选择与位移接口，不注册专用带土传送节点。

```text
技能：神威·转移
触发器：使用技能
行动点消耗：1
充能点消耗：0
冷却：3
每局使用次数：不限

code：
    新建【棋子】变量【友军】 = 目标选择器(
        类型：棋子，中心：当前棋子.位置，范围：7，
        筛选条件：{
            关系：友方，排除当前棋子：true，
            不具有状态：{禁锢，不可操作}
        }
    )
    新建【地格】变量【落点】 = 目标选择器(
        类型：地格，中心：当前棋子.位置，范围：7，
        筛选条件：{可行走：true，被占用：false}
    )
    位移(
        棋子：友军，起点：友军.位置，终点：落点，
        敌军可通过性：false，友军可通过性：false，
        不可通行地格可通过性：false，中间地格是否经过：false
    )
```

两个范围都以带土位置为中心，不把第二次选择改成友军位置；友军按战斗阵营，不仅本玩家。禁锢/imprisoned与不可操作/inoperable按统一定义引用映射，保留基线targeting.forbiddenTargetStatuses；排除当前棋子字段对应excludeSourcePiece，不扩展为只允许核心棋子。落点为空且可行走，目标选择器本身不允许空放。

位移走权威提交，中间地格不经过，沿途障碍不影响传送；通行参数不豁免落脚条件。非法初始选择在释放前拒绝并提示，不消耗费用。后续独立位移效果被Rule阻止时，按已确认的新框架只取消该效果，不写技能级失败fallback；基线技能code原来在teleport返回失败后返回success:false，此返回与用户新统一效果失败语义不同，迁移须记录并验证CP/AP/CD提交边界，不假装与旧返回完全一致。目标引用失效时位移语句跳过。

位置改变与单个落点接触由通用位移引擎产生，不伪装成普通移动。没有技能专属动画；日志保留发起者、被移动友军、目标落点与阻止原因。字段显示名、选择高亮、两阶段取消与重试、状态限制和已失效目标提示在实施时核对，当前只做作者文档格式检查，未运行游戏测试。
