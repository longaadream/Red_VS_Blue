# RED-196 官方账号与 1v1 排位

本任务对应用户2026-09-08确认的新增运营方案：官方Colyseus运行并裁定排位，P2P及玩家主机转发房间仍属休闲、不计排位分；2v2仍是休闲和活动。此前去中心化账号/排位讨论作废。本文件描述RED-193 RC2之后的独立功能，不改变RC2历史验收。

## 玩家与组织者分别运行什么

- 玩家：完整解压 Windows-x64 玩家包，打开 `Red-vs-Blue/RED vs BLUE.exe`，主菜单选择“联机大厅”。默认浏览当前服务器房间；左侧切换“官方排位”或“服务器”。普通玩家不用配置SMTP。
- 组织者：完整解压 Official-Server-Windows-x64 包，按下一节启动官方账号与排位服务器。Relay.zip 是独立的休闲转发服务，沿用[休闲试玩说明](RED-193-FIRST-PLAYTEST.md)。

## Windows 启动

完整解压官方服务器包，双击 `Start-Official.cmd`。无需另装Node或PostgreSQL。首次启动自动打开本机邮件设置页面：选择QQ邮箱、163邮箱或其他SMTP，输入发信邮箱和SMTP授权码，点击“验证发信连接并启动”。终端输出 `http://127.0.0.1:2568/official.html` 后即可在本机浏览器注册、验证、登录和匹配。两名测试者必须用不同账号；浏览器不同窗口/标签页可分别保存登录会话。

SMTP须在邮箱设置中开启。QQ默认smtp.qq.com、163默认smtp.163.com，465使用TLS，587要求STARTTLS。授权码不是邮箱登录密码；QQ配置说明见[腾讯官方文档](https://main.qcloudimg.com/raw/document/product/pdf/1270_46586_cn.pdf)。注册/找回邮件提供一次性24字符验证代码，15分钟有效；复制到游戏中完成操作。检查垃圾邮件文件夹。设置页面只检查SMTP连接和认证；是否真实送达以注册邮件实际收件为准。个人邮箱发信限制须实测，不能据本机容量保证大批量注册送达。

SMTP授权码与内嵌数据库密码由Windows当前用户加密保管。配置、账号、战绩及数据库存于 `%LOCALAPPDATA%/Red-vs-Blue-Official`，不要分享这个目录。运行中可在面板“邮件服务”修改SMTP，先验证再保存；`Configure-Mail.cmd`仍可用于停服配置。重复启动会被单实例锁拒绝，不会重启正在使用的数据库。同一Windows用户可以再次启动保留账号和已落盘对局。若提示 official-start.lock 遗留，先确认官方服务和配置窗口都已退出，再检查用户目录中的启动锁；不要在运行中删除锁。

此版监听127.0.0.1，适用于先本机验证。异地账号登录需要可信HTTPS入口，将HTTPS反向代理指向本机2568端口并支持WebSocket；客户端不会通过公网明文HTTP发送账号密码。P2P的frp明文直连能力不等于官方账号入口也可明文使用。

## 玩家流程与规则

客户端“联机大厅→官方排位”，在底部“服务器设置”中填写官方入口；也可直接使用官方服务器提供的网页。邮箱验证前不会创建可登录账号。完全开放注册，无邀请码。登录后点击“开始匹配”，接受任意Elo的真人对手；等待顺序优先，不用AI补空缺。首次入场前选择光方或暗方，再点击“进入当前比赛”；已锁定的阵容会在重连时保留。匹配成功后，双方在3分钟内进入并完成现有8枚阵容选择，沿用开阔原野地图和现有规则。未完成的准备局作废，不增减分。

首版显示Elo积分，初始1000，K=32，预期分使用400分尺度；同分胜负±16，和局按0.5分计算，双方调整零和。排行榜只列已完成比赛的账号，不另设晋级赛或未确认的段位名称。只有系统分配且服务器已落盘的终局可结算，客户端不能上传胜负/积分。多人重复请求、终局后重启都不能重复结算。

掉线120秒后AI接管，仍可使用原服务器账号重连收回控制；按最终胜负计分。每个账号每局最多记录一次长掉线，24小时内第3次起增加15分钟匹配冷却；当前对局重连不受冷却限制。改密码、找回和新登录撤销旧会话。服务器故障导致未落盘的状态不作为结算依据；恢复依照现有Colyseus/PG耐久记录，恢复失败必须保留证据并暂停扩量。

首次测试赛季为test-1。正式赛季可重置为1000初始分，保留旧战绩和测试参与者标识。切换赛季必须先停止新增匹配，等待所有比赛结束。

## 本机管理与停服

从 RED-196-rc2 起，服务就绪后自动打开“服务器指挥台”。浏览器关闭或刷新后，双击 `Open-Control-Panel.cmd` 重新打开，不会重启服务或数据库。面板使用独立的随机本机端口；不要将管理地址配置到 frp 或公网反向代理。玩家仍连接原来的2568端口。

- 运行总览：当前对局、排队账号、对局连接、注册账号、Node进程内存和数据库/结算状态。对局连接含玩家与观众，不等于全站在线人数，不统计仅停留大厅的用户。
- 对局记录：最近100条准备/进行中、已结算或作废对局；不提供隐藏手牌和秘密选择。
- 账号管理：按昵称、邮箱或完整UID搜索，30条分页；脱敏邮箱，封禁/解封需确认。封禁撤销登录和排队，不强行改判已开始的对局。
- 邮件服务：本次启动的SMTP提交成功/失败次数与连接认证检查。连接通过不代表收件成功；检查按钮不发送邮件。
- 维护与赛季：确认后停止/恢复新匹配、开启正式赛季、正常停服。有未结束对局时拒绝切换赛季或从面板停服。赛季切换不可撤销，需先核对编号；历史仍保留。
- 操作记录：最近100条成功管理操作，CLI操作同样可见。运行错误仍在服务终端查看，不将原始日志或SMTP凭据展示给浏览器。

面板每5秒刷新；连接失败会标记数据过期，不能把旧数值当作当前状态。管理凭据经Windows当前用户加密落盘，浏览器只在内存持有，刷新即失效。正常停服后删除面板入口凭据文件。点击停服后等待终端显示数据库已停止；再次启动仍保留维护状态，请在面板中恢复匹配。

在服务器包目录的终端执行，官方服务须已运行：

```powershell
.\Admin.cmd maintenance on
.\Admin.cmd maintenance off
.\Admin.cmd ban 账号UID
.\Admin.cmd unban 账号UID
.\Admin.cmd season season-1
```

管理命令使用本机Windows保护的管理凭据连接正在运行的服务，不启动或停止另一份数据库。维护只停止新匹配；封禁撤销登录并停止该账号新排队；季赛切换在存在已分配比赛时拒绝。所有操作在official_audit保留记录。管理范围见下节；不包含商城、批量邮件或管理员手工修改Elo。

正常停服：Ctrl+C，等待Colyseus落盘和PostgreSQL停止。停服后备份整个用户数据目录；不要只复制数据库中的个别文件。账号库与P2P玩家主机库分开。回退保留旧服务器包与匹配的数据库备份，禁止用旧版本覆盖新库或删除用户数据排错。

## 开发与验证

代码由lib/server/official提供独立账号/匹配/结算服务，复用现有BattleRoom；SMTP使用Nodemailer，不升级现有Colyseus/规则依赖。base main@b8a26a90fc591b61fef9fa33db4e679fb75eb33b，纳入RED-193 be82ae3依赖。风险High，独立审查、聚焦测试、类型静态与候选验证后再进入人工验收。

```powershell
npm.cmd run test:official
npm.cmd run build:official
npm.cmd run dev:official
```

## 联机大厅布局

主菜单联机入口默认房间列表：左侧常驻房间/排位/服务器导航，中间搜索及模式/状态筛选，右侧选中房间详情与加入/返回/观战。创建房间和12位房间邀请码通过弹窗；8位玩家主机邀请码在服务器页使用。服务器页用于P2P、直接连接、frp及公网转发配置。

从 RED-196-rc3 起，已结束房间会在大厅下次刷新时退出公开房间列表，旧服务器返回的结束房间也会在客户端过滤。已在房间里的玩家和观众仍可看到终局；战绩保留。重启不会重新创建已结束的实时房间，完整战报仍从数据库读取。

排位使用备战区、阵营选择和固定匹配操作栏；战绩、排行榜通过页内标签查看，不中断当前排队。账号登录、注册、找回在弹窗内完成。

交互参考采用[Dota官方大厅说明](https://www.dota2.com/reborn/part1)中的常驻开始入口、公共房间浏览与模式选择原则；美术继续使用本项目tabletop资源。没有加入虚构好友、聊天、服务器延迟或在线人数。


## 管理操作扩展（PVE 接入延期）

按2026-09-09用户确认，PVE由用户先完成，本轮不接入单人/合作PVE。当前面板管理本机官方账号与排位服务，不冒充可管理独立Relay中的匿名身份。

| 页面 | 可执行操作 | 行为 |
| --- | --- | --- |
| 账号管理 | 踢下线、封禁/解封、限制/恢复排位资格、解除匹配冷却 | 踢人撤销登录并断开对局，可重新登录；排位限制只影响后续匹配；不改进行中比赛胜负。 |
| 对局记录 | 作废异常未结束对局 | 先停止本局所有权威写入并落盘，再释放双方席位；已正常结束或已结算的对局拒绝作废。重启不恢复作废房间，日志保留。 |
| 容量与公告 | 并发1–50局、清空等待队列、更新/撤下公告 | 并发设置和公告保存在数据库，重启保留；降低上限不打断已有比赛。公告以纯文本显示在官方排位入口。 |

| 维护与赛季 | 维护开关、新赛季、正常停服 | 保留既有保护；绝无手动Elo编辑接口。 |

### 备份恢复

1. 在“维护与赛季”开启维护，等待进行中比赛为0。
2. 在“备份与恢复”创建备份；服务短暂停止后重新启动，保持维护。备份在数据目录的 backups 下。
3. 可先点击“校验备份”。恢复前会自动创建当前数据的备份，并保留 postgres.previous-* 旧数据库副本。
4. 恢复将账号、密码、战绩及服务设置回到备份时间；恢复后撤销全部登录和待用邮件代码，玩家需要重新登录。SMTP配置保持当前值。
5. 验证完毕后再恢复匹配。不得把数据目录或备份当作玩家分发包分享。

备份格式v1，仅支持原Windows用户的本机PostgreSQL16数据库；拒绝损坏、符号链接、非法路径和不兼容清单。文件/目录清单及SHA256用于校验；首版单份上限10GB/10万条目。副本先验证再替换，恢复意图记录在替换前同步落盘；中断后优先恢复旧完整数据库，损坏的新副本保存为 postgres.failed-*，不会自动删除。进程状态无法确认时拒绝替换。关闭浏览器不取消已接受的数据操作；停服会等待数据操作安全完成。备份和旧副本需服主自行离线归档，首版不自动清理磁盘。

### 回退与验证

保留RC3完整包及升级前的停止数据库副本。新增官方表列为兼容增量，不改变PVE或战斗记录格式；整版回退时先停止服务，使用对应版本的数据备份，避免旧管理工具绕开新的排位资格规则。新旧程序不同时操作同一数据目录。
