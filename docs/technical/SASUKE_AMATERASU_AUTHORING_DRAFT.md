## 三个独立Rule

1. 路径接触：基线读取afterPiecePathContact.contactCells计算接触层数。用户已明确改为每实际接触一格立即结算；传送只计落点。友军也会烧，不筛阵营。创建或叠加灼烧，不立即造成灼烧伤害。
2. 站立叠层：每位玩家回合结束时，给所有站在天照地格上的存活棋子增加一层，不只处理该回合玩家的棋子。
3. 灼烧伤害：每位玩家回合结束时，仅该玩家所属的受灼烧棋子受到每层2真实伤害。灼烧为永久状态，离开天照地格后仍存在，地格被消耗也不移除已附着状态。

现役用amaterasuOwnerPlayerId限制多个玩家安装的Rule只由首次登记玩家调度，全场地格来源仍各自保存。新代码不得让多个佐助的Rule重复叠层或伤害，调度去重与全场数据归属须在完整草案中明确。伤害来源直接读取状态extension.伤害玩家（铺设/附加时保存），原棋子来源只用于叠加分组；已撤回死亡来源回退，不写技能级fallback。已核对基线玩家Rule按优先级降序稳定排序，本组未声明优先级，按注册顺序先站立叠层再伤害；不擅自给它们新增优先级而改变相邻Rule顺序。

## 已确认：强度就是层数

基线amaterasu-burn同时有intensity=2与stacks=层数，真实伤害读取2×stacks，不读取intensity。用户确认强度就是层数，作者语言用天照灼烧的强度表示层数，持续时间为永久，每层2点由独立伤害Rule计算，不增加技能专属“天照层数”数据类型。

```text
// 已确认计算方式：每接触一个天照地格
附加状态(
    目标：当前事件.棋子，类型：天照灼烧，
    强度：1，持续时间：永久，来源：该地格保存的来源
)

// 已确认计算方式：所属玩家回合结束
新建【数值】变量【层数】 = 获取状态强度(目标：目标，类型：天照灼烧)
造成伤害(
    目标：目标，类型：真实，伤害量：层数 × 2，
    伤害来源：该状态保存的来源
)
```

以上只是字段映射与计算展示，不是可运行完整Rule；地格/状态来源读取已在详细作者正文中用映射和具体状态实例展开。普通永久状态的合并必须保持永久，不制造有限时间。强度显示与旧stacks显示需在迁移时适配，不把基线intensity=2自动当成两层。强度表示层数与具体状态查询均已获用户确认；同来源或双方无来源允许按原规则合并，不同来源保留独立实例。天照显式保留来源。

## 加具土命：本次最多4层，总强度不设上限

基线消耗目标曼哈顿4格内全部天照地格，包括其他玩家来源地格，已附着灼烧不随之清理。本次算得层数为2+min(2,消耗地格数)，即最多4。新状态创建为该层数；已有状态时，代码写stacks=min(4,旧层数+本次层数)。所以原本6层的目标会被该次使用压到4层，牌面“本次最多4层”与此实际行为不一致。用户已明确选择按描述处理：只限制本次附加强度最多为4，已有灼烧按普通状态叠加，不限制总强度。因此不沿用基线的总层数钳制，不需要设置状态强度或读取旧强度再写回。完整作者代码见SASUKE_KAGUTSUCHI_AUTHORING_DRAFT.md；这属于已批准的基线差异，实施须补回归。
