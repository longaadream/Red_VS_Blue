# 圣光降临与穆鲁的挽歌

固定基线：`082166c6b803b2e838bce5f0f6824c5bbc714dd6`。只整理作者规范，未改运行代码。参数遵循用户指定基线；容器、阵营、伤害类型与技能实例字段使用最新规范。

## 圣光降临

```text
Skill：圣光降临
触发器：使用技能
行动点消耗：3
充能点消耗：1
冷却：5
每局使用次数：不限
code：
    新建【地格】变量【中心】 = 目标选择器(类型：地格，范围：6)
    新建【映射<数值,数值>】变量【距离效果量】 = {0:9, 1:7, 2:4, 3:4}
    新建【元组<数值>】变量【距离顺序】 = {0, 1, 2, 3}
    对每个 圈 属于 距离顺序：
        新建【元组<棋子>】变量【本圈棋子】 = 目标选择器(
            类型：元组<棋子>，方式：自动，中心：中心，
            范围：圈，最小距离：圈，距离算法：曼哈顿
        )
        新建【元组<棋子>】变量【友军】 = 筛选(
            容器：本圈棋子，条件：(棋子) => 棋子.阵营 == 当前棋子.阵营
        )
        新建【元组<棋子>】变量【敌军】 = 筛选(
            容器：本圈棋子，条件：(棋子) => 棋子.阵营 != 当前棋子.阵营
        )
        新建【数值】变量【效果量】 = 距离效果量[圈]
        恢复生命(目标：友军，数值：效果量，来源：当前棋子)
        造成伤害(目标：敌军，类型：普通，伤害量：效果量，伤害来源：当前棋子)
```

按已经确认的逐圈处理，不新增同时结算控制语句。用映射读取效果量，但不依赖Map遍历顺序；0/1/2/3由元组明确排序。每圈重新查询存活棋子，保存该圈友军与敌军后先治疗再伤害；同圈相同效果的多目标调用沿已有批量接口同时结算，不改成每名棋子逐个伤害，也不把不同圈合成同一次伤害。

中心选择默认最小距离1；效果第0圈显式最小距离0，可以影响中心格棋子。不要求中心可行走或空闲，避免增加基线没有的限制。来源失效后依赖该棋子的效果语句失效，不改成玩家来源。

基线执行量为9/7/4/4，旧描述写9/7/5存在不一致。本草案依据用户“以基线为准”的要求采用实际执行数值，正式描述可写：“选择地格（6）。按距离由近到远结算：距离0／1／2～3格的友军恢复9／7／4点生命，敌人受到等量普通伤害。”未直接更改数据文件。

## 穆鲁的挽歌

```text
Skill：穆鲁的挽歌
触发器：使用技能
行动点消耗：3
充能点消耗：3
冷却：2
每局使用次数：3
引用：圣光汲取实例 = 当前棋子持有的圣光汲取Skill实例
code：
    新建【元组<手牌>】变量【所选手牌】 = 目标选择器(
        类型：元组<手牌>，区域：当前棋子.所属玩家.手牌区，
        筛选条件：{具有标签：圣光}，最少数量：1，最多数量：4，允许取消：true
    )
    新建【数值】变量【张数】 = 获取长度(容器：所选手牌)
    对每个 手牌 属于 所选手牌：
        弃置手牌(手牌：手牌)
    新建【数值】变量【轮次】 = 0
    当 轮次 < 张数：
        轮次 = 轮次 + 1
        新建【元组<棋子>】变量【敌军】 = 目标选择器(
            类型：元组<棋子>，方式：自动，范围：全图，筛选条件：{关系：敌方}
        )
        新建【元组<棋子>】变量【友军】 = 目标选择器(
            类型：元组<棋子>，方式：自动，范围：全图，筛选条件：{关系：友方}
        )
        造成伤害(目标：敌军，类型：真实，伤害量：2，伤害来源：当前棋子)
        恢复生命(目标：友军，数值：2，来源：当前棋子)
    如果 张数 >= 3：
        新建【元组<棋子>】变量【现存友军】 = 目标选择器(
            类型：元组<棋子>，方式：自动，范围：全图，筛选条件：{关系：友方}
        )
        对每个 友军 属于 现存友军：
            如果 获取长度(容器：获取状态(目标：友军，类型：圣盾)) == 0：
                附加状态(目标：友军，类型：圣盾，强度：1，持续时间：永久)
                附加规则(挂载对象：友军，规则：圣盾抵挡)
        圣光汲取实例.当前冷却 = 0
```

圣光标签覆盖现有三张候选定义：圣光惩击、圣光治疗、圣光充能；不按卡名字符串识别。未来给新卡明确加此标签才进入候选。选择器使用手牌区牌面多选、实例引用与1～4张限制；同名不同实例可分别选择，同一实例不能重复勾选。作者元组有序可重不代表交互允许重复选择同一张实体。没有候选无法完成必要选择，使用前拒绝；取消不扣资源、不弃牌。

准备阶段复核全部所选手牌仍在该玩家手牌区、具有标签且数量合法，然后才提交费用和弃置。先全部弃置，再按保存张数重复效果，不读取弃置后的拥有者字段决定次数；弃置不作为使用手牌事件。每轮先查询双方当前存活棋子，再批量伤害敌方、批量治疗友方；伤害反应中新召唤的友军下一轮才能进入，不擅自把治疗查询挪至伤害之后。不能合并为一次2×张数，否则圣盾消耗和触发次数改变。

至少3张时重新查友军，只给没有圣盾的目标添加；这是此技能的基线条件，不替换其他技能普通叠加政策。共享[圣盾抵挡Rule](PALADIN_SHIELD_AUTHORING_DRAFT.md)，不添加第二套隐藏Skill。冷却直接写当前棋子的实际Skill实例，不改定义；若移植Cluster后没有这个Skill实例，最后一句按无效引用跳过，前面效果照常。

maxCharges=3按已确认字段含义为每局3次；覆盖历史记录曾因未见usesPerBattle而误判的说法。施法者中途死亡时，依赖其有效来源的后续伤害/治疗失效，不重新选另一个棋子或回退玩家；已发生的弃置与资源消耗不退款。
