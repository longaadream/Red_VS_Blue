# 联机入口与房间生命周期

本次验收修复基线：2026-09-15。三个入口共用游戏规则，但目录和连接来源必须明确。

| 入口 | 房间目录 | 谁执行规则、保存进度 | 连接方式 |
| --- | --- | --- | --- |
| 主页创建／加入 | 局域网专属 `lan.html` | 玩家设备上的本机服务 | 明确的主机地址；没有邀请码 |
| 官方／非官方服务器的自由房间 | `multiplayer.html` | 玩家设备上的本机服务 | 所选服务器的 Relay 转发 |
| 官方排位 | `official.html` | 官方权威服务器 | 官方账号及排位协议 |

单人 PVE 直接启动本机服务进入冒险，无需经过房间目录。连接公网不停止本机服务。自由房间要区分 1v1、2v2、PVE；Relay 不决定规则、不保存玩家冒险。

## 来源必须随页面传递

LAN 目录只使用入口指定的 `serverUrl`，不回退到记忆中的公网地址。公网目录只查询当前 Relay 的 hosts。公开房间的房主虽然连接本机地址，也必须携带 `lobbyContext=public`；房间、选人、战斗、返回全程保留，不能仅用 `server=local` 判断目录归属。

普通 Colyseus 匹配请求显式不携带 Cookie，身份仍由签名 admission 校验。官方账号 Bearer 及排位 token 不受此设置影响。这样避免列表 fetch 成功、SDK 加房却因通配 CORS 与 credentials 冲突失败。

## 离开与断线

- PVP 主动离开先等待权威席位释放，再断开客户端。旧连接的延迟断开不得清除新的会话映射。
- 意外断线保留协议的重连窗口；主动离开清掉该连接的重连状态。
- PVE 队员可离开队伍；房主可保存并解散。解散在权威命令队列中保存当前已提交进度，冻结后续动作和 tick，再关闭房间。保存失败保留房间，允许重试。
- 冒险存档仍留在房主设备。公网列表不再展示该房间；Relay 主机连接本身可继续运行。

## 尚未定义的战区投降

不能把 PVP surrender 直接用于合作冒险：它按全局席位和队伍结算，可能拒绝三／五席，或结束其他战区的冒险。当前版本保留原限制，关闭房间使用明确的离开／保存解散操作。

独立战区投降需要进一步确定：本队退场还是本战区全体败北、多人同意方式，以及队长／储备／补给的失败后状态。不得在未确定这些规则时直接透传 PVP 投降。

## 验收顺序

先验 LAN 首次进入、离开重进、断线恢复；再验 Relay 同样流程；最后验官方排位。每轮都使用同一批 Windows／安卓包及相同资源身份。移动端还需覆盖列表触屏滚动、手牌操作、部署区和横屏安全区域。

## 局域网发现与直连地址
安卓本机权威启动后每 2 秒向所在 IPv4 子网广播 RVB_DISCOVER（UDP 7877，携带实际游戏端口、主机名称与公开标识），关闭时停止。广播异常只记录，不中止游戏服务。LAN 页面、准备房间与 PVE 同行者面板展示主机 IP 和端口；本机回环地址转换为原生网卡地址，公网房间不展示 LAN 控件。广播被路由器隔离时可通过主页加入房间填写直连地址。

## 删除冒险存档
继续存档列表提供逐条删除及确认。请求按登录玩家和列表 revision 校验，旧列表不能删除后来保存的新进度。删除最后一份相同 revision 的手动记录时同步清除对应自动存档指针，避免重复出现；不删除运行中的 current 进度和动作记录。PostgreSQL 使用事务与行锁，安卓 SQLite 使用即时事务。存档仍在创建冒险的主机设备，不在 Relay 上。
