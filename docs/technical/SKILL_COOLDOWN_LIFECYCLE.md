# 技能冷却结算（RED-206）

2026-09-13 用户明确决定：棋子技能冷却从所属玩家回合开始移至所属玩家回合结束，施放当回合也扣减。

## 权威顺序

技能实际使用后写入 `cooldownTurns`，使用后效果（如月读）可额外增加计数。当前冷却大于0时拒绝施放。

`endTurn` 依次完成结束触发链及交互、`whenever`、状态到期事件，然后只对结束回合玩家的场上棋子技能，将正数 `currentCooldown` 减1。零和未设置的计数保持原样。随后进入 `end` 阶段。同一回合再次提交 `endTurn` 会被拒绝，不重复结算。超时结束走同一权威流程。

交互暂停期间不提交冷却变化；序列化后的交互续接也只提交一次。开始阶段、部署选择和部署续接不扣棋子技能冷却。现有 `refreshedAtTurn` 继续保护被动规则 `limits` 的刷新，不用于技能计数。被动规则冷却与规则持续时间仍按原机制在开始阶段更新。

## 数值含义

| 情况 | 使用/施加后 | 所属方回合结束后 | 下一次所属方行动阶段 |
| --- | --- | --- | --- |
| 自己回合使用冷却1技能 | 1 | 0 | 可用 |
| 自己回合使用冷却2技能 | 2 | 1 | 不可用；该回合结束降为0，之后可用 |
| 对方回合被施加至少1冷却 | 至少1 | 施加方结束不会扣目标冷却 | 目标不能用，到目标回合结束才扣减 |

十拳剑与志志雄自燃压制使用 `Math.max(原冷却, 1)`，不覆盖更长冷却，不额外叠加1。月读在实际使用后加1，仍让目标技能额外等待一个自己的回合。重置冷却仍立即清零；新增初始冷却0的技能仍可当回合使用。

## 交付与兼容

这是引擎规则变更。客户端/服务端引擎与十拳剑、志志雄内容应成套更新。旧引擎搭配至少1的强制冷却仍会在目标回合开始提前解除，因此作者资源候选不能单独用于旧客户端。

未修改存档结构或执行中的对局。既有录制状态回放保持历史数值；使用旧规则录制的命令重新交给新引擎模拟，不保证产生相同状态。回退应同时恢复引擎、资源数值并重新构建。
