# 护甲组装与组合护甲：代码块作者草案

固定核验基线`082166c6b803b2e838bce5f0f6824c5bbc714dd6`。已读tails-armor-assembly、rule-tails-armor-recovery；当前工作区已经提供文本多选模块，并以组合模板生成卡牌。用户认可将结构化代码块存入手牌extension，取代字符串识别组合。满手已确认由引擎把新牌放入弃牌区，作者主体转A；仅作者设计，未实施运行。

## 四种代码块

以下每个片段显式接收目标棋子，无返回值、不捕获制作护甲时的施法者。片段定义在技能内容资源中，作为可引用的结构化模块树；不需要把片段注册成主动Skill或Cluster。

```text
代码块【恢复模块】(目标：棋子)：
    附加状态(目标：目标，类型：护甲恢复，强度：1，持续时间：永久)
    附加规则(挂载对象：目标，规则：护甲恢复)

代码块【攻击模块】(目标：棋子)：
    目标.攻击力 = 目标.攻击力 + 3

代码块【高速模块】(目标：棋子)：
    附加状态(目标：目标，类型：高速模块，强度：1，持续时间：永久)
    附加规则(挂载对象：目标，规则：每回合首次移动免费)
    附加规则(挂载对象：目标，规则：首次免费移动费用)
    附加规则(挂载对象：目标，规则：首次免费移动消费)
    附加规则(挂载对象：目标，规则：首次免费移动回合清理)

代码块【硬化模块】(目标：棋子)：
    目标.防御力 = 目标.防御力 + 2

StatusTag：护甲恢复
可见：true
允许叠加：true

StatusTag：高速模块
可见：true
允许叠加：true

Rule：护甲恢复
挂载对象：棋子
触发器：本玩家.回合结束
code：
    新建【数值】变量【恢复量】 = 0
    遍历【获取状态(目标：当前棋子，类型：护甲恢复)】中的每一项【状态】：
        恢复量 = 恢复量 + 状态.强度 × 3
    如果 恢复量 > 0：
        恢复生命(目标：当前棋子，数值：恢复量，来源：当前棋子)
```

恢复使用正常治疗模块，经过禁疗、治疗修正与最大生命值检查；不照抄旧直接写生命。基线按独立状态条目数×3，新规范按所有状态实例的总强度×3，避免同持续时间合并后少算装备数量。一份3、两份6，以一次治疗调用处理，保留基线合计回复的方式。状态消失后Rule无效果即可，不删除其他来源可能仍依赖的共享Rule。

攻击与硬化是当次永久属性增量，多张卡逐次累加。高速复用[音速免费移动Rule](SONIC_FREE_MOVE_AUTHORING_DRAFT.md)，多份高速或同时拥有音速也只刷新一次资格；装备当时不立刻赠送一次。基线高速Rule不筛选高速标记，移除该显示状态不撤销已经附加的Rule；本草案保留这一行为，不偷偷把状态与Rule绑定。若要改为驱散高速即可取消能力，应另明确玩法变更。

## 组装技能与手牌正文

```text
Skill：护甲组装
触发器：使用技能
行动点消耗：0
充能点消耗：2
冷却：3
每局使用次数：不限
code：
    新建【映射<字符串,代码块<(目标:棋子),无返回值>>】变量【选项】 = {
        "恢复模块"：恢复模块,
        "攻击模块"：攻击模块,
        "高速模块"：高速模块,
        "硬化模块"：硬化模块
    }
    新建【元组<代码块<(目标:棋子),无返回值>>】变量【所选效果】 = 选项选择器(
        选项：选项，最少选择：2，最多选择：2
    )
    新建【手牌】变量【护甲】 = 获得手牌(
        玩家：当前棋子.所属玩家，手牌定义：组合护甲，
        extension：{效果列表：所选效果}
    )

手牌：组合护甲
触发器：使用手牌
行动点消耗：2
code：
    新建【棋子】变量【目标】 = 目标选择器(
        类型：棋子，范围：全图，筛选条件：{关系：友方}
    )
    遍历【当前手牌.extension.效果列表】中的每一项【效果】：
        执行代码块(代码块：效果，参数：{目标：目标})
```

多选沿已有四选二能力，标签只负责显示，业务值直接是代码块引用；不能重复同一选项。返回元组保存选项顺序，手牌逐项执行，不把它转换成Set而丢失顺序。代码块的目标来自使用手牌时选择的友军，包含自己、同阵营队友；不是制造牌的塔尔斯。使用后默认弃牌，不在片段内重复弃牌。两张同名护甲各有独立效果列表，复制按手牌实例复制合同处理。

这里没有新增“把源码写入手牌”操作：同一手牌定义只有一段遍历代码，不同实例携带不同代码块值。数据注册名只供内容定位，不生成armor-attack-heal这样的业务识别字符串，也不为6种组合各维护一份执行代码。

显示应由所选片段的显示元数据组合牌名与描述；显示文字不能反过来决定效果。本轮代码片段的执行签名不含未确认的任意对象字段，因此不假写效果.名称；名称/描述可在选项的配套显示映射中声明并初始化进实例显示数据。具体显示绑定与日志沿已有表现合同后续对齐，不能宣称与当前UI等价已验收。

## 满手：直接由引擎放入弃牌区

用户明确满手仍正常释放，取消此前建议的容量前置失败；正文不增加手牌长度判断，也不在获得手牌之后返回释放失败。引擎创建带有所选效果列表的新护甲，检查容量并直接放入弃牌区。仍扣2充能并进入3回合冷却；其他独立效果照常。

返回的护甲实例仍有效，所在区域为弃牌区。其效果列表初始化完成，但没有“使用手牌”，所以不会给任何棋子装备护甲。之后若被其他效果取回手牌，仍保留这张实例原有的两种片段。失败进入手牌区不等于实例创建失败；没有规则要求时不自动改装备目标、不自动执行片段。

旧addCardToHand失败后返回success:false的路径被此明确规则取代。具体获得/区域事件与日志表现待运行实施核对，不能把新规则说成旧引擎已支持。

## 验证清单

6种两两组合、选项不重复、取消不提交；两张同名卡效果不串；制作后不提前加属性、使用时才作用于选择目标；多恢复按总强度治疗且禁疗有效；多高速仍一次免费移动；攻击/防御多次增加；原制作者死亡或归属改变不改变已生成牌的效果；手牌复制可变元组独立；初始满手/期间填满均转弃牌且不退款；自动描述与实际片段一致。当前只检查文档及基线证据，未运行游戏测试。
