# 资源工作区与发布（RED-200）

开发基线：`main` / `12a0937c3f39ca43e5cbb2f1d9a6f1e8c11ac441`。本轮只修改资源编辑器及其测试，不修改游戏客户端主进程或引擎。

## 日常使用

1. 在编辑器顶部点 **导入资源包**，选择 `.rvbpack` 和保存位置。已有内容项目用 **打开项目**；也可复制官方内容或创建空白项目。
2. 导入后自动建立“更新导入的资源包”任务和比较基准。把任务的 AI 交接文件交给任意外部 AI，或直接使用编辑器修改资源。
3. 工作台可见且没有正在输入的表单时，每 4 秒检查外部修改。查看文件、JSON 值和图片前后差异；勾选文件，点 **接受选中修改** 或 **撤销选中修改**。
4. 接受只保存本地不可变版本。未接受的草稿不会进入导出或发布。撤销有版本冲突检查，并保留恢复记录。
5. 到 **版本与发布** 填更新说明并发布。首次设置 GitHub 仓库、令牌和已有签名密钥；日常操作自动计算版本、哈希、补丁操作和签名。

“部分接受”目前以文件为单位。JSON 字段差异用于检查，不能逐字段接受。

## 原包导入

支持符合 `rvb-pack/v1` 的完整快照包；选择补丁时会追加要求选择其匹配的完整原包。当前导入界面支持完整包或完整包加一个匹配补丁，不支持任意多包链选择。已有长补丁链可使用对应发布的完整包。

读取、解压预算、文件路径、哈希、ABI、签名及数据安全均复用现有管线，在编辑器 utility process 中校验。未签名包仅作为本地创作源导入，不因此取得正式客户端信任。签名存在时必须验证通过；验证签名不代表认可发布者身份。旧式 `pack.json` ZIP、客户端安装包、带可执行 `code/skillCode` 的外部资源不会被强制转换或绕过校验。

成功后创建唯一的 `rvb-import-UUID` 目录，原包逐字节备份到 `archives/<sha256>.rvbpack`，原文件保留。缺失的四类集合清单初始化为 `[]`，记录于项目描述文件的 `initializedFiles`；初始化后的可编辑树立即成为比较基准。失败不切换当前项目；写入期间的失败保留临时目录供检查。不会合并覆盖已有项目。

## 发布与连续补丁

只从已接受内容的对象快照构建；再复制并验证到编辑器私有暂存目录，避免 AI 修改待签名文件。每个发布都带完整 `content.rvbpack` 和 `content-update.json`。存在上一份本地发布记录时，自动生成 `content-patch.rvbpack`，真实解析验证后才上传。

本地发布记录保存实际完整基包及补丁链，连续第三版补丁以前一补丁应用后的 Profile 身份为父版本。链长达到 256 后用完整包重新建立基线。新装用户或父 Profile 不匹配的用户需要当前完整包；不能把内容相同的独立完整包身份当成补丁链身份。换电脑、丢失发布记录或仓库配置变化可能需要重新以完整包建立基线。

GitHub 使用内容哈希确定标签；先创建草稿，上传后核对文件大小和 SHA-256，再公开为测试发布。遇到未知结果先读取并核对远端状态；不覆盖同名但不同内容的资产。更新说明最多 4000 字符，包内简述最多 1000，完整说明保留在 Release。参考 [GitHub Releases REST API](https://docs.github.com/en/rest/releases/releases)。

发布仓库使用跨进程独占锁，防止两个编辑器同时更新父版本记录。崩溃后残留锁需要检查发布记录后人工清理，不能不查远端就重建版本。已生成缓存的同一接受版本重试使用原说明与原产物。

GitHub 令牌用 Electron `safeStorage` 加密，保存在编辑器用户数据目录；签名密钥必须位于 AI 内容目录之外，只使用已有密钥。设置不会写入内容项目。AI 提示文件不是操作系统沙箱：外部 AI 工具仍应只授权内容项目写权限。

## 当前能力边界

- GitHub 发布协调器和签名构建已实现；测试使用模拟 GitHub API，没有发布真实资源或验证实际网络上传。
- 玩家客户端自动发现/下载这些资源更新尚未接线。当前通过发布链接分发文件，不能声称玩家自动差量更新已经完成。
- 游戏客户端缺少编辑器候选交接和训练营启动接口；按钮明确显示不可用，场景与反馈可以保存，不能声称已实战运行。
- 本轮授权不允许修改游戏客户端主进程/引擎；上述两项需要后续单独明确接口范围。
- 当前资源预算为压缩包 32 MiB、单文件 16 MiB、展开 128 MiB，沿用现有合同；大型旧包不会自动兼容。

## 恢复与数据位置

项目内 `.workbench/objects` 保存原始字节，`.workbench/accepted.json` 为项目共享接受指针，`.workbench/tasks` 保存任务与不可变版本，`.workbench/transactions` 保存撤销备份与恢复计划。并发外部写入不会被假装成完整回滚成功；遇到冲突必须按记录检查。

用户数据目录的 `resource-releases` 保存发布缓存、完整包/补丁链和发布锁；`resource-publication.json` 保存加密令牌与密钥路径。备份时将创作项目与私有发布状态分别备份，不把令牌、私钥交给内容 AI。
