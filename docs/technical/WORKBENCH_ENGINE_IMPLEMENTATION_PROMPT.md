## 二、作者模型：Skill + StatusTag + Rule，以Cluster为技能单位

2026-10-12 最新澄清：**Skill 不等同于 Cluster**。Skill 表示可主动使用的技能，许多被动能力由 Rule 实现。技能菜单展示和展开的单位是 Cluster；一个 Cluster 可包含 Skill、Rule、StatusTag、Card 相关内容及 extension，也可以没有主动 Skill。不要为了显示一个被动能力而虚构主动技能。现有历史 `type: passive` 文档的存储兼容与作者界面含义分开处理。

StatusTag 不设置独立顶层目录。在能力组内查看和编辑状态定义及图标，保持定义实际所属文档和共享引用，不自动绑定 Rule 生命周期。extension 也在所属对象内编辑，不引入第二份运行数据。

- 棋子是工作台主要入口，主动技能和被动技能都以Cluster为可视化操作单位。Cluster汇聚相关Skill、Rule、StatusTag定义、初始化声明、模板和引用依赖；不能将被动遗漏成不可编辑引擎特例。
- 复制、授予、移除、偷取技能等以Cluster为完整能力边界。明确实例数据、共享定义、专属成员和共享依赖的所有权，防止同名技能串改、移除一个能力误删其他能力的公共Rule。
- Rule与StatusTag没有隐式生命周期绑定。Rule显式查询状态；附加/移除状态不会自动安装/卸载Rule。同一挂载实例+Rule定义去重，返回已有实例时保留extension。
- 不要求作者使用任意JavaScript、字符串ID、角色名称分支或不可展开的角色专用复杂节点。复杂行为由通用表达式、控制结构、效果模块与代码块组成；不能把旧整段技能代码藏进一个节点后宣称完成迁移。

## 三、整个工作台的UI和交互重做

视觉以用户提供的浅色参考图为方向：白色/浅灰底、克制蓝色强调、清晰文字、充足间距、统一图标、边框和轻阴影。以实际创作效率为验收标准，不以截图相似或装饰数量代替易用性。沿用游戏统一动画管线，不为每个模块制作特殊动画。

导航以棋子列表/搜索为主要入口，主目录为棋子、技能（Cluster）、卡牌、规则、素材与资源包。状态和模板由所属能力组进入。所有目录提供一致的列表—详情—引用跳转体验；进入专注编辑后内容列表可收起。中间主体编辑、右侧说明/预览形成稳定布局。支持清晰返回、当前上下文、保存状态、撤销/重做、校验错误定位和引用影响提示。此次初版必须覆盖所有主目录及打包流程，不得只换技能页皮肤而保留其他区域的复杂旧操作。

棋子详情展示属性及主动/被动Cluster。进入Cluster后，效果编辑页就能完成全部能力，包括初始化、触发条件、分支、循环、目标选择、状态、延迟规则、召唤模板和显示配置。相关定义可以在同一工作区切换/引用编辑，不能为了编辑普通参数反复打开多层抽屉或折叠面板。

采用可读的语句列表与行内参数，类似参考图中的自然语言编辑：点击蓝色字段编辑目标、范围、变量或公式。所有语句从模块列表插入；所有表达式通过有类型的模块、属性访问和运算符组合。可提供可选键盘快捷输入，但不允许把手打代码作为完成复杂功能的唯一方式。

交互借鉴 Construct 的行式条件/动作组织、Blockly 的值输入嵌套及 Blueprint 的纯计算/执行边界。参数槽不是仅能填写数字的表单：运算的每个操作数、函数参数、条件、索引都能继续组合兼容类型的表达式。编辑时保留完整语句与所选子表达式上下文，不通过多层弹窗或流程图完成必要步骤。分支/循环内部应能插入、移动、复制和删除语句；只读展示不计为编辑覆盖。模块覆盖必须分别统计定义、注册、可视化创建编辑、保存重开、运行验证，不使用说明书行数充当完成数量。

高级选项提供完整类型、定义/实例引用、事件字段、权限、优先级、extension、绑定关系等信息；它们必须可见可查可修改，不能为了简洁丢掉表达能力。流程图可作为可选调试视图，但不是任何能力的必经编辑入口。

试验场支持工作台内切换，并支持另开窗口。复用同一资源版本与权威规则运行时；清楚显示当前使用的已保存版本或草稿版本，禁止另建一套近似规则模拟器。

## 四、统一结构化定义与模块注册表

建立版本化、有类型的结构化作者表示。模块注册表至少描述：模块身份、参数/结果类型、默认值、作用对象、字段读写权限、事件阶段、纯表达式或副作用属性、编辑控件、语言模板、运行映射与错误定位信息。

同一结构化定义驱动：

1. 工作台编辑和静态校验；
2. 编译/解释执行；
3. 能力描述与实例显示模板；
4. 只读数值预览与可用性/消耗显示；
5. 运行日志、调试定位与统一表现事件。

不要分别维护一份UI公式、一份描述数字和一份战斗代码。描述生成需允许经过约束的措辞模板与显示配置；秘密信息按查看者投影，不能自动把内部变量写进公开说明。预览只执行允许的纯计算，不能通过模拟执行副作用Rule来更新费用或文字。

完整支持：类型化变量、属性读写、extension声明/赋值/删除、算术/比较/布尔表达式、显式参数lambda、条件与return、for/while、代码块、实例与定义引用、Set/Map/用户称元组的vector。Set不重复且无下标；元组有序允许重复、从1开始索引。纯表达式与效果语句严格区分，拒绝类型不匹配和越权字段。

## 五、新版引擎的共通保证

- 规则核心可在无窗口环境中运行。React/Electron只展示权威结果和发送命令，不复制规则。所有位置提交经过现有权威生命周期和位置体系，不直接写坐标。
- before事件按schema允许写入，after事实只读。支持局部变量在使用前Rule中的有类型访问/改写，尚未声明的变量使对应语句跳过，不创建默认值。挂起恢复不能重复费用、随机、倍率或已完成效果。
- 清晰区分准备阶段使用失败与效果阶段结束/无效果成功；默认主动使用成功，显式提前失败不扣费，正常结束按规则消费。不要把所有效果失败都回滚成整次技能失败。
- 失效实体使依赖语句无效，独立后续继续；条件及else的传播须统一。明确保存语句依赖，不能从角色名猜测。影分身传送失败取消依赖召唤，回溯位置失败仍恢复其他信息，是必须覆盖的相反案例。
- 目标选择、选项选择、手牌区点选、方向选择、拖动/点按普通移动统一支持等待、取消与恢复。默认与显式取消规则按已确认合同执行，不强迫作者写常规fallback。
- 伤害只有普通/真实，真实只无视防御；最小伤害、blocked、非正中止、前后触发、击杀返回及来源有效性按最新合同。治疗使用正常治疗模块；消灭直接进入死亡流程，不能混同伤害或出局。
- 敌友按阵营，所有权与阵营不同；“本玩家”与“友方”上下文分开。只有核心棋子参与判负，普通召唤物无普通死亡充能结晶，明确技能奖励另算。
- 状态强度/时长、可见即可驱散、来源可选、extension参与合并、不叠加忽略新状态、创建回合不减时长、当前所属玩家回合末递减均按最新约定；不把圣盾等内容硬编码成引擎特例。
- 所有随机使用可注入可回放的种子流；统一整数语义、优先级、循环/改写上限。不要在内容中散布Math.random或角色专用调度规则。
- 复制实例、应用信息、原实例回场、模板新建分别定义身份与生命周期。外部引用保持身份，可变副本独立；不复制全场引用图、不共享误写可变状态。保存格式必须版本化，不静默破坏旧存档。
- 费用、冷却、次数与描述在依赖变化和需要读取时更新，不靠多次轮询，不在渲染过程中执行效果。

## 六、必须保留的复杂案例

逐项追踪作者正文、模块、运行入口、UI操作及测试证据，至少覆盖：

- 影分身：技能内声明模板，空技能/空状态、移速0、独立受伤消散Rule；召唤首次即应用逐字段伪装快照，只有所属玩家辨认，队友也看伪装。
- 双尾飞行：两个独立传送；施法者离场队友仍继续；任务独立计时；状态extension隔离；只读移除快照识别主动取消与自然到期。
- 镜花水月：秘密目标、逐目标前置改写、新候选规则、取消不消费、多实例记录与改写上限。
- 回溯：保存独立实例副本与历史位置；位置失败其他信息仍恢复；不伪造普通治疗/状态增删事件。
- 圣光预言：具体手牌实例的Rule，维伦死亡不取消；离手保留，返手后继续回合开始处理；万千未来提前完成不重复强化。
- 月神赐福：玩家Multiplier与使用前局部变量改写；无目标但成功使用仍消费；不叠加执行旧修饰器。
- 艾露恩守护：每玩家独立一次，可保护同阵营棋子；一次伤害被阻挡后不再消费队友守护；正常治疗5。
- 命运庇护：施加选友军，施加后不分敌我照常结算；死亡清理与状态失效按独立Rule处理。
- 恶魔仪式：五张牌逐实例传递绑定原棋子；无绑定不新建；仅召回原实例，满血作为入场初始化，首次显示/召唤后已满，不触发治疗。失败不独立补血。
- 圣铸进军：选友军后直接调用一次免费普通移动，合法性由引擎处理，不加作者落点查询流程。

这只是代表性验收集，不是替代全量内容迁移的样例清单。

## 七、实施顺序与范围

阶段1：规范归一和现状审计。产出统一schema/注册表、旧新接口映射、冲突清单、全部可达内容清单和分阶段Linear合同。已明确的常规差异直接解决，关键玩法歧义才停对应部分。

阶段2：建立贯通路径。从一个简单主动技能、一个被动、一个手牌技能验证“可视化编辑→保存→重新打开→编译/运行→描述/预览→日志/动画→试验场”。这些是架构验收，不是最终交付边界。

阶段3：完成通用运行时与整个工作台，并覆盖上述复杂案例。高级能力必须可通过效果编辑器完成，不能以手改JSON/代码弥补控件缺失。

阶段4：迁移140个初始Skill及所有可达派生内容。按Cluster与依赖统计真实迁移覆盖；兼容后端可分阶段保留，但最终正式入口不得绕过语义模块执行旧整段代码。

阶段5：全量验证、独立审查和用户验收。缺陷回归修复后交付可运行工作台、引擎、迁移数据及完整证据。

范围包括工作台导航/编辑/预览/试验、共享schema、编译与运行、必要的表现和日志适配、现有内容迁移、相关存储版本适配及测试。冒险模式内容暂不纳入，但阵营/玩家边界不能写死为1v1。不要顺手改经济平衡、随机算法、账号/服务器等无关模块；禁止未经说明改玩法以简化迁移。

## 八、验收与交付

- 先读取package.json与相关测试说明，使用实际存在的命令；按受影响范围运行模块测试、类型/静态检查、固定种子回放和必要的桌面/UI冒烟。
- 每个模块有可验证的输入、输出、失败和权限边界；重点测试状态变化、事件顺序、实例隔离、交互挂起恢复、引用失效、循环保护及回放确定性，不写仅镜像实现的测试凑数。
- 旧基线行为与最新用户明确修改分列。未改规则验证一致；授权变化按新期望验证，不为了通过旧快照改回过时行为。
- 全工作台任务通过实际操作验收：无需手写代码完成简单/复杂技能，保存重开不丢类型/引用/布局数据，运行行为和描述一致，错误能定位到具体语句，窗口切换/另开试验场正常。
- 检查真实游戏内选择UI、动画、日志、费用/冷却和秘密信息投影；不得仅以引擎测试或截图证明交互已完成。
- 验证保存/读取、版本迁移、外部引用重绑定、同种子同输入结果一致。未经明确授权不更新失败快照以掩盖回归。
- 分别报告作者覆盖、语义模块迁移、运行验证、UI验收四个数字。未支持入口、兼容路径、待定接口及未跑测试必须如实列出。
- 每阶段提交可复查差异、测试结果、关键截图/日志/回放、剩余风险和回退办法。最终报告实现完成并等待人工验收，不自行宣布用户体验验收通过。

开始时先给出真实现状、可复用部分、首阶段改动目录、风险、测试计划和具体实施合同；随后按已经授权的范围持续推进。不要只生成设计图或计划后声称完成，也不要以缺少无关未来特性为由拖延现有内容迁移。


## 首版视觉稿确认补充（2026-10-12）

用户已确认棋子工作台、技能语句编辑、表达式组合三张示意图，要求严格沿用其浅色布局、蓝色可编辑字段和主次关系。技能没有图标，不为技能增加图标、装饰卡面或虚构插画；可视StatusTag应能设置资源图标。界面中的棋子数值、描述、技能依赖均来自项目真实数据，不复制示意图占位数据。

资源包生成必须接入已有`prepareWorkspacePackage + contentOperation(build)`管线，生成当前项目已保存的内容和图片；未保存编辑应明确阻止生成，避免静默遗漏。现有“已接受版本导出”仍只导出已接受快照，两者文案明确区分。生成本地包不等同上传发布。状态图标使用现有`iconPath`资源路径，编辑不得丢失状态其他字段。


## 全局可靠性原则补充（2026-10-12）

实现必须遵守[语句故障隔离与不得卡死](SKILL_MODULE_INTERFACES.md#语句故障隔离与不得卡死2026-10-12-用户最新确认)：坏语句记录并跳过、依赖结果失效、独立后续继续，保护循环和异步等待，避免半提交及已完成效果重放。正常玩家选择仍可等待，显式return语义保留。将该原则作为分模块验收要求，未验证的运行路径不得宣称已实现。
